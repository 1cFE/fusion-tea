## Findings

1. **The shared stylesheet was edited directly instead of proposed.** `git diff HEAD -- docs/write-up/write-up.css` shows an uncommitted, unproposed change that adds: the `--skim` color token and the `.skim` highlight class (write-up.css:30, 335-344); the whole "Explore panels" block — `.live`, `.live-head`, `.live-kind`, `.chips`, `.chip`, `.readout`, `.explorable`, `.exploring` (write-up.css:648-722); a `details.detail + p, details.detail + ul` spacing rule (write-up.css:592-594); `code, pre { font-variant-ligatures: none; }` (write-up.css:293-294); a `.table-figure figcaption` rule; and a change to `td code`'s `overflow-wrap` from `anywhere` to `break-word`. The render prompt's Style section is explicit: "Use it as it is... propose any change in your report instead of making it," because "a change to it also changes pages the owner has accepted." `harness.html` is the only page using `.skim` (21 uses); `sysml-codegen-model-evaluation.html` also already carries the explore-panel markup, so this stylesheet edit is already bleeding into a second, previously-accepted page. Whatever the intent, the change was made, not proposed.

2. **The inline script does more than track navigation state.** The render prompt's hard constraints say: "An inline script may only track navigation state, as the style sample's script does." `style-sample.html`'s script only opens a closed `<details>` when a link targets something inside it. `harness.html`'s script (lines 1581-1675) additionally builds a whole interactive "explore" feature for Figures 1 and 9: it enumerates `[data-part]` elements, generates chip buttons, wires click handlers, toggles `.picked`/`.holds-pick`/`.exploring` classes, and copies node content into a `.readout` panel. That is new interactive behavior, not navigation-state tracking, and it is the runtime half of the unproposed stylesheet addition in finding 1.

5. **Content that is uncollapsed, flowing prose in the markdown is now hidden behind a closed-by-default `<details>` that the markdown does not have,** contrary to html-render-prompt.md ("Collapse detail, not the story: a reader who opens nothing still follows the whole argument") and the shared feedback's "Main-flow heading behind a closed dropdown" ("Never collapse a heading that is part of the main flow"):
   - Table 1 (harness.html:675-736) is wrapped in `<details class="detail wide" id="table-1">`, closed by default. In the markdown it is plain flowing content (harness.md:114-126), and the preceding sentence — "Table 1 shows how each area implements the pattern" — treats it as something the reader is meant to see, not optional detail.
   - "The loop, part by part" (harness.html:586-607) collapses six paragraphs of flowing prose (harness.md:61-83) that the immediately preceding sentence promises directly: "Figure 1 shows that structure, and the rest of this section walks it from top to bottom" (harness.md:55). With JS off this is a closed `<details>`; with JS on, the alternative is a `.live` panel that starts with an empty readout ("Choose a part of the loop... to read how it works") and needs a click per part. Either way, the promised walkthrough is not visible until the reader acts, and Figure 1 itself carries only structural labels (Goal/Approach/Tasks/Record/Review/Owner), not the explanation.
   - "The code checks" and "The agent reviews" (`#code-checks`, `#agent-reviews`, harness.html:1516-1561) collapse the section-7 bullets that the preceding sentence promises directly: "Below we describe the mechanisms in each class, each with an example from the stored-energy goal" (harness.md:332). Figure 9 again gives only check names positioned on a timeline, not their explanation.
   - By contrast, Figures 4/5/7/8's strip cards do give a headline sentence for each closed detail (even though, per finding 3, that sentence is often the one deleted from the detail itself), so a reader who opens nothing at least gets a result for those tasks/stages. Figures 1 and 9 do not give even that.
   - One instance inside a detail compounds this: Figure 8's Spec card (harness.html:1277-1281) headlines "Requirement 1's check: 4.7 at 10 keV, 3.5 at 20 keV," a check threshold not stated anywhere in the markdown. A reader who does not open the Spec detail never learns what requirement 1 actually is (harness.md:287, "The ash profile follows the paper's rule at every design point, never a fixed exponent") — only a number that presupposes it.

8. **`harness-assets/README.md`'s row for the redrawn chart is out of step with the page it documents.** It labels `stored-energy.svg`/`.png` as "the page's Figure 2," but the page numbers this chart Figure 6 (harness.html:940). Cites html-render-prompt.md: "A redrawn or new image figure gets a render script in the support's assets folder and a row in that folder's README, following the existing convention."

9. **A sentence fragment in new page text.** Figure 8's second card note (harness.html:1285), "The correction to stored energy across the machine sizes the earlier studies covered, larger where the machine holds more ash," has no verb — it reads as a noun phrase, not a sentence. The markdown original it was drawn from has one ("the correction to stored energy ranged from 1 to 23 percent," harness.md:292). Cites synthesis.md, "Thought compressed into a fragment": "Cut any thought that will not stand alone as a complete sentence. Do not compress it into a phrase."

10. **A count stands in for the members it counts, in new text that had the members available nearby.** Figure 7's second card (harness.html:1182), "2 new sources kept, 4 rejected, 2 queued for a person," gives only tallies; the detail directly below names all of them (the 2021 paper and 2023 thesis; the publisher's page, two Proxima Fusion pages and the barred Helios paper; the author query and the paywalled confinement-scaling paper). This is a softer instance than the cited examples — the names are one click away, not absent from the page — but it is the same pattern. Cites synthesis.md, "Count standing in for the members": "Name the members. If you give only a count, the reader still has to ask which ones you mean."
