## Findings resolved

- **Actual-byte joins:** registration hashes real archive, rules, raw request, native result, model export, observations, metadata and final report bytes. It validates the archive checksum inventory, compares archived metadata bytes with the files used for reporting, checks rules and semantic/executable identity joins, reconstructs selected and effective inputs with declared types, checks classification against the original request and regenerates the export from the retained native result. Observation run kind, execution state, predicates and numerical model values pass the existing comparison boundary. Artifacts are hashed again before the external receipt is written. A missing archive or identity refuses; caller-supplied digest claims alone are insufficient.
- **One original per declared register:** exclusive creation of `registration.lock` serializes registration. The fixed `first-forward.identity.json` is written exclusively only after report production. A differently named second forward report cannot become another original in that register. The report does not contain its own hash; the sidecar binds the finished report bytes. A register is caller-declared, so this is one original per register, not a claim of global uniqueness across arbitrary directories.
- **Follow-up identity:** conditioned and corrected reports identify the original receipt digest plus its native/report digests and their own kind. Corrected reports require a nonempty reason. The helper requires the declared register's original receipt, unchanged original artifact hashes and matching archive/executable identity. The same retained bundle can relocate together because stored artifact references are relative. File custody does not authorize a follow-up's scientific interpretation.
- **Preparation and genuine failures:** preparation is the default; verification, blind preparation and Table5 preparation cannot create an original register receipt and receive no independent blind-comparison credit. A completed blind execution with numerical disagreement or engineering violations can become the first report. An uncompleted execution cannot. Every current report remains `publication_ready: false`; caller-declared post-reveal intent is not owner authorization.
- **Retention, overwrite and concurrency:** report destinations are exclusively reserved before parsing. Malformed inputs and ordinary validation failures leave error documents and raw attempt evidence. Existing destinations remain byte-identical and get a separate refusal receipt. Both same-destination and distinct-report races are tested. If final identity publication fails after a report was written, the wrapper returns failure, retains a custody-refusal artifact and deliberately leaves the register locked for explicit recovery. There is no automatic promotion of a later result after that partial transaction.
