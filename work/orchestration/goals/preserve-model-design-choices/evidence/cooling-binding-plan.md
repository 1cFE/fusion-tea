# WI-078 cooling binding and acceptance plan

[AGENT] Proposed for non-author review before implementation. Authority: MR-7, the executed owner prompt, and the bounded WI-078 assignment. The contract preserves a supplied machine design operating point as the price basis and supplied purchased coolant stock. Actual operating flow and power remain heat-balance outputs. It does not infer an off-design performance envelope from independent scalar ratings. This repairs chosen-design costing; physical machine adequacy remains unqualified.

[OWNER-VERBATIM] “As soon as you start introducing ‘sizing’, then you are basically pre-defining which design parameters are ‘free’ and which are ‘derived’. this is explicitly what we wanted to avoid.” The directional closure below is an explicit supported analysis, not authority to impose that direction on every analysis.

## Exact bindings and output semantics

1. **Primary hydraulic calibration:** retain `mdot_loop_ref` and `'Primary Coolant Loop'::mdot_loop_ref_in` solely as the hydraulic-law anchor. Add `mdot_loop_rated_in` to that calculation, bound from the new offered flow attribute. Change only `capacity_margin` to `mdot_loop_rated_in - mdot_loop`. Change the generic plant's `loop_capacity_ok` input at `models/designs/generic_mfe/mfe_plant.sysml:836` to `heat_transport.mdot_loop_rated`. The loss equation continues using `mdot_loop_ref_in`. Changing the offered ceiling must not change loss, work, flow or selected prices.
2. **Operating demand:** preserve primary-loop demand bindings into E: required flow, pressure loss, suction temperature, shaft/electrical draw and IHX duty. Preserve salt operating flow `Q/(cp ΔT)`, selected operating head and operating efficiencies. These continue driving power balance, cycle heat and operating diagnostics.
3. **Helium price:** in `exploration/stellarator_e2e/generated/handwritten/mfe_cooling_equipment/cooling_equipment_impl.py`, replace only the BNL price arguments with supplied design pumping shaft duty and suction pressure. Retain the 50hp pumping-duty normalization; motor nameplate is unsupported. Current shaft duty and pressure remain operating outputs.
4. **Salt price:** use supplied design flow/head and design efficiencies to calculate the design-point shaft/electrical duty, volumetric gpm, head ft and size factor for existing pump/motor price equations. Retain 270°C density and current price-domain conventions. Do not replace operating values with design values in salt heat or work equations.
5. **Design outputs:** add `helium_design_shaft_MW`, `helium_design_suction_Pa`, `salt_design_flow_kg_s`, `salt_design_head_m`, `salt_design_shaft_MW`, `salt_design_electric_MW`. Preserve existing `pump_flow_gpm`, `pump_head_ft`, `pump_size_factor`, `pump_shaft_hp`, `motor_electric_hp` as operating diagnostics; add `design_` counterparts and `design_pump_size_ok`, `design_pump_type_ok`, `design_motor_base_ok`, `design_motor_factor_ok` for the priced point's source-domain checks.
6. **Qualification:** add `machine_off_design_performance_qualified : Boolean`, always false in this implementation. No rectangular flow/head envelope or `machine_capacity_ok` is introduced. Existing source-transfer flags remain false. Neither the offered circuit flow screen nor a match to the selected design point establishes machine performance qualification.
7. **Parts:** amend `'Cooling Machine Account'` docs so `mass_flow` and `shaft_power` clearly mean operating demand. Add usage-specific chosen-point attributes on `primary_circulators` and `salt_pumps`, using the new design outputs, rather than giving either type meaningless placeholders. Existing capital-cost bindings stay unchanged but now price the selected point. All package, spare, replacement and delivered/shipping-exclusion costs follow selected design values. Count changes deliberately change installed costs under the stated topology.
8. **Inventory:** preserve `helium_inventory_mass` and `salt_inventory_mass` and their child bindings as purchased represented stock, now taken from selected procurement inputs. Add `helium_required_fill_mass_kg`, `salt_required_fill_mass_kg` from represented volume/state, and `helium_inventory_target_mass_kg`, `salt_inventory_target_mass_kg` for fill times existing reserve policy. These are requirements/suggestions, never procurement bindings. Initial fluid price and make-up fraction use purchased stock. `inventory_complete` remains false; no complete-system fill-adequacy predicate is invented.
9. **HX/pipe:** retain fixed geometry and the existing installed-versus-required IHX area comparison. Tube count 14,852, OD 0.01905m, tube length 11.6m, shell bore/length 3.2/13m and fixed pipe shapes remain explicit scenario constants. The source U calibration uses that fixed reference area, never demand or a resized area. Primary pipe geometry and layout multiplier do not recalculate the source hydraulic loss law; disclose that limitation. Existing selected wall thickness/accessory/layout inputs retain their physical quantity and price effects.

The entering purchased stock includes the prior reserve once. Later reserve changes modify the target diagnostic only; later demand changes modify required fill if density changes, without mutating procurement. Update current tests that previously expected reserve or layout changes to automatically buy more fluid.

## Remaining limits

[AGENT] The existing correlations can price an independently supplied design operating point under their existing unvalidated technology-transfer assumptions. This does not establish a pump/compressor map, controls or off-design feasible region. A power limit alone is not equipment adequacy, and independent flow/head ceilings do not prove their combination can be delivered. Full supplied-machine performance evaluation remains open.

[AGENT] Fixed IHX/pipe scenario evaluation is retained as the independently reviewed bounded relationship. Steam/cooling-water remain operating closures; cryogenic/turbine/heat-rejection prices remain explicit demand-matched proxies lacking installed-capacity evaluation. Their meanings and qualification limits must not disappear during this repair.
