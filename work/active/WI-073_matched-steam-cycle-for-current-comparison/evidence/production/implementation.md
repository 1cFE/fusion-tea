## Interface and implementation

- `seeds/matched_steam_cycle_impl.py`: 19 named inputs, 71 Real outputs and seven Boolean outputs, exactly matching `interface-inventory.md`. The solver consumes actual heat and per-circuit salt flow times active circuit count; it solves the extraction/reheat state, branch heat/flow and turbine/pump/generator balances. It distinguishes gross electricity, cycle net before cooling and all declared losses.
- `seeds/cooling_water_rejection_impl.py`: nine inputs, nine Real outputs and four Boolean outputs. It solves water flow with the pump's complete electrical input inside the represented rejection balance. Temperature rise is the specified mean-cp diagnostic, not a claimed local outlet state.
- `seeds/cycle_mode_selection_impl.py`: four inputs and three outputs. It selects efficiency and explicit applicability without replacing the raw legacy domain result. Selected matched efficiency is finite and in (0,1]; the historical branch preserves its existing finite efficiency meaning.
- Every seed declares `AUTO_IMPLEMENTED = False`. `calculate(parameters)` takes a dictionary with the unsuffixed interface input names and returns exact output-name keys. `run_<module>(inputs)` reads `<input>_in` attributes and orders its tuple through `GENERATED_OUTPUT_ORDER`. That tuple currently uses seed interface order. Parent must replace it with the actual generated stencil order before integration; declaration order is not asserted to be generated order.
- Cooling and selection import pure helpers from the sibling matched-cycle seed. They support a normal package-relative import and a standalone seed-directory import. There are no top-level generated-schema imports and no production NumPy, HTML, network or external water-property dependency.
