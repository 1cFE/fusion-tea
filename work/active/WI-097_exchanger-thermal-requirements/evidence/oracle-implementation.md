## Method and independence

The new oracle is `exploration/exchanger_architecture/thermal_requirements/studies/oracle_entry.py`. It retains the prior independent profile, source, equipment and lifecycle equations. It imports the unchanged ARIES independent equipment/lifecycle modules and the inherited comparison/operand catalog. No generated arithmetic, production closure, bypass helper or production root solver is called. Stored native outputs are comparison values only; they never enter oracle arithmetic.

The independent thermal implementation is `studies/thermal_oracle.py`. Passive transfer follows the counterflow energy/LMTD identity `ln(a/b) = UA (1/Ch − 1/Cs)` with stable exponential and equal-capacity limits. For controlled full duty, the oracle solves `LMTD(a,b) = Q/UA` for `log(b/a)` and recovers active primary capacity as `Q/(H−S−b)`. The native model instead solves its effectiveness-NTU capability against bypass fraction. The oracle uses Brent's method for the coupled cycle; the native cycle uses bisection. Insufficient UA retains actual partial transfer, unmet duty and the calculated mixed-return error.

The log-domain solve preserves a positive cold terminal smaller than binary64 temperature subtraction can resolve. A secondary-capacity asymptote whose hot terminal rounds away uses a 100-digit LMTD reconstruction and returns the finite duty. Rounded zero terminal differences fail the 30 K check without changing state validity. Inactive duty, zero UA and absent inlet drive remain separate finite diagnostic cases with undefined terminal states.
