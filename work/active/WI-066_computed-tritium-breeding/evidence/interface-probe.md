## Pattern finding

A calculation added directly inside `part :>> blanket` on one plant leaked into another same-type plant in native generation. `interface-probe/unsafe-occurrence.sysml` and `unsafe-pipeline.yaml` retain the reproduction. The second plant still read its held TBR but acquired a phantom calculation and misassigned output alias. A separate unrelated mixin type was refused as incomparable exact typings. A genuine `part def BreedingModel :> Blanket` plus explicitly retyped occurrence isolates the calculation correctly; the two-instance probe retains the held plant's independent input and has exactly one breeding occurrence. `isolated-subtype.sysml`, `subtype-pipeline.yaml`, and `checks.json` preserve that passing result. No upstream runtime patch was made.

## Concrete implementation

1. `models/library/analyses/mfe_tritium_breeding.sysml` defines two typed manual calculations and the binding-only adequacy constraint. No table values or configuration defaults are embedded in the library. Root owns released design data and both numerical implementations. `defined` and `requirement` are reserved SysML tokens; the output names are `defined_flag` and `required_tbr`.
2. `models/designs/generic_mfe/mfe_subsystems.sysml` adds `'Transport Calculated Blanket' :> 'Blanket'`. It owns `breeding : 'Blanket Tritium Breeding'` and redefines `tbr = breeding.tbr_mean`. The generic `'Blanket'` remains held, default 1.0. Public EXPOSEs include isotope contributions, standard error, interpolation allowance, numerical lower estimate and applicability. Other concrete plants need not adopt this subtype.
3. The stellarator explicitly retypes its blanket. Its subtype geometry attributes bind to `stellaris.plasma.R/a/kappa`, `stellaris.shield.ht_shield_t`, `stellaris.structure.structure_t`, and `stellaris.vessel.gap1_t/vessel_t`. Local breeding inputs use inherited `blanket_t`, `reflector_t`, and `first_wall.vacuum_t/firstwall_t`. Native pipeline inspection confirms all eleven formals reach their actual owning entry fields, without duplicated independent geometry parameters.
4. `'Fuel Cycle'` exposes `fuel.tbr_required`, `fuel.loss_rate` and `fuel.tbr_margin`; existing formulas and procurement costs remain unchanged. The stellarator's `breeding_adequacy` calculation consumes these interfaces, achieved mean/lower/applicability, design floor and all fuel-account controls. It publishes requirement, separate design/fuel/numerical margins, production, extracted supply, extraction/recycle losses, decay, growth, balance and validity. Documentation makes raw fuel margins undefined when applicability/account validity fails.
5. Keep the occurrence name `tbr_ok`, replace its definition with `'Computed TBR Adequacy'`, and bind adequacy validity and numerical margin. The admitted predicate is `defined_in >= 1.0 and numerical_margin_in >= 0.0`; the manual calculation guarantees flags exactly 0/1. Native generation preserves ID `stellarator_09__stellaris__tbr_ok__2cd198f674d413e4` and all twenty constraint IDs. Exactly two calculation modules are added.
