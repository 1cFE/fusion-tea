# WI-013 Findings: Pipeline Execution Spike

**Date**: 2026-07-04
**Verdict: the loop is closed.** A sysml-codegen-generated pipeline (solar_battery fixture, 36 modules) executed end-to-end through the teax executor, and all 11 asserted outputs match hand-computed expectations exactly (relative tolerance 1e-12). LCOE = 288.675539 $/MWh. This had never been done before.

All artifacts live in `exploration/pipeline_spike/`:

- `generate_from_snapshot.py` — generation harness (snapshot → ComputationGraph → generators)
- `generated/` — the full generated package (modules, schemas, YAML pipeline, registry, inputs)
- `fill_impls.py` — the AI implementation pass (fills the 15 stencils, every body cited to library.sysml)
- `run_pipeline.py` — execution harness with assertions
- `outputs/` — executor run directories (per-channel JSON + manifest)
- `.venv-exec/` — venv with teax-simkit installed editable

## What ran

1. **Generation** — from the fixture's `extraction_snapshot.json`, not live SysML parsing, because syside's license is expired (see Blocker below). The harness replicates `run_codegen()` (`sysml-codegen/src/sysml_codegen/cli/__init__.py:600`) with the snapshot-loading pattern the conformance tests use (`tests/conformance/test_entry_point_classifier.py:56-161`). Output: 36-module graph, pipeline YAML, Pydantic schemas, module wrappers, 15 implementation stencils, 21 auto-implemented aggregation modules, pre-filled input JSONs.
   - Sanity check: the generated registry is **byte-identical** to the committed baseline (`tests/fixtures/baseline_outputs/solar_battery/registry_init.py`) modulo package name.
2. **AI implementation pass** — the 15 library calc-def stencils raise `NotImplementedError` as generated. `fill_impls.py` replaces each raise with a mechanical translation of the calc def's `out attribute` expressions, each line citing its `library.sysml` line. **Every expression translated mechanically; none needed anything beyond `+ - * /` and `**`.** The 21 assembly rollup impls (capital_cost sums etc.) were auto-generated by codegen (`AUTO_IMPLEMENTED = True`) and needed no work.
3. **Execution** — teax `execute_pipeline()` over `generated/pipelines/solar_battery.yaml` with the generated registry, custom schema types, and a harness-built OutputRouter (two executor gaps required it — see teax findings). 77 channels produced; per-channel JSON written.
4. **Assertion** — 11 outputs asserted against hand computation. Exact match.

## Blocker (environment, not codegen/teax)

**syside license expired.** Both installs fail at import with "License expired" — sysml-codegen's venv (syside 0.8.4) and fusion-tea's (0.8.6); the `SYSIDE_LICENSE_KEY` in `fusion-tea/.env` is itself expired. `sysml-codegen generate` (the CLI) is currently unusable end-to-end because Step 1 is live parsing (`extraction/extractor.py:57` → `agentic-mbse/src/agentic_mbse/sysml/syside_adapter.py:44`). The spike routed around it via the fixture's extraction snapshot. **Consequence for Item 3 (IFE demo): the IFE models have no extraction snapshot, so Item 3 is blocked on a license renewal.** Flag this now.

## Codegen findings (file the following in sysml-codegen)

1. **No snapshot-input path in the CLI.** Generation from a snapshot required a custom harness replicating orchestration internals plus test-only helpers. A `--from-snapshot` mode would decouple generation debugging (and this spike-class work) from the syside license. Pointers: `src/sysml_codegen/cli/__init__.py:622` (context build is parse-only), `tests/helpers/snapshot_loader.py` (loader exists, test-tree only).
2. **Numeric literals render as `LiteralRationalEvaluation()` in extracted expressions.** Stencil docstrings show e.g. `annual_energy_mwh = LiteralRationalEvaluation() * p_net_mw * n_mod * plant_availability` — the literal `8760.0` is lost. Mechanism: SysIDE literal nodes carry a `.function.name`, so they hit the invocation branch of `reconstruct_expression` (`src/sysml_codegen/extraction/expression_utils.py:57-62`) before the literal branch (`:64-66`, which matches node type names SysIDE doesn't use). 39 occurrences baked into the solar_battery snapshot. Damage is doc-only (auto-implemented bodies get literals right via a different path), but it degrades the stencil as an in-file spec for the AI pass — the implementer must open the `.sysml` source for every literal.
3. **Warning noise that looks like failure but isn't.** (a) 10 "Registry unresolved" lines for design-attribute-bound params (e.g. `...energy_production|p_net_mw`) that resolve correctly as `design_params` entry points; (b) "EXPOSE_PURE misc_hardware_cost: could not identify instance/output" yet the YAML wires `allocation_model__total_allocation` into the rollup correctly (`pipelines/solar_battery.yaml:319`). Either the warnings are stale or they mask a real edge case elsewhere — worth triage.
4. **Module class-name collisions handled, confirm intended.** 20 aggregation modules share class names (`capital_costModule` × 4 scopes, etc.); the generator emits aliased imports + `module_type_override` and it works. Informational.
5. **`compilation_results` cannot be rebuilt from a snapshot** (expression ASTs aren't serialized; loader documents this at `tests/helpers/snapshot_loader.py:6`). Passing `compilation_results=None`/`{}` still produced a correct package for this model — but any model relying on compiled-expression stencil bodies would lose them in a snapshot-driven run. Relevant if finding 1 is implemented.

## teax findings (file the following in teax)

1. **ExitPoint cannot write primitive-typed channels out of the box — contract gap with codegen.** The generated YAML declares exit outputs as `RootModel[float]` and `float`, but the default router has no handlers for those names, so validation hard-fails (`packages/teax-simkit/simkit/core/pipeline_validator.py:320`). `execute_pipeline`'s `custom_schema_types` can't express them (registers class-named Pydantic types only, `simkit/core/pipeline.py:76-100`). Workaround: harness-built router via `create_output_router_with_json_schemas(["RootModel[float]", ...])` (`simkit/io/output_router.py:276`). One side of the contract must move: teax registers primitive handlers by default, or codegen emits/registers them in the generated package.
2. **`write_json_model` assumes a Pydantic model.** Plain-float channels (codegen emits many) crash at write time with `'float' object has no attribute 'model_dump'` (`simkit/io/writers.py:25`). Needed a custom scalar `WriteHandler` in the harness. Same contract gap as (1), second layer: validation *and* writing both reject primitives.
3. **Workspace packaging is broken for `uv run`.** `uv run --project ~/1cfe/teax` fails to build the root: setuptools flat-layout discovery finds `['thoughts', 'packages']` as top-level packages and aborts. The repo's `.venv` is also empty (nothing installed). Installing `packages/teax-simkit` editable into a fresh venv works fine — the root `pyproject.toml` just isn't a functioning workspace root.

## Constraint-predicate status: NOT emitted — Phase 6 gap confirmed

Generation does **not** emit evaluable constraint predicates. The machinery exists in three disconnected pieces, none reachable from the generation pipeline:

- **Extraction into the pipeline is stubbed.** `src/sysml_codegen/extraction/extractor.py:106-107`: `# Extract constraints (stub for now)` / `constraints = []` — every `PartDefinitionData` gets an empty constraint list. `CalculationDefinitionData` has no constraints field at all (`src/sysml_codegen/extraction/data_models.py:96-126`).
- **A standalone constraint extractor exists but has zero callers.** `src/sysml_codegen/extraction/constraint_extractor.py:39` (`extract_all_constraints`, handles `constraint` / `assert constraint` / `require constraint`) — grep finds no import anywhere in `src/` or `tests/`.
- **A constraint→Pydantic translator exists but has zero callers, and its output template is a TODO.** `src/sysml_codegen/extraction/constraints.py:41,107` (parse + validator codegen) is imported nowhere; the validator body it would render is `# TODO: Implement constraint validation` then `return self` (`src/sysml_codegen/templates/constraint_validator.py.jinja2:9-17`).
- Downstream, `ComputationGraph`/`PipelineModule` carry no constraint fields and the generated YAML/modules contain nothing constraint-shaped — the teax executor never sees a predicate.

(The solar_battery fixture itself contains no constraints, so nothing could have been exercised end-to-end regardless; the status above is from code reading.) **Consequence for Items 1/3: as the epic anticipated, constraint evaluation must happen harness-side from the extracted constraint expressions until Phase 6 lands.**
