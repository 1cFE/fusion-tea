## Result

**Acceptance: 100% agreement, modulo 7 flagged boundary rows.** The retiring hand rule
(`sweep_ife.py:82`, `eta * gain > 10`, strict `>`) and the now-executing generated
`'Viability Threshold'` constraint assertion (`eta * gain >= threshold`, `>=`) were replayed
once, together, over the full 2301-point `(eta, gain)` grid (`ETA_GRID` × `G_GRID`, matching
`sweep_ife.py`'s own grid exactly). 2294 rows match exactly; 7 rows sit exactly on
`eta*gain == 10.0` and diverge — this is the documented `>` vs `>=` boundary hazard
(`.project/reference/fusion-tea-ife-sweep/FACTS.md`), not a defect. See
`acceptance_table.csv` (columns: `eta, gain, eta_g, old_viable, new_verdict, new_viable,
at_boundary, match`).

The hand rule at `sweep_ife.py:82` is retired: `sweep_ife.py`'s hot grid loop now calls the
generated predicate function (`ife_tea.modules.constraints.predicates
.constraint_pred_ife_plant__ife_power_plant__viability`) directly, the same mechanical-import
pattern the file already used for LCOE/recirculating-fraction. The LCOE-threshold overlay at
`:84` (`attractive = viable and power_positive and lcoe <= 100`) is untouched — policy, not a
modeled constraint, per FACTS.md.

**Prepare-once benchmark** (`prepare_once_benchmark.json`, N=200 real evaluations against the
sealed package): prepare-once **~168x** faster than rebuild-per-case (0.166 ms/case prepared
vs 27.8 ms/case rebuilt), 200/200 verdict parity between the two paths. A recorded
measurement (S5 carry-forward (2)), not a tuning target.

## Three named schema/wiring gaps (surfacing — not silently patched around)

**Preconditions were reported "ALL MET"** (W1 landed, teax Items 10-12 certified, W5b loader
seal wired) — true for the single-entry-channel toy fixture every teax test and the pre-Item-9
Item-0 spike (`teax/.project/active/constraint-study-integration-spike/`) exercised. This
session is the first time a *real, multi-entry-channel, whole-plant* sysml-codegen package has
been run through the certified teax study layer, and it surfaced three gaps the certifications
didn't catch. None are architectural — each is exactly the "schema/naming/wiring" class the
Item-0 spike's own mismatches were. All three were bridged from fusion-tea's side only
(sysml-codegen and teax source are out of this session's sandbox); each bridge is a small,
clearly-marked adapter, not a silent workaround:

1. **`contracts/constraint_catalog.json` is never emitted as a standalone file.**
   sysml-codegen's Item 9 embeds the constraint catalog inside `contracts/model_contract.json`
   (key `constraint_catalog`), with field names (`usage_qualified_name`,
   `definition_qualified_name`, `formal_names`) that don't match what teax's Item 12
   (`simkit.study.config`, `simkit.study.cli`, `simkit.study.query._Catalog`) reads from a
   *standalone* `contracts/constraint_catalog.json` (`usage_name`, `source_usage`, `owner_qn`,
   `definition_qn`, `source_form`). teax's own fixture at
   `teax/packages/teax-simkit/simkit/tests/evaluation/fixtures/sealed_package/package_live/
   contracts/constraint_catalog.json` is hand-authored to teax's expected shape — it was never
   generated by, or checked against, a real sysml-codegen Item 9 artifact until this session.
   **Bridge:** `materialize_constraint_catalog.py` derives a conformant standalone file from
   the embedded catalog, then `sysml-codegen seal` re-seals the package so the derived file is
   covered by the integrity hash set (the same `seal` command the CLI documents for
   "after editing a handwritten stencil").
2. **`CandidateBridge` only ever builds ONE entry channel's typed model**
   (`simkit.study.bridge.CandidateBridge.build`), but `MappingEntrySource.validate`
   (`simkit.evaluation.entry_source`) requires *every* channel the package's `EntryPoint`
   declares or raises `EvaluationFailed(ENTRY_VALIDATION)` → `StudyBridgeDefect`. The toy
   fixture Items 10-12 were built and tested against has exactly one entry channel; this
   package's whole-plant `EntryPoint` has four (`hif_driver_params`, `hif_plant_params`,
   `ife_plant_params`, `system_design`). This is the same class of gap the Item-0 spike
   flagged as mismatch #1 ("Item 10 must define the typed-entry contract at both levels") —
   resolved for the single-channel case only. **Bridge:** `MultiChannelEvaluator` in
   `run_viability_study.py` wraps the real `PreparedEvaluator`; on every `evaluate()` call it
   merges the swept channel (built by the real, unmodified `CandidateBridge`) with the other
   three channels' typed models, loaded once from the package's own committed `inputs/*.json`
   templates. `StudyRunner`/`CandidateBridge`/`PreparedEvaluator` are unmodified — this plugs
   into the documented `Evaluator` protocol seam, the same seam the Item-0 spike proved
   pluggable by construction.
   > **RESOLVED (Lifecycle Item 9, 2026-07-20):** stock teax now builds zero/one/many channels
   > itself — `StudyDefinition` carries the `entry_models` map and `CandidateBridge` routes each
   > field to its owning channel. `MultiChannelEvaluator` is deleted; the plain `PreparedEvaluator`
   > runs the 2,301-point study green. (The four-channel decomposition quoted above predates Item 8;
   > the regen is three channels.)
3. **`PreparedEvaluator.__init__` unconditionally sets `self.ToyPlantParams =
   self.package.ToyPlantParams`** (`simkit/evaluation/evaluator.py:107`) — a toy-fixture
   convenience left in the constructor, not generalized to the loaded package's actual entry
   model name. Any package without a class literally named `ToyPlantParams` fails to
   construct. **Bridge:** both driver scripts alias `module.ToyPlantParams =
   module.IfePlantParams` on the loaded module before constructing `PreparedEvaluator` —
   harmless, additive, no teax source touched.

**Recommendation for Phase 6 / a future item:** gaps 1 and 2 are load-bearing for any
multi-constraint or multi-entry-channel package (i.e. any real plant model past a toy
fixture) — not fusion-tea-specific. They should become real sysml-codegen/teax work items
(emit a conformant standalone catalog file; make `CandidateBridge`/`StudyDefinition` carry a
full typed-entry set, not one channel) rather than staying as three per-consumer harness
adapters. Gap 3 is a one-line fix in teax. None of the three block this item's own
Critical Success Factor — the acceptance table and benchmark above are real, and match the
epic's expectation — but they mean the "Items 9-12 certified" claim only covers what those
items' own test fixtures exercised, not a real whole-plant package until now.
