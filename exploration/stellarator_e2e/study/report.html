What this is

The demo asks one thing of the toolchain: author a fusion power plant as a SysML v2 model, generate executable code from it, and then search the design space — vary design levers, and get back cost and feasibility for every candidate. Cost here is the levelized cost of electricity (LCOE, $/MWh — lifetime cost per delivered megawatt-hour). This report is the first end-to-end run of that loop on the stellarator (Stellaris, concept-09).

Three layers did the work — none of the study machinery was hand-rolled (the small documented glue harness is itemized in the caveats):

  • The SysML model owns the meaning: plasma geometry, profile-integrated fusion power, power balance, the full cost-account stack (CAS — the standard fusion cost breakdown), LCOE, and five viability constraints (beta limit, wall load, tritium breeding, recirculation, net power).
  • The generated package (sysml-codegen, sealed July build) owns evaluation — the same package that reproduces the pinned $275.26/MWh headline bit-exact.
  • The study layer of teax (the evaluation toolkit) owns exploration, pinned to the package's era (see caveats): stock PreparedListStrategy → StudyRunner → StudyStore → StudyQuery, with every swept SysML attribute expanded to its complete set of generated input keys.

Every point carries the model's own verdict for all five constraints, plus recorded outputs (LCOE, fusion power, wall load, capital). Nothing here is tuned to a result: the two study axes are causal design levers (the machine's major and minor radius), and the constraint set is exactly what the model already asserted.

The design map

Each cell is one plant design at that (R, a); everything else is held at the Stellaris baseline. Color is LCOE (log scale — dark is expensive). Hatched cells are designs the model itself rejects; the dotted corner is geometrically impossible (the radial build no longer fits inside the major radius).

Three things the search found:

  • The wall-load limit is the active fence. 353 of 385 constraint violations are the neutron wall load exceeding the sourced 4.05 MW/m² limit. LCOE keeps falling as the plasma gets fatter: the cheapest point in the window is $163/MWh at R = 9, a = 2.2, at wall load 5.46 — and the model correctly fences that whole region off.
  • The best feasible design sits on the boundary. R = 14 m, a = 1.65 m gives $209.00/MWh (-24% vs the authored baseline) at wall load 4.035 of 4.05 — the classic signature of a constrained optimum, found by the model's own verdicts, not by a hand rule.
  • Recirculation kills the small-machine corner. 32 small-R·a designs fail the economic recirculation threshold — Qeng, the plant's engineering gain (gross electric over recirculated power), must be at least 2 — before net power even goes negative. Net-positive never fires in this window, and the beta and TBR verdicts cannot move on these axes (they are bound design inputs; see caveats).

The availability sweep

A second study exercises a non-geometry lever: availability. The package carries this one attribute as four separate input keys (fuel throughput, scheduled replacement, both LCOE forms) — the known duplicated-input defect, where mutating one copy leaves the rest stale. The study layer moves all four together, closing the defect at the study surface (see caveats for what remains untied).

What this does not prove (read before quoting)

  • The package runs at its own era, behind a scoped seal exception. Current teax refuses this July package's v1.0.0 seal (a deliberate fail-closed version gate). The studies ran on a read-only teax worktree pinned to the era that built and certified this package, through a small harness-side wrapper around the era's loader (GlueAwareLoader, study/run_design_search.py). Two files differ from their sealed hashes — exactly the two the documented harness glue edits; the loader verifies every other artifact and refuses anything beyond those two. Regenerating the package on the current toolchain is known upstream work, currently parked (unowned, behind a July hold): the current code generator refuses the canonical stellarator models — at least 114 uses of a modeling pattern it no longer accepts (self-binding), counting only the first diagnostic class.
  • Three values are harness-supplied per point (glue), not model-computed: the CAS27 special-materials cost (recomputed per point from the blanket volume — the package cannot wire it cross-part, so the oracle check does not independently verify this one ingredient), the CAS28 digital-twin constant, and a replacement-schedule module count. All inherited from the documented glue ledger of the July build items (WI-018/028/029).
  • Only the three declared axes are safe to sweep. R, a, and availability carry complete attribute→entry-key expansion maps; the package's remaining duplicated input keys (interest rate ×4, operational years ×4, and others) are untied, so sweeping anything else would silently leave stale siblings. The expansion completeness check is name-based; magnet__R0 rides with R as a hand-declared physical-identity tie (the magnet-cost current runs on the major radius), and known semantic duplicates under different names are held fixed (installed heating power appears twice; one fraction appears at two precisions).
  • Interest rate is deliberately not swept. The model's levelization calc lacks a guard for the degenerate case where interest rate approaches the inflation rate — a known library gap that only a regenerated package can fix.
  • This is a power-balance-and-cost feasibility map under an assumed plasma. Density and temperature profiles, heating power, cryo loads, and the magnet shape factor are held at Stellaris baseline values at every point; no confinement-scaling constraint (e.g. ISS04) exists in the model yet, so nothing asks whether the assumed plasma is achievable at each geometry. Beta and TBR are bound design inputs — their verdicts cannot flip on these axes.
  • The sweep window is engineered. Ranges were chosen by oracle pre-scan so the constraint boundaries sit in frame; the feasible fraction (59%) is a property of the window, not a finding about stellarators.
  • The study store records only single-number outputs at this toolchain version: net electric power and Qeng reach the record through their verdicts, not as stored numbers.
  • This is a first cut of the demo epic's design-search items, not their close-out. The instance-swap (A/B) study, the formal review and policy-ratification step, and the search-process animation remain open.

Reproduce

Prerequisite: a read-only teax worktree at commit fa0e06a at /home/reid/1cfe/teax-v1-era (the era pin — see the script docstring). On a machine without it, create one with git worktree add ../teax-v1-era fa0e06a from the teax repo.

cd exploration/stellarator_e2e
uv run python study/run_design_search.py run     # both studies + gates (~2 min)
uv run python study/run_design_search.py verify  # oracle spot-checks
uv run python study/make_report.py               # this report
