## Main finding

The model has sufficient reactor radial geometry and cooling exchanger geometry to begin a conceptual layout. It does not yet have the component segmentation, removal paths, handling envelopes or maintenance throughput needed to size a hot cell. Buildings remain six grouped power/fixed/staff cost terms. Remote handling remains a separate power-scaled equipment allowance. They provide neither building dimensions nor demonstrated processing capacity.

The cooling implementation is newer than the September 18 reassessment and must be preserved. The actual current model and generated parameter file select **14 cooling circuits**, while the cooling goal's retained selected study case uses **18**. Facility interfaces must read the executed case's circuit count. They must not embed eighteen as a plant constant. References: `models/designs/stellarator_09/stellarator_plant.sysml:1073`, `:1173`; `exploration/stellarator_e2e/generated/inputs/stellarator_plant_params.json:110`; `work/orchestration/goals/installed-cooling-equipment-costs/answer.md:13`.

## Maintenance demand and calendar

The live calendar uses physical life L = fluence limit / peak neutron wall load, with fluence limit 18 MW-year/m². It purchases the blanket plus divertor as one bundled event. Dates are `t_k = k*L/(1-u) + (k-1)*d`, conditional on restart before the 30-year horizon. The current scheduled outage d is seven months; u=0 is an explicitly unsupported unplanned-failure assumption. The source's five-month replacement window and 90% availability are targets, not achieved facts. Approximately thirty days each for cooldown and recommissioning are already inside the seven-month estimate. References: `models/library/analyses/mfe_lifecycle.sysml:14`; stellarator `:1650`, `:1668`, `:1682`; generic plant `:620`.

Calendar outputs include life, replacement count, productive time, downtime, availability and replacement present value. Event dates are available through the existing diagnostic `calendar_events` at `exploration/stellarator_e2e/generated/handwritten/mfe_lifecycle/lifecycle_calendar_impl.py:177`, not a serialized producer channel. They should be reused for a facilities demand check or deliberately exposed once; a second independently evolving event schedule would be a risk.

Cooling machine life is ten calendar years and bundle life fifteen years in the current scenario. Events are k*life strictly less than thirty years: two machine events and one bundle event. All active machine purchases/installation/removal are repeated per machine event; exchanger tube/accessory bundles are repeated per bundle event. These dates are not coupled to the in-vessel outage calendar. Adding hot-cell capacity or assuming synchronized maintenance must not erase that distinction. Initial spare purchases do not repeat. Normative equations: `models/library/analyses/mfe_cooling_equipment.sysml:15`; current bindings: stellarator `:1083`.

No model currently specifies receipt duration, storage decay/hold time, processing duration per component, parallel workstation count, shift pattern, dispatch rate, radioactive classification or handling route. No independent blanket/divertor task-level replacement quantities are available. Thus neither steady throughput nor peak coincident inventory is established. Cooling replacements provide additional count/mass demand but no outage duration or storage schedule.

Give facilities a read-only interface containing equipment count, external L/W/H, removal L/W/H, maximum lifted mass, source/assumption status and servicing class. Expose genuine cooling geometry from its existing owner; keep unavailable package dimensions explicitly provisional at the facilities scenario boundary. Do not relabel flow-derived or tube-area quantities as exterior envelopes.

[AGENT] Keep the calendar the authority for replacement demand. A facilities capacity calculation should consume event dates/counts, component batch quantities and explicit dwell/process assumptions. It should return required storage positions, workstation capacity, handling-space dimensions and a capacity verdict. If task time or throughput exceeds the allocated outage window, return the conflict while leaving the calendar's availability unchanged. The new study can show incompatible layouts without silently repairing them.

[AGENT] Begin with reactor hall, assembly/transfer space, hot-cell processing/storage and exchanger hall.
