# Critic Review — 36-helical-coil-stellarator

## Headline issues

1. **The 1 GWe projection CAS22 explodes to $56.5B (4.95× family median) while CAS21–27 all run 4–5× high — this is not a concept-specific cost driver, it's a scaling pathology** — The deterministic sanity check flagged 18 outlier accounts, but the pattern reveals a structural problem: every account in the primary power loop (CAS21 buildings, CAS22 reactor, CAS23 turbine, CAS30 capitalized equipment, CAS50–60 construction services, CAS90 project contingency) scales to 1 GWe by 4–5× the stellarator family median, while the native-scale results are in-family. This is not HESTIA's architecture diverging from comparables — it's the two-knob projection formula applying an aggressive scale factor to a 70.4 MWe → 1 GWe jump (14.2× power ratio) in a way that compounds across linked accounts. The analysis never flags this; `model_output.txt` shows it silently. The $904/MWh LCOE at 1 GWe is presented as headline but is mechanically unreliable. **Action**: Either (a) acknowledge that the 1 GWe projection is not grounded for a 70.4 MWe native design (the two-knob formula assumes ~500 MWe → 1 GWe scaling, not 70 → 1000), and report native LCOE ($1021/MWh) as the defensible figure, or (b) add a 200–300 MWe intermediate step to validate scaling linearity before jumping to 1 GWe.

2. **The single enabled override (C220108 = 0 for integrated blanket/divertor) is well-grounded, but five other override candidates in §5b are all left disabled with "no company-grounded cost" — this is correct discipline, but it hides that the two largest CAPEX drivers (C220103 magnets $3.08B, C220101 blanket $154M at native) are complete library-defaults with zero concept-specific grounding** — Analysis §5b correctly refuses to override C220103 (HTS magnets) and C220101 (blanket) because Helical Fusion provides no WISE conductor unit cost and no liquid-metal blanket module cost. This is the right call under the override discipline ("no override without company-grounded or direct-citation value"). But it means the model's two largest capital cost items are generic stellarator defaults (C220103 from CFS ARC REBCO assumptions, C220101 from ARIES-AT FLiBe blanket proxy per §5b lines on C220101). The analysis flags this as "major cost uncertainty" in §5b but does not elevate it to a headline gap in the LCOE interpretation. The AIP paper's lump-sum $5B (1990s basis) direct cost is never reconciled with the library's CAS22 total of $4.12B at native scale (close in magnitude but with zero per-account validation). **Action**: Either find independent WISE conductor pricing (vendor partnership announcements, investor deck leaks, analogous quotes from Tokamak Energy or Type One for non-planar HTS) or explicitly state in the synthesis that C220103 is ±50% uncertain and drives LCOE by ±$200–400/MWh.

3. **The design point block cites P_native = 70.4 MWe with "grounding_confidence: high" and lists two markdown sources, but analysis §1 warns that the AIP paper's $5B cost excludes inflation (2× multiplier suggested) and O&M, and the $1.22/kWh figure is not LCOE — yet none of this cost-basis fragility is carried through to the override registry or model commentary** — The deterministic `dpc` check passes because P_native coherence is satisfied (70.4 MWe in table = analysis.md = model_setup.py), but *confidence in the cost estimate* is a separate dimension. The AIP paper (analysis §1, §2, §5b) repeatedly flags: (a) 1990s cost basis with 2× inflation uncertainty, (b) no CAS-level breakdown, (c) $1.22/kWh is *direct construction cost / total energy over 6.4-year lifetime*, not LCOE (excludes O&M, financing, decommissioning). Yet the design-point block rates `grounding_confidence: high`. This is a category error — the *power output* (70.4 MWe) is well-grounded (Table I in AIP paper), but the *cost model inputs* are not. The override registry never references the $5B figure, so there's no attempt to reconcile it with the library's native overnight cost of $6.6B (generic) or $6.58B (native w/ overrides). **Action**: Either downgrade `grounding_confidence` to `medium` (the P_native value itself is solid, but the cost anchor is 1990s-basis with ±2× inflation range), or add a Cost-Basis-Confidence field to the design-point block and rate it separately.

### Spec coherence (beyond P_native)

The analysis describes **one named plant**: HESTIA Fusion Pilot Plant, reference operating case from Miyazawa & Goto, Physics of Plasmas 2023, Table I. Every parameter in §5 (Design Point Parameters) cites Table I or a specific section of the AIP paper. The design-point block's `design_name` field matches the analysis §1 header ("HESTIA Fusion Pilot Plant — reference operating case"). There is no stitching across published designs — the 2023 AIP paper is the sole quantitative anchor, and company announcements (Oct 2025 HTS coil demo, GALOP test system) are cited only for technology validation, not for reactor parameters.

However, there is **one subtle coherence issue**: the analysis §5 notes "Reactor lifetime T_net = 6.4 years" (AIP paper Table I line 167) and explains that the AIP paper's $1.22/kWh figure is "direct construction cost divided by total energy production over the 6.4-year reactor lifetime, not a levelized cost" (§1, §2). But the model does not use this 6.4-year lifetime anywhere — the 1costingFE library assumes a standard 30-year plant lifetime for LCOE denominators. The analysis never reconciles the 6.4-year design lifetime with the model's implicit 30-year assumption. Is HESTIA a 6.4-year demonstration plant (in which case LCOE should use 6.4 years and account for multiple reactor rebuilds over a 30-year site lifetime), or is the 6.4 years a blanket/first-wall component lifetime (and the plant operates for 30 years with periodic component replacement)? The AIP paper (analysis §1, lines 363-365) states "target availability of >80%, with ~1 year continuous operation + ~3 month maintenance cycles," which suggests the 6.4 years is total *burn time* across multiple campaigns, not calendar lifetime. But this is never clarified in the analysis, and the model does not reflect it.

**Verdict on spec coherence**: Passes the single-plant test (no stitching), but the lifetime accounting is ambiguous and may mis-state LCOE if the 6.4-year figure is interpreted differently by the AIP paper vs. the library.

### Override discipline (judgment)

The override registry has 6 entries; only 1 is enabled. Walk each:

1. **C220103 (HTS magnets)** — `enabled: false`, rationale: "no company-grounded HTS unit cost; WISE conductor pricing is proprietary and undisclosed." The analysis correctly refuses to override because Helical Fusion provides no $/kA-m or $/kg figure for WISE conductor. The Oct 2025 demo (40 kA at 7 T) validates the technology but not the cost. The library default (CFS ARC REBCO assumptions, per §5b) is planar-winding pricing; HESTIA's continuous helical winding "likely carries a manufacturing premium, but without a published WISE conductor price, no override is justified." **Judgment**: Correct discipline. The rationale acknowledges the architectural difference (3D helical vs. planar) but correctly refuses to guess the magnitude of the premium.

2. **C220104 (ECRH)** — `enabled: false`, rationale: "no per-gyrotron unit cost published." The analysis notes that 250 GHz, 1 MW CW gyrotrons do not exist ("a 250 GHz-1 MW-CW gyrotron does not exist," AIP paper line 261), and ITER's 170 GHz units are "several million dollars each" but scaling to 250 GHz "may increase or decrease cost depending on production volume and technical maturity." **Judgment**: Correct discipline. The uncertainty range is stated as "too wide and the data too thin to justify a derived override." This is the right call.

3. **C220101 (blanket)** — `enabled: false`, rationale: "no blanket unit cost ($/kg LM, $/module) provided." The AIP paper describes a modular liquid metal blanket (90 modules, tin-indium-lead-lithium alloy, 3D-printed porous first wall) but "provides no cost breakdown." The library default is "derived from ARIES-AT FLiBe blanket estimates." **Judgment**: Correct discipline, but the rationale undersells the architectural divergence. HESTIA's integrated blanket/divertor (zero separate divertor, per the enabled C220108 override) should *reduce* C220101 cost relative to a conventional blanket-only design, or at least shift cost from C220108 into C220101. But the override registry leaves C220101 at library default (which assumes a *separate* divertor exists). The analysis §5b acknowledges this: "The blanket's integration of first wall + breeding + shielding functions 'eliminates the need for separate divertor systems' (line 234), suggesting cost savings relative to tokamak blanket + divertor, but this is qualitative." The correct discipline is to refuse the override (no $/module figure exists), but the *directional implication* (HESTIA's C220101 should be higher than a blanket-only design, because it subsumes divertor function) is not reflected. This is a modeling-layer gap, not an override-discipline error, but it means the native CAS22 total may be understated (C220108 is zeroed, but C220101 is not incremented to absorb the integrated functionality).

4. **C220108 (divertor)** — `enabled: true`, `value: 0.0`, `provenance: direct`, rationale cites AIP paper lines 81-84, 234-236 stating "individual divertor systems are not required in HESTIA. The rationale correctly notes "The divertor functionality is embedded in C220101 (blanket)," but as noted in item 3 above, the model does not *add* cost to C220101 to reflect this. The override itself is correct; the gap is in C220101 (which is left at library default).

### Two-knob projection (judgment)

The `model_output.txt` shows three columns: `generic` (P_native, overrides off), `native` (P_native, overrides on), `1 GWe` (1 GWe NOAK, overrides on). The generic vs. native columns are nearly identical (total overnight $94,274/kW vs. $93,504/kW, LCOE $1038.5/MWh vs. $1021.0/MWh), which makes sense because only 1 override is enabled and it removes $36.6M from a $4.1B reactor plant (a 0.9% reduction). The 1 GWe column shows $85,440/kW overnight and $904.1/MWh LCOE.

**Implausibility check per account**:
- **C220103 (magnets)** = $3,081M at native, $3,081M at 1 GWe. This is **constant** — the magnet cost does not scale with power. This is plausible only if the 1 GWe plant uses the exact same magnet system as the 70.4 MWe plant (same field strength, same coil geometry, same conductor length). But a 1 GWe plant at the same field strength would require 14.2× more fusion power, which implies 14.2× larger plasma volume (if power density is held constant), which implies larger major radius or aspect ratio, which implies longer coil length. The fact that C220103 is constant suggests the two-knob formula is *not* scaling the coil size, only the power balance. This is a formula limitation, not a HESTIA-specific issue, but it makes the 1 GWe C220103 figure suspect (likely understated).

- **CAS21 (buildings)** = $225.7M at 1 GWe, vs. $225.3M at native. Nearly constant. Buildings should scale with reactor size (larger plasma → larger reactor hall), but the formula holds them nearly flat. At 1 GWe, CAS21 is 0.47× the stellarator family median (per sanity check), i.e., half the expected cost. This is **implausible** — a 1 GWe stellarator should have comparable or larger building footprint than other 1 GWe stellarators, not half. The fact that it's low suggests the formula is not scaling buildings appropriately for a 70 → 1000 MWe jump.

- **CAS22 (reactor plant)** = $56.5B at 1 GWe, vs. $4.1B at native. This is a 13.8× increase for a 14.2× power increase, so the scaling exponent is ~1.0 (linear). But the stellarator family median for CAS22 at 1 GWe is $11.4B, so HESTIA is 4.95× higher. Why? If HESTIA's native CAS22 ($4.1B) is in-family, and the formula scales it linearly, it should land near the family median at 1 GWe unless (a) HESTIA's native scale is an outlier (smaller than other stellarators, so the 14× jump is more aggressive), or (b) the formula is wrong. The analysis never explains this divergence.

- **CAS23 (turbine plant)** = $414M at 1 GWe, vs. $29.4M at native. This is a 14.1× increase, matching the power scale factor. The sanity check shows CAS23 at 1 GWe is 1.75× the family median, i.e., moderately high but not an outlier (within 2× threshold). This is plausible if HESTIA's sCO2 turbine is 75% more expensive than a Rankine cycle, but the analysis §5b states "sCO2 vs. Rankine cost differences are small relative to the reactor plant cost." The 1.75× ratio is borderline.

**Verdict on two-knob projection**: The 1 GWe results are mechanically unreliable. The magnet cost (C220103) does not scale, the buildings (CAS21) barely scale, and the reactor plant (CAS22) scales linearly but lands 5× above the family median. The analysis never validates the 1 GWe projection or discusses its plausibility. The native LCOE ($1021/MWh) is the defensible figure; the 1 GWe LCOE ($904/MWh) is a formula artifact.

### Family delta vs comparables

The analysis §7 compares HESTIA to five stellarator comparables on architecture: coil geometry (continuous helical vs. modular planar vs. modular 3D), blanket type (liquid metal vs. solid breeder), and manufacturing approach (WISE vs. planar stacking vs. laser-patterned film). Every divergence is attributed to a deliberate design choice:
- Continuous helical coils → manufacturing simplicity (fewer joints) but higher winding complexity (3D path)
- Integrated liquid metal blanket/divertor → eliminates C220108 (divertor) but increases C220101 (blanket) complexity
- WISE conductor → flexibility for helical winding, but unproven at reactor scale

The analysis correctly notes that "all stellarator concepts share the following cost advantages relative to tokamaks: no disruption risk, true steady-state operation, no central solenoid" (§7, Shared advantages). It also notes "shared challenges: 3D coil complexity, lower power density than compact tokamaks, unvalidated high-performance scenarios" (§7, Shared challenges).

However, the analysis does **not** explain why HESTIA's 1 GWe CAS22 is 4.95× the family median. The architectural divergences (continuous coils, liquid metal blanket) are qualitatively discussed, but there is no quantitative reconciliation. If continuous helical coils are cheaper than modular coils (per the §7 claim "HESTIA gains a cost advantage via simpler coil manufacturing if H = 1.3 is validated"), then HESTIA's C220103 should be *below* the family median, not at it. If the integrated blanket/divertor saves cost (C220108 = 0), then HESTIA's CAS22 should be *below* the family median, not 5× above it (at 1 GWe).

The sanity check flags the divergence; the analysis does not explain it. This is a **judgment gap**.

### Gaps and load-bearing assumptions

The analysis §6 lists 20 data gaps, ranked by criticality. The two most critical (blocking) are:
1. **WISE HTS conductor unit cost** (gap #1) — "blocking" because C220103 is the largest CAPEX item ($3.08B at native, 47% of CAS22) and is currently at library default (CFS ARC REBCO pricing for planar coils, which may not apply to 3D helical winding).
2. **Confinement enhancement factor H = 1.3 experimental validation** (gap #5) — "blocking" because if H = 1.0 (baseline heliotron), the plasma must run at higher density or field to achieve the same fusion power, which increases cost and may exceed the Sudo density limit (already a concern per analysis §2, §5).

The analysis correctly identifies these as load-bearing. If WISE conductor is 2× more expensive than library default, C220103 doubles, CAS22 increases by ~50%, and LCOE increases by ~$300–400/MWh. If H = 1.0 instead of 1.3, the plant may not reach 70.4 MWe net (Q_eng collapses), and the entire design is non-viable.

However, the analysis does **not** identify the 1 GWe scaling formula as a gap or assumption. The $904/MWh headline LCOE depends on the two-knob projection being valid for a 70.4 → 1000 MWe jump, which is unvalidated. This should be flagged as a load-bearing assumption.

## What I deliberately did not say

**Half-formed concern #1**: The AIP paper's $5B (1990s basis) direct construction cost is cited repeatedly (§1, §2, §5b, §6 gap #8) but is never reconciled with the library's native overnight cost of $6.58B (2025 basis, overrides on). If we inflate $5B by 2× (the AIP paper's suggested multiplier, line 119), we get $10B, which is 1.5× the library figure. This could mean (a) the AIP paper's $5B excludes accounts the library includes (e.g., CAS90 contingency, CAS60 construction services), (b) the library's defaults are conservative, or (c) the 2× inflation multiplier is wrong (should be 1.3× if using CPI-U from late 1990s → 2025). The analysis flags this as gap #8 ("CAS-level cost breakdown of the USD 5 billion") and gap #9 ("inflation adjustment methodology"), but never attempts a reconciliation. I want to say "the $5B anchor is too weak to validate the library output," but I cannot back this up without the full AIP paper (only the abstract is in the dossier) or a CAS-level breakdown. This is borderline out-of-scope for `model_critic` (it's a source-data question, not a modeling-artifact question), but it smells like a hidden divergence.

**Half-formed concern #2**: The analysis §5 lists `eta_th = 0.50` (sCO2 target efficiency) with spec key notation, but `model_setup.py` does not pass `eta_th` to the model. The design-point parameters table (§5) also lists "Availability / Capacity factor >80%" with spec key `availability`, but again, `availability` is not in the `spec` dict. Either (a) these are library defaults that match HESTIA's targets (so no override needed), or (b) the code is incomplete (should pass `eta_th` and `availability` explicitly). The deterministic contract check shows `ok`, so the library does not *require* these kwargs, but the analysis *promises* to use them. This is a spec-vs-implementation gap. I want to say "the code does not implement the spec," but the contract validator says otherwise, so maybe the library defaults are correct and the spec-key notation in §5 is just documentation. This is ambiguous.

**Half-formed concern #3**: The liquid metal blanket inventory (gap #11, §6) is estimated at ~$34M via a rough calculation (500 t, mixed alloy), but the analysis notes "the alloy composition is stated as 'tin-indium alloy with lead and lithium' with no percentages." The AIP paper (lines 226-228, per citations) warns "Tin is highly corrosive to steel and therefore careful consideration for corrosion protection is required." If corrosion forces blanket module replacement every 2–3 years instead of 6–10 years (tokamak blanket lifetime target), the CAS70 O&M cost could be 2–3× higher than library default. But the analysis does not quantify this sensitivity, and I cannot estimate it without knowing (a) blanket module lifetime under tin corrosion, (b) library default blanket replacement schedule, (c) remote handling time per module (gap #7). This is a cost-risk flag, not a deterministic error, but it could flip the LCOE by ±$100–200/MWh. I want to elevate it, but the data is too thin.

**Out-of-scope note on design-point selection**: The design-point block lists "alternatives_considered: SOARHER (alternative FPP candidate); FOAK commercial plant (Table I, Miyazawa & Goto 2023); HESTIA-Primary (prototype, Table I)" but does not explain *why* the reference operating case was chosen over the FOAK commercial plant.
