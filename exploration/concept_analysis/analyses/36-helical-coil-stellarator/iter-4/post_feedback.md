### F-1: Sensitivity table computed at back-solved design point misrepresents eta_th importance
- **Target:** Model output — sensitivity elasticity table and design point labeling
- **Category:** model
- **Finding:** The sensitivity elasticity table is computed at the back-solved design point (P_net=70.4 MWe, Q_sci>13), which the analysis explicitly states should NOT be used for cross-concept comparison (Section 7: "Use this result for cross-concept LCOE comparison — not the back-solved 70.4 MWe figure"). At the back-solved point, `eta_th` shows only −0.086 elasticity. The physics-forward sCO₂ sweep — computed at the correct Q=13 fixed design point — demonstrates that going from η_th=50% to η_th=40% changes LCOE from $1,502/MWh to $3,324/MWh (implied elasticity ~−3×). This is a factor of ~35× discrepancy. The sensitivity table as published will cause any automated cross-concept comparison to classify sCO₂ efficiency as a minor lever, directly contradicting the analysis narrative that it is "load-bearing." The r_coil elasticity (1.36) and availability elasticity (−0.96) may also shift at the physics-forward design point.
- **Recommendation:** Re-run the full sensitivity sweep at the physics-forward design point (Q=13 fixed, P_fus=260 MW, P_net≈52 MWe). Clearly label the sensitivity table header with which design point it applies to, and either replace the back-solved sensitivity table with the physics-forward one or report both with explicit labels. The model output should not present the back-solved sensitivities as the primary sensitivity characterization given that the back-solved point is already identified as a non-primary output.
- **Priority:** blocking

### F-2: H-factor LCOE penalty implausibly small relative to "blocking uncertainty" framing
- **Target:** Model output — H-factor scenario sweep and key assumption #13
- **Category:** model
- **Finding:** The H-factor scenario sweep reports only +1.1% LCOE change (Δ=+12.7 $/MWh) when H drops from 1.3 to 1.0, despite an 18.8% plasma volume increase. For a capital-dominated concept where C220103 (coils) represents 71% of RPE and has an r_coil elasticity of 1.36, this figure is implausibly small. Back-of-envelope: if coil cost scales with machine volume at fixed fusion power, an 18.8% volume increase would inflate C220103 by ~18.8%, contributing roughly 71% × 1.36 × 18.8% ≈ 18% LCOE increase — approximately 16× larger than the 1.1% reported. The model note acknowledges "not modeled directly in the framework; captured qualitatively as cost lower-bound caveat," but then presents the 1.1% figure in a comparison table alongside the base case as if it were a credible sensitivity result. The analysis calls H=1.3 a "blocking uncertainty" (Section 2, Section 6 Gap 5) — the +1.1% model output is inconsistent with this characterization and will cause readers to underweight the H-factor risk.
- **Recommendation:** Either (a) correct the H-factor cost scaling so that a volume increase at fixed fusion power inflates coil and blanket capital costs proportionally without Q-adjustment compensation, or (b) remove the 1.1% figure from the comparison table and replace it with an analytical estimate of the true penalty range (~15–20% LCOE impact based on the back-of-envelope above), clearly labeled as an estimate. If the framework cannot compute this correctly, the note should state the analytical estimate explicitly rather than presenting a near-zero model output that contradicts the analysis narrative.
- **Priority:** important

### F-3: Coil cost hypothesis lacks a pass/fail threshold for cross-concept positioning
- **Target:** Section 7 (cross-concept notes, modeling priority — coil cost upper-bound sweep)
- **Category:** analysis
- **Finding:** The analysis correctly identifies the continuous helical coil manufacturing premium as the dominant capital uncertainty and recommends a coil cost multiplier sweep (1×, 2×, 3× C220103), which the model implements. However, the analysis frames this as an action to perform rather than a testable hypothesis with an outcome-bounded conclusion. Goal 4 requires hypotheses stated as testable propositions. The critical question — at what coil cost multiplier does the continuous helical winding premium make HESTIA non-competitive relative to QI modular stellarators in the same portfolio — is never answered. The analysis establishes that the QI modular premium is 1.5–5× over wound tokamaks, and separately that HESTIA's coil cost is 71% of RPE, but never synthesizes these into a decision criterion: e.g., "If continuous helical coil manufacturing costs exceed 2× the modular coil baseline, HESTIA's physics-forward LCOE exceeds $2,900/MWh — above any QI modular stellarator design point in the portfolio and above the $1.76/kWh published-cost anchor — implying the concept can only close economically through NOAK fleet learning that has no quantitative basis." Without a stated threshold, the sweep generates scenario bounds but provides no analytical conclusion on whether the continuous helical coil architecture is compatible with competitive economics at any plausible manufacturing cost.
- **Recommendation:** Add a concluding sentence to the Section 7 coil cost modeling priority that states the threshold multiplier at which HESTIA's LCOE exceeds the highest-cost comparable stellarator concept in the portfolio (using the physics-forward design point, not the back-solved one), and state what happens economically above that threshold. This converts the multiplier sweep from a sensitivity exercise into a falsifiable test of the concept's economic viability.
- **Priority:** important
