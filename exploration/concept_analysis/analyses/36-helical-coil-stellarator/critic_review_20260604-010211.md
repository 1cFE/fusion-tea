# Critic Review — 36-helical-coil-stellarator

## Headline issues

1. **CAS22 outlier (4.53× median) is unexplained by any architectural divergence in the analysis** — The sanity check flags C220000 (total CAS22) at $51,787M vs. median $11,423M (4.53× ratio). The analysis walks through magnet architecture (continuous helical vs. modular coils) and blanket architecture (liquid metal with divertor elimination) but provides no quantitative bridge from these features to a 4.5× magnet cost multiplier. The family-delta section (§7) concludes HESTIA magnets are "comparable capital cost" to Proxima's modular coils and only "20-40% higher" than Thea's planar coils — nowhere near the 4.5× the model shows. Either the library is grossly mis-extrapolating 70.4 MWe → 1 GWe for helical geometry, or the analysis failed to identify a real cost driver (e.g., 46.2 GJ stored energy vs. comparables' lower fields). The analysis must reconcile this: read comparables' CAS22 native-scale values, identify which sub-account drives the 4.5× ratio (C220103 magnets? C220111 installation?), and either justify it architecturally or flag it as a library extrapolation artifact.

2. **Seven CAS22 sub-accounts are outlier-low (0.26–0.45× median) with no architectural explanation** — C220101 (first wall/blanket), C220102 (shield), C220105 (primary structure), C220106 (vacuum), C220107 (power supplies), C220108 (divertor, overridden to zero), C220110 (remote handling) all fall 55–74% below comparables. The analysis attributes divertor elimination (C220108 = 0) to liquid metal architecture, but the *other six accounts* show comparable magnitude divergence with no mention. If HESTIA's 70.4 MWe scale drives these down, why is CAS22 total 4.5× *high*? The pattern suggests the library is simultaneously under-costing subsystems (blanket, shield, structure) and over-costing something else (magnets or installation) at 1 GWe projection. The analysis does not surface this incoherence. Either the library's stellarator scaling is broken for 14× extrapolations (the analysis's CRITICAL CAVEAT acknowledges this but doesn't follow through to per-account diagnosis), or HESTIA's architecture justifies the asymmetry and the analysis missed it.

3. **P_fus coherence gap is acknowledged but not validated** — The design-point table (§5) includes a "P_fus validation note" warning that the library back-solves P_fus from energy balance (P_native, p_input, thermal efficiency, blanket multiplication) and "may not match the design point's stated 250 MW." The note flags thermal efficiency ambiguity (41% Table I vs. >50% text claim) as a potential source of divergence. The analysis does not follow through: no diagnostic output of library-inferred P_fus, no cross-check against the 250 MW target, no sensitivity to η_th. Data Gap #7 calls η_th reconciliation "blocking," but the override registry is empty on this dimension. If the library assumes 50% efficiency and back-solves P_fus to 200 MW (not 250 MW), the entire cost model is misaligned with the design point. The artifacts provide no evidence this was checked.

4. **Liquid metal pump power flagged as "blocking" data gap, but no override or bounding analysis** — Data Gap #1 calls LM pump power "truly-unknown" and "blocking" because "if LM pump power exceeds ~5–10 MW (beyond the 20 MW ECRH and cryogenic loads), the net electric output drops below 60 MWe, degrading the already-marginal economics." The analysis acknowledges this could swing P_native by 15% but proposes no override, no bounding calculation, no sensitivity sweep. The spec passes `p_input=20.0` (ECRH only) with no LM pump term, implying the library's auxiliary power model either doesn't account for liquid-metal circulation or buries it in a generic stellarator auxiliary fraction. Either way, the analysis knows this is a first-order uncertainty and does nothing to bound its LCOE impact. A bounding override (5 MW and 15 MW LM pump scenarios) or an explicit "library does not model this, native-scale LCOE is unreliable" flag is required.

5. **Override count = 1 (divertor only) despite "Moderate" data availability and numerous architectural divergences** — The override registry contains one enabled entry (C220108 divertor = 0) and one disabled conditional (C220104 gyrotrons). The analysis walks through liquid metal blanket material (tin-In-Pb-Li, no cost data), high-Mn steel structure (no cost data), WISE HTS conductor (km-scale REBCO, no tape-length calculation), sCO₂ Brayton cycle (efficiency ambiguity), and 60× 250 GHz gyrotrons (unit cost derivable at $1M/tube = $60M), yet concludes "no override proposed" for all but divertor. This is defensible if library defaults are trusted, but the analysis rates data availability as "Moderate" (not High) and flags multiple "important" or "blocking" data gaps. The mismatch between gap severity and override discipline suggests either (a) the analyst over-stated gap criticality, or (b) the override discipline is too conservative, leaving known divergences unmodeled. The count_smell check shows `status: ok` (1 override consistent with High archetype fit), but the *qualitative* assessment in the analysis implies more overrides are justified.

## Detailed reasoning

### Deterministic-flag interpretation

**dpc (P_native coherence): status ok** — The three-leg coherence check (design-point table 70.4 MWe, `analysis.md` §5 P_NE = 70.4 MWe, `model_setup.py` P_native = 70.4) passes. The design point is unambiguous: Table I of Miyazawa & Goto (2023) states P_NE = 70.4 MWe, and all artifacts align. No interpretation needed — this is clean.

**contract (module structure): status ok** — `model_setup.py` uses the `run_native_and_1gw` helper form (forward 2/3), satisfies the six-field override schema, and produces valid `result_1gw` output. The contract is structurally sound. No issues.

**count_smell (override count vs. archetype fit): status ok** — One enabled override (C220108) falls within the 0–4 band expected for High archetype fit. The deterministic check is satisfied. However, the *judgment* question remains: does the analysis's extensive gap inventory (15 gaps, 5 flagged "blocking") justify more overrides? The count is consistent with the archetype grade but potentially inconsistent with the analyst's own assessment of data sufficiency. This is a qualitative tension, not a deterministic error — addressed in "Override discipline" below.

**sanity (outlier accounts): status flagged, 18 accounts** — This is the critical flag. CAS22 total is 4.53× median; seven CAS22 sub-accounts are 0.26–0.45× median (outlier-low); five top-level accounts (CAS30, CAS50, CAS60, CAS90) are 3.50–4.26× median (all scale with CAS22). The pattern is: (1) CAS22 total explodes at 1 GWe projection, (2) within CAS22, some accounts shrink (blanket, shield, structure) while others must be driving the explosion (magnets or installation), (3) downstream accounts (indirect costs) inherit the explosion. The analysis does not surface this incoherence. The family-delta section (§7) compares HESTIA to five stellarator concepts and concludes cost deltas are 5–60% (Thea +5–15% on magnets, Proxima –25–40% overall, Gauss –40–60% on scale, Type One –35–55%, Renaissance –40–70% conditional). None of these deltas approach 4.5×. Either (a) the comparables' CAS22 values at 1 GWe are similarly inflated (the library's stellarator archetype over-costs magnets universally, and HESTIA is merely the most extreme example), or (b) HESTIA has a real architectural cost driver the analysis missed (e.g., continuous helical coil winding at 1 GWe scale requires 10× the REBCO tape length of modular-coil concepts due to poor winding-pack utilization). The analysis must diagnose which. **Action required**: Read comparables' `model_output.txt` CAS22 values at 1 GWe. If all stellarators show CAS22 = $40–60B (4–5× tokamak baseline), the library's stellarator archetype is over-costing universally, and this is a library artifact, not a HESTIA-specific issue. If HESTIA alone is 4.5× and comparables are 1.5–2×, the analysis missed a real cost driver.

**drift (live recomputation vs. artifact): not present** — The import succeeded, and no drift block appears, implying the recorded `model_output.txt` matches today's library computation. Clean.

### Spec coherence (beyond P_native)

The design-point block (§1 of `analysis.md`) describes a single named plant: **HESTIA Fusion Pilot Plant — reference operating case (Miyazawa & Goto, Phys. Plasmas 2023)**. All parameters in §5 cite Table I of the same paper or derive from it (e.g., a_eff inferred from plasma volume). The analysis does reference company announcements (October 2025 HTS coil milestone, GALOP blanket test system) but only as technology-readiness updates, not as sources of parameter stitching. The LCOE-parameters table (§5) is internally consistent: R₀ = 7.8 m, B = 5.0 T, P_fus = 250 MW, P_NE = 70.4 MWe all come from the same Table I. **No stitching detected.**

However, the analysis does note one **presentation ambiguity** (not stitching): thermal efficiency is stated as ">50%" in §II.F of the paper but Table I implies 41.2% (139 MWe / 337.5 MW thermal). The analysis flags this as Data Gap #7 ("blocking") and recommends using 41% as the grounded value. The spec does not pass `eta_th` (correctly — this is a library-owned parameter, not a design-point input), so the library will use its default sCO₂ Brayton efficiency. The P_fus validation note (§5) warns that if the library assumes 50% and the design point achieved 70.4 MWe at 41%, the back-solved P_fus will diverge. This is a **coherence risk**, not a realized coherence failure. The analysis identifies it but does not validate whether it fired. **Recommendation**: Emit a diagnostic override that forces a specific η_th or P_fus crosscheck, or explicitly state "the library's sCO₂ efficiency assumption is unknown; if it differs from 41%, P_fus coherence is broken."

### Override discipline (judgment)

**C220108 (divertor = 0, enabled)** — The override is well-justified. The AIP paper explicitly states "individual divertor systems are not required in HESTIA" (§II.C), the liquid metal free-surface flow covers divertor strike zones, and the model output confirms the library does NOT auto-zero divertor cost for liquid-metal stellarators (generic C220108 = $36.6M at 70.4 MWe scale). The provenance is `direct` (not derived — the paper directly states no divertor), the source citation is specific (§II.C), and the rationale explains why the library default is inapplicable. **Override discipline: excellent.**

**C220104 (gyrotrons, disabled conditional)** — The override candidate proposes 60 gyrotrons × $1M/tube = $60M based on ITER procurement pricing for 170 GHz units, scaled to 250 GHz. The rationale correctly flags uncertainty: "the AIP paper's USD 5 billion construction cost (Table I) is 1990s-basis and explicitly flagged as requiring 'factor of 2 or more' inflation adjustment, making it unreliable. Disabled pending validation of whether 1costingFE's ECRH cost model at 20 MW input adequately captures 250 GHz CW gyrotron costs." This is cautious and defensible, but the analysis could have done more: (1) Check the model output's C220104 value (generic = $100M, native = $100M, 1 GWe = $100M — no scale dependence, suggesting library uses a per-MW-input cost model). (2) Compare $100M (library) vs. $60M (override) — the library is 67% higher, which is within the "factor of 2 or more" inflation uncertainty the analysis cites. The override is therefore unlikely to move LCOE materially. **Judgment**: Disabling this override is defensible, but the analysis should have explicitly noted "library default $100M exceeds our derived $60M, so no override needed" rather than leaving it as "pending validation."

**C220103 (magnets, no override proposed)** — The analysis identifies WISE HTS conductor and 46.2 GJ stored energy as proprietary, notes REBCO tape cost sensitivity ($50–100/kA-m current vs. <$10/kA-m target), and concludes "no override proposed pending tape-length calculation." This is where override discipline becomes questionable. The stored energy (46.2 GJ) and on-axis field (5.0 T, max 8.79 T at coil) are known. The magnet cost model in 1costingFE likely scales with stored energy and field, not directly with tape length. A **bounding override** is feasible: if REBCO costs $100/kA-m today and the library assumes $10/kA-m (NOAK target), magnets are under-costed by 10×. The model output shows generic C220103 = $2,814M (native scale). If this is based on $10/kA-m REBCO, the FOAK cost is $28B — completely implausible, suggesting the library is already using a higher REBCO price or a different cost basis ($/J stored energy). The analysis does not investigate. **Judgment failure**: The analysis correctly identifies magnet cost as uncertain but does not bound the uncertainty or check whether the library default is conservative or aggressive. Given CAS22 total is flagged as 4.53× median outlier, and C220103 is the single largest CAS22 sub-account ($2.8B at native scale), this is the most likely driver of the outlier and deserves a bounding override or explicit statement that library assumptions are trusted.

**C220101 (blanket, no override proposed)** — The analysis notes "liquid metal blanket with free-surface flow is architecturally distinct from the library's default solid breeder or FLiBe assumptions, but the dossier provides no company-grounded unit cost for tin-In-Pb-Li alloy." This is defensible if the library's liquid-metal blanket archetype is trusted, but the sanity check flags C220101 as 0.27× median (outlier-low). The analysis does not explain why HESTIA's blanket costs 73% less than comparables' blankets. Is it because (a) the liquid metal eliminates solid breeder fabrication (real architectural advantage), (b) HESTIA's 70.4 MWe scale has less blanket area than 1 GWe comparables (scale effect), or (c) the library under-costs liquid metal blankets? The analysis does not reason through this. **Judgment gap**: The outlier-low accounts (C220101, C220102, C220105, etc.) are flagged numerically but not interpreted. If these are real architectural advantages, the analysis should celebrate them ("liquid metal blanket costs 70% less than solid breeder, per library model"). If they're library artifacts, the analysis should flag them as unreliable.

**C220107 (power supplies, no override proposed)** — Flagged as 0.32× median. HTS coils at 20 K don't need DC resistive power supplies during steady-state (only startup/shutdown and quench protection). The outlier-low value makes sense architecturally (HTS advantage over resistive coils), but the analysis doesn't say this. **Minor judgment gap** — the reasoning exists implicitly (§3 mentions "HTS coils at 20 K require cryogenic power (2% of P_gross stated) but not DC resistive power supplies") but is not connected to the sanity-check flag.

**Overall override discipline**: The single enabled override (divertor) is exemplary. The disabled conditional (gyrotrons) is defensible but could be tighter. The **absence** of magnet, blanket, and LM-pump overrides is the concern — not because overrides are required (library defaults may be adequate), but because the analysis identifies large uncertainties (Data Gaps #1, #2, #5 are "important" or "blocking") and does nothing to bound them. The override registry should either (a) contain bounding overrides for these accounts, or (b) explicitly state "library defaults are trusted despite data gaps because [reason]."

### Two-knob projection (judgment)

The CRITICAL CAVEAT at the top of `model_setup.py` and in §2 of `analysis.md` acknowledges that 1 GWe projection from 70.4 MWe (14× scale-up) is "beyond the library's reliable range" for stellarators. The model output shows 1 GWe overnight cost = $78,466/kW and LCOE = 829 $/MWh, which the analysis calls "implausibly high even for FOAK stellarators." This is self-aware and correct. The caveat concludes: "The 1 GWe projection should be treated as a diagnostic output illustrating scale-up challenges, not a credible cost estimate."

**Judgment question**: Do the per-account `result_1gw` values reveal any architectural reason *why* HESTIA scales poorly? The sanity check flags CAS22 (magnets) as 4.53× comparables. The analysis does not follow through: is this because (a) continuous helical coils scale worse than modular coils (winding complexity grows non-linearly with major radius), (b) the library's stellarator archetype over-costs magnets universally (all five comparables show similar CAS22 inflation, not HESTIA-specific), or (c) something else? The two-knob projection is **implausible**, the analysis **acknowledges** it, but the analysis does not **diagnose** it. This is a missed opportunity — the 1 GWe projection is unreliable, but *why it's unreliable* (which scaling assumptions break down) is useful information for understanding HESTIA's architectural constraints.

**Specific implausibility**: CAS22 jumps from $3.8B (native, 70.4 MWe) to $51.8B (1 GWe). That's a 13.7× increase for a 14.2× power increase, implying near-linear scaling (exponent ~0.97). But stellarator magnets should scale *worse* than linear (stored energy scales with volume ~ R³, power scales with surface area ~ R², so magnets-per-watt should grow as ~R). If anything, CAS22 should grow faster than 14×, not slower. The near-linear scaling suggests the library is applying a favorable economies-of-scale factor (NOAK learning curve) that partially offsets geometric scaling. The analysis does not unpack this. **Recommendation**: Either (a) disable the 1 GWe projection entirely (if it's unreliable, why emit it?), or (b) diagnose which accounts drive the impla usibility and state whether it's a library artifact or a real HESTIA constraint.

### Family delta vs comparables

The analysis's §7 provides detailed qualitative comparisons against five stellarator concepts and concludes HESTIA is "~20–50% higher $/kW than utility-scale stellarator comparables due to small scale, partially offset by divertor elimination" and "cost-competitive with other small-scale stellarators (Thea)." The sanity check flags 18 outlier accounts, including CAS22 at 4.53× median. **These are irreconcilable.**

If HESTIA is 20–50% more expensive than comparables (as §7 claims), CAS22 should be 1.2–1.5× median, not 4.5×. If CAS22 is truly 4.5× median, HESTIA is 4× more expensive than comparables, not 1.2–1.5×. The analysis does not address this. Possible explanations:

1. **The comparables' CAS22 values are also inflated** — If all stellarators in the comparison set show CAS22 = $40–60B at 1 GWe (4–5× tokamak baseline), then 4.53× is not a HESTIA outlier; it's a stellarator-archetype universal over-cost, and the "median" is itself inflated. The analysis should check this: read `05-planar-coil-stellarator/model_output.txt`, `09-qi-stellarator-hts/model_output.txt`, etc., and compare CAS22 at 1 GWe. If they're all $40–60B, the outlier flag is a false alarm (HESTIA is typical for stellarators, but stellarators as a family are outliers vs. tokamaks).

2. **The analysis's 20–50% delta is qualitative, the sanity check is quantitative** — The §7 comparisons are *architectural reasoning* ("modular coils are cheaper to wind," "QI optimization reduces plasma volume by 15–25%"), not *numerical cost-model comparisons*. The analysis may have reasoned about what *should* differ without checking what the library *actually* outputs for comparables. If Proxima Fusion's `model_output.txt` shows CAS22 = $12B and HESTIA shows $52B, the 4.3× ratio is real, and the §7 claim of "comparable capital cost" is wrong.

3. **HESTIA's small native scale (70.4 MWe) breaks the 1 GWe projection more severely than comparables' larger native scales** — If Proxima's design point is 500 MWe (2× scale-up to 1 GWe) and HESTIA's is 70.4 MWe (14× scale-up), the library's extrapolation error is larger for HESTIA. This would explain why HESTIA's 1 GWe projection is "implausibly high" while comparables' projections are merely "high." The analysis hints at this (CRITICAL CAVEAT mentions 14× scale-up) but does not connect it to the family-delta divergence.

**Action required**: The analysis must reconcile §7's qualitative deltas with the sanity check's quantitative outliers. Either (a) read comparables' numerical outputs and confirm HESTIA is 4× more expensive (revising §7's conclusions), (b) confirm all stellarators are 4× inflated and the median is misleading (explaining why the outlier flag is a false alarm), or (c) state "§7's architectural reasoning is conceptual; numerical comparison awaits comparables' cost-model outputs."

### Gaps and load-bearing assumptions

The analysis's §6 identifies 15 data gaps, 5 flagged "blocking." The two most load-bearing for LCOE:

1. **Gap #9: Subsystem-level cost breakdown for USD 5B HESTIA construction cost (1990s-basis)** — The AIP paper's aggregate cost figure is unusable (explicitly flagged as outdated, requiring 2× inflation, no CAS decomposition). The analysis correctly calls this "blocking" and notes "a bottom-up reconstruction from subsystem unit costs is required." The current model relies entirely on library defaults (no capital-cost overrides except divertor). If the library's stellarator archetype over-costs magnets by 2× and under-costs blankets by 2×, the LCOE is wrong by ~30–50% (CAS22 is ~66% of overnight cost). **Load-bearing assumption**: The library's STELLARATOR archetype adequately models HESTIA's continuous-helical-coil + liquid-metal-blanket architecture at 70.4 MWe scale, despite having no subsystem-level validation against HESTIA's published cost figure.

2. **Gap #1: Liquid metal pump electrical power consumption** — The analysis states "if LM pump power exceeds ~5–10 MW (beyond the 20 MW ECRH and cryogenic loads), the net electric output drops below 60 MWe, degrading the already-marginal economics." P_native = 70.4 MWe is a 10 MW uncertainty (14% swing). The spec passes `p_input=20.0` (ECRH only), implying LM pump power is either (a) zero (library doesn't model it), (b) buried in a generic auxiliary fraction, or (c) derived from blanket thermal power. The analysis does not validate which. **Load-bearing assumption**: LM pump power is negligible or adequately captured by library defaults, despite the AIP paper explicitly stating it is "quite unknown" (§II.C).

If Gap #9 is resolved and the library's CAS22 is found to be 2× too high, and Gap #1 is resolved and LM pump adds 10 MW recirculating load, HESTIA's LCOE could swing by 50–100% (doubling CAS22 adds ~35% to LCOE; losing 10 MWe of P_native adds another ~15%). These are first-order uncertainties, not refinements.

**Other load-bearing assumption** (not in gap inventory): **Thermal efficiency η_th = 41% vs. 50%** — The P_fus validation note (§5) warns this could break P_fus coherence. If the library assumes 50% and back-solves P_fus to 200 MW instead of 250 MW, the fusion power is under-estimated by 20%, and LCOE is over-estimated by ~20% (less fusion power requires higher $/kW capital to hit the same P_native). The analysis flags this as Data Gap #7 but does not bound its impact.

## What I deliberately did not say

**Source quality** — The analysis relies on an AIP paper abstract extraction (aip-2023-paper-abstract.md, 58 KB) rather than the full paywalled paper. The note in §8 states "detailed appendices (if present in the full paper) may contain subsystem cost breakdowns, 3D neutronics results, and thermal cycle calculations that would close Data Gaps #3, #7, #8, #9." I did not critique whether the analyst should have obtained the full paper, as source-quality decisions are upstream `research`-stage concerns. However, if Gap #9 (cost breakdown) is blocking and the full paper contains it, the analysis is incomplete through no fault of the modeling stage — the dossier should have included the full paper. This is a `research`-stage process issue, not a `model_critic` issue, but I flag it for awareness.

**Comparables' numerical outputs** — The family-delta section (§7) provides rich architectural reasoning but no numerical cross-checks against comparables' `model_output.txt` files. I cannot tell whether the 20–50% qualitative deltas match the sanity check's 4.53× quantitative outlier because I have not seen comparables' CAS22 values. The analysis should have read at least one comparable's output (e.g., `05-planar-coil-stellarator/model_output.txt`) to validate the magnitude. This is not a deterministic failure (the contract validator doesn't require comparables reads), but it's a judgment gap — the analyst reasoned conceptually when numerical validation was one file-read away.

**REBCO tape length calculation** — The analysis identifies HTS conductor cost as uncertain (Gap #5: "derivable, important") and notes REBCO tape cost sensitivity ($50–100/kA-m vs. <$10/kA-m target) but does not attempt the derivation. The stored energy (46.2 GJ), field (8.79 T max), and coil geometry (R₀ = 7.8 m helical winding) are sufficient to estimate tape length via E_stored = ½LI² and L ~ μ₀N²A/ℓ. This is a "derivable" gap, meaning the analyst could have closed it with 30 minutes of back-of-envelope calculation and a magnet-physics reference. I did not critique the absence of this calculation because the analysis explicitly flags it as a gap and proposes no override (consistent with deferring the calculation). However, given CAS22 is the headline outlier, closing this gap would materially improve confidence in whether the library's C220103 ($2.8B) is reasonable or not.

**Divertor-elimination cost validation** — The C220108 override zeros divertor cost based on the AIP paper's statement that "individual divertor systems are not required." The model output shows generic C220108 = $36.6M (native scale). The analysis does not validate whether $36.6M is plausible for a stellarator divertor at 70 MWe scale. If the library's default is too low (e.g., tokamak divertors at similar scale cost $100–200M), the override's LCOE impact is understated. If the default is too high (stellarators have simpler divertors than tokamaks), the override's impact is overstated. I did not pursue this because the override direction is unambiguous (HESTIA has no divertor, so cost = 0 is correct), but the *magnitude* of the benefit (how much $ is saved) depends on whether the library's default is accurate. This is a second-order concern — the override is right, but we don't know by how much it matters.
