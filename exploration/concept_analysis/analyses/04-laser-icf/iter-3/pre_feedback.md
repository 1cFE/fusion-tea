### F-1: CAS21 override embeds a wrong per-module/n_mod NOTE and an unstated (monolithic) baseline
- **Target:** model_setup.py overrides list — the `CAS21` entry (`"account": "CAS21"`, `"value": 0.50 * generic.costs.cas21`, currently at model_setup.py:168–192). This is the ONLY override to change.
- **Category:** model
- **Finding:** The CAS21 override's rationale ends with this NOTE, which is factually wrong: *"NOTE: CAS21 is a per-module account. At 1 GWe (n_mod=2) the output shows the same per-module value (139.9 M$) as native; total plant CAS21 is 139.9 * 2 = ~279.8 M$, handled by n_mod aggregation downstream. The apparent lack of scaling is correct per-module behavior, not a bug."* CAS21 (buildings) is a **Class-S / shared account**: the costingfe library computes it per module and does **NOT** multiply it by `n_mod`. In the replicated 1 GWe fleet it is **charged once** (that single charge is the fleet amortization) — there is no `139.9 * 2` aggregation; the headline plant carries CAS21 ≈ one module's buildings, not two. So `0.50 * generic.costs.cas21` does not deliver "50% of a 1 GWe plant's buildings" — it delivers 50% of **one 500 MWe module's** buildings, charged once for the whole fleet. Separately, the rationale's "50% reduction reflects elimination of ~half the building scope of a DT IFE plant" silently anchors to a conventional/monolithic-plant baseline. Per the 1 GWe override policy (`.project/reports/2026-06-06-1gw-estimate-policy.md`, Part 4 Rule 3): *"Every relative override `M * generic.costs.X` means 'M of the library's natural answer for that account in the replicated 1 GWe fleet.' Anchor the rationale to the same frame as the value. Under the modular decision, the baseline is 'the library's default for a fleet of this device,' not 'a conventional 1 GWe monolithic plant' … the monolithic baseline simply does not exist, so don't invoke it."*
- **Recommendation:** (1) **Retract the NOTE entirely** — delete the "CAS21 is a per-module account … not a bug" sentences; do not append a correction beside them, the file must end internally consistent. (2) **Re-anchor the rationale to the modular-fleet frame**: state explicitly that `0.50 ×` means "50% of the library's default Class-S building scope for a fleet of this laser-ICF module at 1 GWe (a single shared, once-charged building cost)", justified by the eliminated facilities (tritium processing, hot cell, biological shielding, cryogenic target prep). Drop any "conventional/DT-IFE 1 GWe plant" baseline phrasing. (3) **Value choice is yours:** either keep `0.50 * generic.costs.cas21` now that the rationale owns the modular-fleet meaning, OR convert to an absolute `M$` figure you would defend as the fleet's once-charged building cost — whichever you can justify; name the choice in the rationale. (4) **No-touch:** change ONLY the CAS21 entry. Preserve bit-for-bit every other override in this file — C220101, C220102, C220107, C220108, C220110 (Class-U `cas22_detail`), CAS27 (absolute), and the disabled CAS70/CAS80 entries. Do not re-author, re-order, or re-number them.
