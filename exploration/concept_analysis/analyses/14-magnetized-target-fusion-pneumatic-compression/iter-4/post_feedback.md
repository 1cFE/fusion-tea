### F-1: Target factory and driver scaling leaking through non-overridden cost accounts
- **Target:** Model cost accounting — CAS220500, driver_mag_target_per_mw constant
- **Category:** model
- **Finding:** `target_factory_base` has elasticity +0.076 and `driver_mag_target_per_mw` has elasticity +0.156 despite (a) the concept having no per-shot consumables and (b) the compression driver being explicitly overridden to $180M flat (C220104). These sensitivities indicate both constants are actively contributing to the LCOE calculation through non-overridden cost accounts. CAS220500 (Fuel Handling DT) at $51.7M is conspicuously large for a concept with no target factory — comparable to the liquid metal wall ($47.8M) — suggesting it is absorbing target-factory costs via framework defaults rather than representing only tritium/deuterium fuel processing. If target_factory_base is non-zero in the effective calculation, the concept's stated OPEX advantage ("no per-shot consumables") is not being captured correctly, corrupting the cross-concept comparison.
- **Recommendation:** Audit which cost accounts target_factory_base and driver_mag_target_per_mw feed into within the 1costingFE framework. Zero out any target-factory cost paths (these should not contribute to CAS220500 for this concept). Verify that driver_mag_target_per_mw is either overridden or explicitly set to reflect only the compression driver ($180M anchor), not a per-MW driver+magnet+target scaling formula. If CAS220500 incorporates target costs, split it into a fuel-only account and zero the target portion.
- **Priority:** blocking

### F-2: Rep rate near-zero elasticity contradicts analysis claim of primary LCOE lever
- **Target:** Sensitivity results and model structure
- **Category:** model
- **Finding:** The analysis identifies rep rate as "the single highest-leverage parameter" with LCOE ∝ 1/rep_rate (halving rep rate doubles LCOE from identical capital). The model shows f_rep with only -0.032 elasticity — effectively irrelevant — while availability dominates at -0.980. The discrepancy arises from the model anchoring on fixed 300 MWe net output: varying f_rep while holding net output constant changes only peripheral costs, not the primary capital-to-energy ratio. But the analysis's actual claim is that a plant built for 1 Hz cannot deliver 300 MWe at 0.5 Hz without a cost penalty — the capital was sized for the higher rep rate. This scaling is absent from the model, making the sensitivity profile inconsistent with the analysis narrative.
- **Recommendation:** Add a rep-rate-to-capital cost link in the model: the compression driver cost (C220104) and vessel/structure costs should scale with pulse energy, which increases as rep rate falls for fixed net output. Concretely, if net output = E_pulse × f_rep × η_th × CF, then reducing f_rep from 1 Hz to 0.5 Hz at fixed net output requires doubling E_pulse, which scales the compression system cost. Implement this as either a parametric scaling of C220104 with f_rep, or add an explicit rep-rate sensitivity scenario (e.g., run at 0.3, 0.5, 1.0, 2.0 Hz with capital rescaled accordingly) so the analysis claim about LCOE doubling at 0.5 Hz is verifiable from the model output.
- **Priority:** blocking

### F-3: Li vs. PbLi scenario branches not implemented despite H2 identifying them as first-order
- **Target:** Model scenarios and H2 (liquid metal composition as LCOE branch)
- **Category:** model
- **Finding:** The analysis correctly identifies Li vs. PbLi selection as a "first-order LCOE branching decision" (H2) with bifurcating cost implications: ISS capital dominates in PbLi (>80% tritium in separation system), blanket extraction dominates in Li (>60% in blanket); safety infrastructure capital differs significantly (Li fire/explosion mitigation vs. PbLi's more benign handling); and the tritium permeation barrier cost differs by wall chemistry. The model implements only one scenario and explicitly notes "Not modeled as separate scenarios here." Given that the analysis frames H2 as testable and as a primary cost branch, the gap between the framing and the implementation is significant — the model output cannot speak to one of its own stated hypotheses.
- **Recommendation:** Implement two explicit scenarios — one anchored on Li wall (higher safety infrastructure, blanket-extraction ISS) and one on PbLi wall (larger ISS capital, lower fire hazard cost). The primary cost difference to model is the isotope separation system capital (CAS220500 or a dedicated ISS account): for PbLi, ISS capital should be substantially larger since >80% of tritium must be processed there. A rough bounding estimate (e.g., ISS at $50M vs. $150M for Li vs. PbLi) would suffice to show whether the branching materially changes LCOE or whether the two scenarios converge. The model notes should reference this as H2-test output.
- **Priority:** important
