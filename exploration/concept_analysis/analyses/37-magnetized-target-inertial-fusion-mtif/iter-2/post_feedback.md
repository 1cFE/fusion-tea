### F-1: Base LCOE excludes rail consumable O&M — the dominant operating cost
- **Target:** Model output (base LCOE) and model_setup.py sensitivity structure
- **Category:** model
- **Finding:** The headline LCOE of 189 $/MWh accounts for rail wear only through the availability parameter (availability = 0.40) but excludes the direct per-swap consumable cost (materials + labor). The model presents rail consumables as a separate additive delta-LCOE table, which is correct methodology — but the base case effectively assumes zero consumable cost, making 189 $/MWh a theoretical lower bound rather than a representative scenario. At the best-documented rail life (400 shots, $10k/swap), the delta is +450 $/MWh, making the true LCOE ~640 $/MWh. The analysis text itself explicitly states that "treating it only as an availability reduction understates the operating cost burden" — yet the base model does exactly that. The current structure gives a misleading headline number.
- **Recommendation:** Add a representative base-case scenario that includes rail consumable costs at the most credible rail life assumption (e.g., documented 400-shot upper bound as pessimistic case, 3,000-shot development target as optimistic case). Make the 189 $/MWh explicitly labelled as a "zero-consumable floor" rather than the nominal result. The model output's headline LCOE should reflect the scenario the analysis narrative treats as most plausible, not the most optimistic possible.
- **Priority:** blocking

### F-2: Key differentiators from the reference concept not explicitly enumerated
- **Target:** Section 7 (Cross-Concept Notes) and overall framing
- **Category:** analysis
- **Finding:** The analysis discusses NearStar's distinguishing features throughout Sections 2–4 and 7, but never presents them as a compact explicit list. The checklist requires that key differentiators from a conventional tokamak (or nearest approved comparator) be explicitly listed — not implied across several sections. A reader building a TEA model must synthesize differentiators from the challenge narrative (D-D physics, railgun wear), the materials section (no REBCO, no tritium), and the cross-concept notes. More importantly, the cost implication of each differentiator (advantage / penalty / neutral) is not systematically mapped. The coal-plant retrofit strategy is discussed qualitatively but its CAS-level implication (eliminates CAS23 turbine investment, potentially eliminates site cost) is never stated. The railgun driver capital premium over pneumatic piston is named in Section 7 but not tied to a CAS account or a specific order-of-magnitude penalty in the analysis text.
- **Recommendation:** Add an explicit differentiator table in Section 7 (or a new Section 2 subsection) listing each key departure from the nearest comparator (General Fusion pneumatic MTF as the closest approved analog), with a one-line cost implication for each: D-D fuel (penalizes gain; eliminates tritium and REBCO costs), railgun driver (capital premium vs. pneumatic baseline — 5–10× per the model scenarios), no external magnets (eliminates HTS magnet cost), coal-plant retrofit (potentially eliminates CAS23 and site civil costs — if thermal matching is solved), molten Pb first wall non-breeding (eliminates Li-6 supply chain). This structured mapping is what Goal 3 requires.
- **Priority:** important

### F-3: Modeling approach not stated; key hypotheses not framed as testable propositions
- **Target:** Section 2 (Challenges) and any modeling recommendation section
- **Category:** analysis
- **Finding:** The analysis does not state whether the costingfe framework or free-form modeling is appropriate for this concept, nor does it explain why. The challenge narrative includes a breakeven calculation (Section 2, Challenge 3: achieving 0.70 availability requires rail life ≥ ~12,000 shots), which is the right analytical move — but this is embedded in prose rather than stated as a testable model hypothesis. The model should be testing specific propositions; the analysis should declare what those propositions are. As written, the challenges read as open questions ("this is uncertain") rather than bounded tests ("if parameter X crosses threshold Y, the concept becomes economically viable / non-viable"). The analysis never says which of the two model forms was used or why.
- **Recommendation:** Add a short modeling approach statement: (1) declare free-form modeling as the appropriate method given the absence of any public NearStar system design data, and note which costingfe defaults are being adapted; (2) restate the two or three challenges as explicit falsifiable hypotheses with threshold values — e.g., "H1: Rail life ≥ 12,000 shots/swap is necessary (not sufficient) for availability ≥ 0.65 and LCOE ≤ 120 $/MWh at $10k/swap — this is the single most important engineering milestone to watch. H2: Q_eng ≥ 10 is the minimum gain at which the energy balance closes for a 200 MWe plant at η_th = 0.35 and η_pin = 0.25." These thresholds are derivable from the model's own sensitivity output and give the model specific targets to test.
- **Priority:** important
