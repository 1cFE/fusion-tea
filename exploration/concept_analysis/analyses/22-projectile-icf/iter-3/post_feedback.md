VERDICT: FINDINGS

### F-1: C220108 value is derived as an annual operating cost but placed in a capital account
- **Target:** Section 5b (Override Candidates), C220108 entry
- **Category:** analysis
- **Finding:** The C220108 override value ($5.6M) is derived as an annualized viability ceiling: "$5.58M/year annualized target factory + consumables cost." The rationale explicitly states "Value represents the annualized target-factory viability ceiling in $M/year." But C220108 is a capital cost account (target factory equipment), not an annual operating cost. The derivation produces a $/year figure (annual target procurement cost at ~$5.6/target × ~1M targets/year) and places it in a capital account denominated in $M of installed equipment. This conflates two different cost categories: (a) the capital cost of building a target factory capable of producing ~1M complex targets per year, and (b) the annual cost of operating that factory and procuring targets. The model consequently carries $5.6M as a capital cost, which is implausibly low for a factory producing 1M precision fusion targets annually — even if individual targets cost only $5.6 each, the factory itself (tooling, cleanrooms, automation, QA) would cost substantially more than $5.6M to build.
- **Recommendation:** Decide whether C220108 represents (a) the capital cost of the target factory (in which case derive it from factory construction analogues, not from annual target procurement revenue) or (b) an annualized consumable cost (in which case it belongs in CAS80 or a target-consumable line, not in C220108). If the intent is a capital-cost override, re-derive from the factory's construction cost at the required throughput (~1M targets/year). If no factory capital estimate is available, state that explicitly and either disable the override or document the value as a placeholder capital proxy with a clear caveat that it is not an annual-cost figure.
- **Priority:** important

### F-2: Analysis promises a target-cost sensitivity sweep that the model does not implement
- **Target:** model_setup.py
- **Category:** model
- **Finding:** The analysis references a "$1–$20/target sensitivity sweep" in two places: the C220108 override rationale ("the model carries a target-cost sensitivity sweep ($1–$20/target annualized) to bound this uncertainty") and Data Gap #5 ("model carries $1–$20/target sensitivity sweep to bound the range"). However, `model_setup.py` contains no sweep, scenario, or sensitivity code — it runs only the three-forward helper (generic, native, 1 GWe) with a single fixed C220108 value. The model output contains no sensitivity results. This is a cross-artifact inconsistency: the analysis claims the model does something it does not.
- **Recommendation:** Either add a target-cost sensitivity sweep to `model_setup.py` (varying C220108 across the $1–$20/target range and reporting the resulting LCOE band), or remove the sweep claims from the analysis C220108 rationale and Data Gap #5 so the analysis accurately describes what the model actually computes. Given the acknowledged importance of target cost as the dominant consumable uncertainty, implementing the sweep is the stronger option.
- **Priority:** important
