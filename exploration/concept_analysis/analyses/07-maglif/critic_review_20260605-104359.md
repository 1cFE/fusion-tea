

# Critic Review — 07-maglif

## Headline issues

1. **All three columns (generic, native, 1 GWe) are identical, meaning the model produces zero analytical differentiation.** With 0 enabled overrides and P_native already at 1000 MWe, the native forward is the generic forward, and the 1 GWe projection is a no-op (1000 MWe → 1000 MWe scaling = identity). The artifact is internally consistent but delivers no concept-specific cost signal whatsoever — every dollar figure is a pure library default for the MAGLIF archetype. The analysis documents extensive cost data (the $372M driver estimate, the $15/J parametric, the per-shot consumable structure) and then correctly concludes none of it meets the override bar. The result is an honest "we have nothing to override" outcome, but the reader should understand that this LCOE (102.9 $/MWh) is the library's *archetype prior*, not an estimate grounded in Z-IFE or Pacific Fusion data.

2. **The disabled C220107 override ($584M) is for a single 1 PW driver, but the plant has 10 independent drivers — the rationale correctly identifies this but the arithmetic implications are severe.** The analysis in §5b explains the driver-count contradiction thoroughly. If the override were naively re-enabled, it would *understate* total plant driver cost by roughly 10×. The disabled override's `value` of $584M (= $372M × 1.57 CPI) would need to be replaced by something like 10 × (per-chamber driver cost), which the source does not provide. This is well-documented in the rationale and blocked by issue #47, but it deserves headline status because the driver account (C220107) is the single largest CAS22 sub-account at $2,184.5M (55% of CAS22), and whether the library default is reasonable for a 10-driver Z-IFE plant is the central unanswered question of this model.

3. **The `spec` contains only one key (`blanket_t=1.0`), and the analysis identifies a published driver efficiency (60%) and rep rate (0.1 Hz) that differ from library defaults but are not passed — the reasoning is documented but load-bearing.** The analysis notes that `eta_pin` is blocklisted (library-owned) and `f_rep=0.1` matches the YAML default. The driver efficiency mismatch (60% published vs. 15% library default for `eta_pin`) is acknowledged in a comment but accepted. If the library's `eta_pin=0.15` is being used to size driver-related costs, and the actual design point assumes 60% wall-plug-to-pinch efficiency, the driver cost account may be significantly misstated by the library default. This is a hidden load-bearing assumption — the comment says "mismatch is noted but accepted," but the magnitude of the mismatch (4× in efficiency) could propagate to a large cost difference.

## Detailed reasoning

### Deterministic-flag interpretation

All four deterministic checks return `ok`. `dpc` confirms P_native coherence at 1000 MWe across the three-leg chain (design-point table → analysis.md → model_setup.py). `contract` confirms the helper-form two-knob call is structurally valid. `count_smell` confirms 0 enabled overrides is within the 0–4 band expected for High archetype fit. `sanity` shows all 38 accounts flagged `no_data` — there are no comparables in the corpus, so no median or ratio can be computed, and no outlier detection is possible. This means the sanity check is structurally unable to catch any anomaly for this concept; it passes by absence of data, not by confirmation. No `drift` block is present, confirming the live re-import reproduces the recorded `model_output.txt`.

### Spec coherence (beyond P_native)

The analysis describes one named plant throughout: the Z-IFE 10-chamber 0.1 Hz baseline (SAND2006-7148, Olson et al. 2006). There is no stitching between the Z-IFE design point and the Pacific Fusion architecture for parameter values — the analysis is careful to note where Pacific Fusion's IMG approach would differ (90% vs 60% driver efficiency, self-magnetizing targets vs. external coils, IMG vs. LTD) but does not mix Pacific Fusion numbers into the design-point parameter table. The `blanket_t=1.0` spec key is correctly attributed to Z-IFE §4.2.1 (1 m FLiBe shielding). The analysis maintains a clean separation between the Z-IFE design point (used for the model) and Pacific Fusion's architecture (discussed for context). This is well-handled.

One minor coherence note: the frontmatter says `Concept: MagLIF (Pacific Fusion)` and `Company: Pacific Fusion`, but the design point is Sandia's Z-IFE, not a Pacific Fusion design. The company field is somewhat misleading — this is a Sandia National Laboratories design point being used as a proxy for the MagLIF concept class. This doesn't affect the model but may cause confusion in downstream tables.

### Override discipline (judgment)

There is one override entry, disabled (`enabled: False`), blocked by issue #47. The judgment questions:

- **Provenance**: Marked `derived`, which is correct — $372M (2004$) × 1.57 CPI is derived arithmetic, not a directly published 2024$ figure.
- **Value vs. source**: The $372M median is correctly sourced to §3.1.2. The CPI multiplier of 1.57 (2004→2024) is reasonable (BLS CPI-U from 2004 to 2024 is approximately 1.55–1.60 depending on base month). The arithmetic checks out.
- **Blocking rationale**: The rationale is thorough and correctly identifies the driver-count contradiction. The $372M is for a *single* 1 PW reference driver; the 10-chamber plant uses 10 *independent, smaller* drivers. The override cannot be enabled as stated.
- **Does it do real work?**: Even if enabled, $584M vs. the library default of $2,184.5M would represent a 73% *reduction* in driver cost — which would be directionally wrong given that the plant has 10 drivers, not one. The override is correctly disabled.

The per-account walkthrough in §5b is unusually thorough. Each account is examined and a clear "no override" rationale is given. The key judgment: is zero overrides appropriate when the Z-IFE study has substantial cost data? The analysis argues yes, because no Z-IFE figure is both (a) extractable as a standalone account-level cost and (b) applicable to the 10-chamber baseline at a company-grounded level. This reasoning is defensible.

### Two-knob projection (judgment)

Since P_native = 1000 MWe and the target is 1 GWe, the scaling is an identity operation. All three columns are identical. There is nothing to evaluate in the projection — no scaling exponents are exercised. The C220107 (pulsed-power capacitor bank) value of $2,184.5M is the library's MAGLIF archetype default for a 1 GWe plant, not a Z-IFE-derived number. Whether this default is reasonable for a 10-independent-driver architecture is unknowable without the library's internal cost model for MAGLIF driver sizing. The total overnight cost of $8,242/kW and LCOE of $102.9/MWh are pure archetype defaults — they cannot be validated against the Z-IFE study's own COE of ~20 ¢/kWh (2005$) for the 10-chamber baseline because the library uses a different cost methodology.

### Family delta vs comparables

No comparables exist in the corpus (`no_data` for all accounts in the sanity check). The analysis correctly notes this and provides a qualitative positioning of MagLIF relative to laser ICF and MFE concepts. No quantitative delta analysis is possible. The key architectural differentiators (10 independent drivers, per-shot consumables, no superconducting magnets, thick liquid wall) are well-identified and would indeed drive large deltas if comparables existed. The absence of comparables means the library default is unchecked by any cross-concept calibration.

### Gaps and load-bearing assumptions

Two assumptions would most change the LCOE conclusion if wrong:

1. **The library's MAGLIF archetype default for C220107 (driver cost).** At $2,184.5M, the driver is 55% of CAS22 and 26% of total overnight cost. The Z-IFE study's own estimate suggests 10 × (per-chamber driver cost) could be substantially different from this default — but we cannot determine the direction without knowing how the library sizes MAGLIF drivers. If the library uses a single-driver assumption internally, the cost could be understated by up to ~10×; if it uses a parametric $/J model at a different unit cost than $15/J, it could be over- or under-stated. This is the single most leveraged unknown.

2. **The `eta_pin` mismatch (15% library default vs. 60% published).** If driver cost scales inversely with efficiency (more stored energy needed for less efficient delivery), then a 4× efficiency gap could propagate to a significant driver cost difference. The analysis acknowledges the mismatch in a code comment but does not quantify its impact. This should be flagged as a gap in `analysis.md` §6 (it is not currently listed there — the gap table focuses on missing data rather than library-vs-published parameter mismatches).

Both of these are flagged in the analysis to varying degrees (the driver-count issue explicitly, the efficiency mismatch only in a code comment), but neither can be resolved without either (a) extracting the library's internal MAGLIF archetype model or (b) obtaining a company-grounded total-plant driver cost.

## What I deliberately did not say

- **Whether the Z-IFE design point is the right choice for concept 07-maglif.** The design-point selection (Z-IFE vs. Pacific Fusion DS vs. Fuse Apeiron I) is a fixed upstream input. The analysis notes the vintage mismatch (2006 study predating 2010 MagLIF concept) and the target-physics mismatch (dynamic hohlraum vs. MagLIF). These are legitimate concerns but belong to design-point-selection review, not `model_critic`.

- **Whether the source quality of SAND2006-7148 is sufficient.** The report is a Sandia technical report, peer-reviewed within the national laboratory system. Source-quality assessment is out of scope for `model_critic` and should be routed to `research`-stage review.

- **Whether the $102.9/MWh LCOE is "right" for MagLIF.** With zero enabled overrides and no comparables, this number is the library's MAGLIF archetype prior. It cannot be validated from within the `model_critic` scope. The Z-IFE study's own COE (~20 ¢/kWh in 2005$ for the 10-chamber baseline, ~7 ¢/kWh for the optimized 1-chamber case) is in a different cost methodology and dollar year, making direct comparison misleading without a careful crosswalk that is beyond this review's scope.

- **The frontmatter lists `Company: Pacific Fusion` but the design point is a Sandia study.** I flagged this as a coherence note above but did not make it a headline issue because it does not affect the model numerics — it is a metadata/presentation concern for the concept registry.
