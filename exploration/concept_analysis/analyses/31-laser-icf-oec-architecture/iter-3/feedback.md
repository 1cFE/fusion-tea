### F-1: eta_dec shows zero auto-diff elasticity — DEC channel not wired into power balance
- **Target:** Model output — Sensitivity (engineering levers), power balance computation
- **Category:** model
- **Finding:** The main sensitivity table reports `eta_dec = +0.0000` elasticity. The manual DEC sweep workaround (added this iteration) correctly shows implied elasticity ≈ −0.077 and LCOE impact of +2.4 $/MWh at η_DEC = 0.20. But the underlying problem remains: the auto-diff produces zero because the model folds both the thermal channel (70%) and DEC channel (30%) into a single composite η_th parameter. `eta_dec` is not separately wired into the net-output computation. A parameter governing 30% of gross electricity output (∼840 MWe at the design point) cannot have zero LCOE elasticity without indicating a wiring failure. The manual workaround documents the correct answer but doesn't fix the model. Any downstream consumer reading the standard sensitivity table will incorrectly conclude DEC efficiency is irrelevant — directly contradicting the analysis narrative that "if DEC is deferred or achieves lower efficiency, the net electric output falls proportionally."
- **Recommendation:** Fix the power-balance code: compute `P_net = P_fus × (f_neutron × η_th + f_charged × η_DEC) − P_recirc` with `f_neutron = 0.70` and `f_charged = 0.30` applied as separate terms. After the fix, eta_dec should show negative elasticity ≈ −0.08 in the standard auto-diff sweep (30%/70% of the eta_th elasticity of −0.258). Remove the manual workaround table once the standard sensitivity correctly propagates eta_dec.
- **Priority:** blocking

### F-2: Primary (G, f_rep) grid uses constant-output framing — viability cliff remains obscured
- **Target:** Model output — (G, f_rep) Scenario Grid
- **Category:** model
- **Finding:** The same-capital viability table (added this iteration) correctly exposes the viability cliff: G=160, f=1 Hz → 424 $/MWh; G=80, f=1 Hz → 1093 $/MWh using the same $8.9B capital base. However, the primary "(G, f_rep) Scenario Grid — LCOE $/MWh @ 2800 MWe" is still the first scenario result presented and uses constant-output framing (capital rescaled to maintain 2800 MWe), compressing the full grid to 48.1–60.7 $/MWh. Section 7 explicitly states that "constant-output rescaling hides the cliff by eliminating the 27× output variation that is the entire point of the joint analysis." Having the wrong-framing grid appear first, followed by a footnote warning, followed by the correct table, inverts the intended emphasis. A downstream consumer extracting only the scenario grid gets a deeply misleading picture of BLF's risk profile.
- **Recommendation:** Promote the same-capital viability table to the primary scenario presentation. Either remove the constant-output grid or clearly relabel it as "Constant-Output Comparison (capital rescaled — hides viability cliff; see same-capital table for correct framing)" immediately adjacent to the grid. The same-capital table's 22.7× LCOE multiplier at (G=80, f=1 Hz) is the key result; it should not appear below a grid that shows only 1.3× variation.
- **Priority:** important

### F-3: Per-shot target fabrication cost absent from base LCOE — systematic understatement
- **Target:** Model output — base LCOE, CAS70/CAS80 accounts, p_target parameter
- **Category:** model
- **Finding:** The manual target OPEX analysis (added this iteration) correctly shows that even the Goodin economic viability floor ($0.035/target) adds +$0.45/MWh and $1/target adds +$12.86/MWh. But the model's own footnote confirms: "p_target=1.0 MW in the base model is the factory electrical load, not a per-shot cost. The Goodin floor ($0.035/target) must be added as annualized OPEX; the base LCOE does not include this consumable cost." The base LCOE of 48.2 $/MWh therefore excludes what the analysis calls a "first-order OPEX driver" with "blocking" criticality. A cost model that omits a self-identified blocking cost item from its headline number is structurally incomplete, and the 48.2 $/MWh figure will be misread as a complete LCOE.
- **Recommendation:** Add `target_cost_per_shot` as an annualized OPEX parameter in the base model computation: `target_opex_annual = target_cost_per_shot × f_rep × availability × 3.15e7`. Feed this into CAS70 (O&M) or CAS80 (Fuel) so it appears in the standard cost breakdown. Set the default to the Goodin floor ($0.035/target) as the minimum economically viable assumption, and include a sensitivity sweep from $0.035 to $10.00/target in the standard sensitivity output. The manual OPEX table can be retained as supporting context but should not substitute for base-model integration.
- **Priority:** blocking
