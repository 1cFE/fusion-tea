### The writer prompt

3. The inline `<script>` does more than track navigation state. Its second block (`harness.html:1753-1822`, "Explore: choose a part of a figure...") implements a full interactive feature for Figures 1, 2 and 9: clickable diagram parts, chip/button controls with `aria-pressed` state, and an `aria-live` readout panel that assembles page text on click. The writer prompt's hard constraints say "An inline script may only track navigation state, as the style sample's script does." This script does that too (the first IIFE, TOC highlighting and hash-driven detail-opening), but the Explore block is a distinct, larger feature beyond it. The page's own `<style>` block likewise adds rules for `.live`, `.chips`, `.readout`, `.explorable`, `.exploring` (`harness.html:407-448`) that style this interactive feature rather than "the layout of its own diagrams," which is what the prompt says a page's own style block is for. (The CSS comment at `harness.html:9` frames the Explore panels as "following the Part 2 page," so this may be an established pattern from an earlier support rather than new to this page — worth checking against Part 2's actual page before treating it as a violation here.)

4. Figure 9 (`#figure-checks`, `harness.html:1612`) has no `role`/`aria-label` text equivalent, unlike every other diagram figure on the page — Figures 1, 2, 3, 6 carry `role="img"`/`role="group"` with `aria-label`, and Figures 4, 5, 7, 8 carry `aria-label` on their `<ol>`. The hard constraints say "Give every diagram a text equivalent, so that color, position and shape never carry meaning alone." Figure 9's own meaning-carrying position (code checks above the line, agent reviews below) is partly redundant with each box's own "Code check"/"Agent review" label, so nothing is silently lost, but the diagram as a whole has no equivalent to the descriptive aria-label every other figure gets.

### Feedback patterns

5. Table 1 (`harness.html:744`, `<details class="detail wide" id="table-1">`) is collapsed by default, though the markdown presents it as a plain, always-visible table that the preceding sentence points to directly ("Table 1 shows how each area implements the pattern," `harness.md` line 114). The shared feedback warns against collapsing main-flow material ("Never collapse a heading that is part of the main flow," `html.md`), and the render prompt itself says "Collapse detail, not the story: a reader who opens nothing still follows the whole argument." In this case the table mostly restates the "Indexes."/"Write tools."/"History." paragraphs that stay visible just above it, so a reader who opens nothing does still get the substance, just not in tabular form — this is a soft instance of the pattern, not a clear loss of the argument.
