# Concept-Analysis Rework — Code Touchpoints

Scope: enumerate every file the rework touches, what its current job is, and what it needs to become. Driven by [concept-analysis-rework-design.md](../concepts/concept-analysis-rework-design.md), [concept-analysis-rework.md](../concepts/concept-analysis-rework.md), [enum-map](20260509-1costingfe-enum-map.md), [pipeline context](20260530-072832_1costingfe-and-pipeline-redesign-context.md).

Bias: start fresh per concept on generated artifacts; keep `knowledge/concept_research/`. Move agent-driven judgments (archetype-fit, comparables, family classification) to deterministic upfront tables.

---

## 1. Upstream library — 1costingFE

### `~/1cfe/1costingfe/src/costingfe/validation.py:90`
- **Now**: `n_mod: int = Field(default=1, ge=1, strict=True)` — rejects non-integer.
- **Needs**: relax to `float`, `gt=0`. One-line change + a unit test. Every downstream `n_mod` use is continuous arithmetic (verified). **Hard prerequisite** — without it the two-knob `n_mod = 1000/P_native` invariant breaks.

### `~/1cfe/1costingfe/src/costingfe/model.py` — `_scale_overrides` (`:849-896`) and `forward()` override paths (`:642-688`)
- **Now**: `override_reference_mw` runs two extra `forward()`s and rescales each user override by per-account ratio. The rework intends to call with `override_reference_mw = P_native` while passing `n_mod = 1000/P_native`. Need to confirm: per-module override scaling is consistent under the two-knob call (per-module reactor-island accounts scale to module count; plant-aggregate accounts scale to 1 GWe total).
- **Needs**: verify (and add a test) that overrides interpreted at the design-point reference scale correctly to the `(net=1000, n_mod=1000/P)` target. The design lists this as the second hard precondition. If the existing per-account-ratio scaler already does this, no code change; if not, fix here.

No other library changes. YAMLs, formulas, enums, NOAK/FOAK boolean stay as-is.

## 2. Project-level deterministic tables (new artifacts)

These replace runtime LLM judgments. Location TBD (open question in design); recommendation: under `knowledge/` or `exploration/concept_analysis/data/`.

### `ontology.{yaml|csv}` (new)
- **Now**: nothing. Confinement family / fuel / taxonomy traits are scattered: `concepts.py:COSTINGFE_MAPPING` (Python), per-concept `analysis.md` body prose, the in-line `**Confinement Family**: ...` line, and frontmatter `Reuses: []` filled at runtime.
- **Needs**: one row per concept — `concept_id`, `confinement_family`, `fuel`, taxonomy axes (driver type, conversion path, pulsed/SS, etc.). Single source of truth read by frontmatter generation, comparables derivation, and analyze/model_setup prompts.

### `archetype_fit.{yaml|csv}` (new)
- **Now**: nothing — the closest analog is the manual rubric in [`20260509-1costingfe-enum-map.md`](20260509-1costingfe-enum-map.md), which has all 39 concepts ranked already.
- **Needs**: one row per concept — `ConfinementConcept` enum + `fit_grade: High|Med|Low|None`. Seed directly from the enum-map document. `None` routes to deferred freeform branch.

### `comparables.{yaml|csv}` (new) + derivation script
- **Now**: `analysis.md` frontmatter has `Reuses: []`; analyzing agent fills it during `analyze` based on prose judgement. Validation: none.
- **Needs**: one row per concept — pre-computed nearest-neighbor set (same family + fuel + similarity heuristic). Either checked-in or generated by a derivation script reading the ontology table. Orchestrator writes this into `Comparables:` frontmatter at concept init.

### `comparables_sanity_check.py` (new)
- **Now**: assess-stage reviewer eyeballs CAS breakdowns; no deterministic checks against neighbors.
- **Needs**: standalone script taking a concept's `result_1gw` per-account dict + its comparables' per-account dicts, computing per-account z-scores / ratios and emitting structured flags (outliers, missing accounts, sign issues). Output is *input to the LLM reviewer*, not a verdict.

## 3. New shared utilities (replace per-concept duplication)

### `exploration/concept_analysis/scripts/lib/model_setup_helpers.py` (new module)
- **Now**: every `model_setup.py` hand-rolls its own forward-call pattern, override dict, sensitivity dict, print block. Concept 01 has ~440 lines; freeform concept 12 has 1142 lines duplicating CAS rollup.
- **Needs**: a thin API the new prompt template targets:
  - `run_native_and_1gw(model, spec, overrides, P_native, **forward_kwargs) -> (result, result_1gw)` — issues the two `forward()` calls with `n_mod=1`, then `(net=1000, n_mod=1000/P_native, override_reference_mw=P_native)`.
  - `Override` dataclass + `enabled_overrides(registry) -> dict` for the registry-to-`cost_overrides` translation.
  - CAS-breakdown print helper.
- Keeps `model_setup.py` to a short, ordered script (the four-step shape in the design doc).

### `exploration/concept_analysis/scripts/agents/model_critic.{md,py}` (new)
- **Now**: no standalone critic. Critique-like behavior lives in the `assess` (in-loop) and `review` (post-loop) stages, both tied to loop state.
- **Needs**: standalone invokable agent — reads a concept directory's `analysis.md`, `model_setup.py`, override registry, archetype-fit grade, comparables, `result`, `result_1gw`. Emits one review markdown: headline issues at the top, detailed reasoning traces below. No loop dependency. Wire as a CLI subcommand under `run_analysis.py` (`cmd_model_critic`).

## 4. Pipeline scripts (`exploration/concept_analysis/scripts/`)

### `lib/concepts.py` (10–242)
- **Now**: hard-coded `COSTINGFE_MAPPING` dict (Python), `get_model_path()`, `_is_freeform_architecture()`. Maps concept→archetype at import time.
- **Needs**: read archetype-fit table as source of truth. `get_model_path()` returns `costingfe` for any fit ≠ `None`, `freeform` for `None`. Drop the in-file mapping dict (or generate it from the table at startup).

### `lib/frontmatter.py:make_frontmatter` (112-130)
- **Now**: emits `Status: draft`, `Reuses: []`. `Reuses` filled at runtime by analyzer.
- **Needs**:
  - Rename `Reuses:` → `Comparables:` and pre-populate from comparables table.
  - Add `Confinement-Family:` (or equivalent) field, populated from ontology table. Migrate the brittle body-prose `**Confinement Family**: ...` regex (extractor) to read this frontmatter field instead.
  - Add `Archetype:` and `Archetype-Fit:` fields from archetype-fit table.
  - Add `Design-Point-Name:` and `Design-Point-Maturity:` — populated by analyze stage (these are produced, not pre-seeded).

### `lib/loop.py` (55–970)
- **Now**: 12-stage loop body; `assess` produces `post_feedback.md` consumed by next iter's analyze; model_setup runs in-iter; review kick-back via frontmatter `Review-Status=revise`.
- **Needs**: minimal change. `model_critic` does NOT register as an in-loop feedback producer (per design — standalone). The relevant change is dropping the in-loop `assess` reliance on the F-N/VERDICT regex format (see validators below). The `_find_best_prior_model` mechanism and per-iter promotion stays.

### `run_analysis.py` (CLI dispatch)
- **Now**: 12 subcommands listed in research §B.1.
- **Needs**:
  - `cmd_model_critic` — new subcommand, takes concept id, runs the standalone agent, writes `critic_review.md` next to artifacts. Operates on active OR archived concept dirs.
  - `cmd_regenerate_concept` — new subcommand wrapping safe `rm -rf analyses/{id}/ && gap-check && analyze && model-setup && …`. Hard-requires the archetype-fit table row exists for the concept. `--keep-gap-report` flag for the lighter form.
  - `cmd_init_tables` (one-off) — bootstrap ontology, archetype-fit, comparables tables from existing data (enum-map doc + concept_research dossiers).

### `lib/validators.py` (22–317)
- **Now**: 9 validators; 5 are regex/YAML parsing of LLM markdown (verdict, findings, score yaml, calibration yaml, PA-N). `validate_python_syntax` does not enforce the `model`/`result`/`result_1gw` module-level contract.
- **Needs**:
  - **Drop** `validate_feedback_verdict`, `validate_review_verdict`, `has_model_category_findings`, `parse_proposed_actions` when assess/review/address-review move to structured JSON output (or a less fragile contract — design doesn't mandate JSON, but the format change is implied by "drop fragile regex").
  - **Add** model_setup AST check that `model`, `result`, `result_1gw` are module-level assignments; that `forward()` is called with `net_electric_mw=1000` for `result_1gw`; that no hardcoded library defaults are passed (heuristic: warn on any kwarg with a `# DEFAULT:` comment).
  - **Add** override registry validator: each entry is a six-field dict; `value` is numeric; `provenance ∈ {direct, derived}`.
  - **Add** override-count vs fit-grade consistency check (High + many overrides, Low + zero overrides → flag).
  - Keep `make_file_modified_validator`, `validate_non_empty`, `validate_python_syntax`.

### `lib/scoring.py`
- **Now**: `validate_score_output`, `validate_calibration_output` — YAML-in-markdown parsers consumed by synthesize/score/calibrate.
- **Needs**: out of rework scope per design ("Restructuring synthesize and score" is non-goal). Update only if the frontmatter rename (`Reuses` → `Comparables`) leaks into score consumption.

### `lib/sources.py`, `lib/iteration.py`, `lib/landscape.py`, `lib/memory.py`, `lib/canonical_params.py`, `lib/claude.py`, `lib/research.py`, `lib/step_runner.py`, `lib/templating.py`, `lib/paths.py`, `lib/state.py`, `lib/heatmap.py`
- **Now / Needs**: untouched. Only knock-on update: anywhere `Reuses` is referenced (search-and-replace to `Comparables`).

## 5. Prompt templates (`exploration/concept_analysis/prompt_templates/`)

### `analysis_v2.md` + `output_template.md`
- **Now**: 8-section data-availability-shaped output (Availability, Challenges, Maturity, Materials, LCOE Parameters, Gaps, Cross-Concept Notes, Sources). No FOAK/NOAK rule; no design-point selection rule; no archetype-first framing; agent fills `Reuses:` by prose judgment.
- **Needs**: restructure around the methodology spine —
  1. Identity / family delta (uses ontology + comparables — handed in upfront).
  2. **Design Point block** (new structured section) — design name, maturity tier, `P_native`, key geometry/physics/performance values, primary source citations. Adjacent to the LCOE-parameters section by construction.
  3. LCOE parameters (one unit, matching design point 1:1).
  4. Override candidates with provenance class and rationale (justified by company data only).
  5. Open data gaps.
- Drop the prose `**Confinement Family**:` line (now in frontmatter).
- Drop the Reuses-discovery instructions (now upfront-deterministic).

### `model_setup_costingfe.md` + `model_setup_costingfe_edit.md`
- **Now**: 91–123 — encourages re-passing library defaults with `# DEFAULT:` comments; threshold for "override vs not" not articulated; `_NOAK_OVERRIDES` plain dict, not toggleable; convention only; FOAK/NOAK examples both shown.
- **Needs**: flip the discipline.
  - Pass **only** deliberately-overridden specification kwargs to `forward()`. Re-passing a library default is an antipattern.
  - Always `noak=True` in the baseline.
  - Always produce both `result` (native, `n_mod=1`) and `result_1gw` (`net_electric_mw=1000`, `n_mod=1000/P_native`, `override_reference_mw=P_native`).
  - Use the shared `model_setup_helpers` utility.
  - Override registry = list of six-field dicts (account / value / enabled / provenance / source / rationale).
  - Drop `_FOAK_OVERRIDES` parallel scenarios (FOAK is no longer in the per-concept setup file — single standardized target).
  - The companion `_edit.md` mirrors the same rules.

### `model_setup_freeform.md` + `model_setup_freeform_edit.md`
- **Now**: parallel CAS rollup hand-rolled; out of rework scope (deferred per design non-goal).
- **Needs**: untouched. Asterisked in comparison view.

### `assessment.md` + `review.md` + `config/feedback_format.md` + `config/assessment_checklist.md`
- **Now**: prompt the agent to emit VERDICT/F-N/Category in a brittle markdown shape, parsed by validators.
- **Needs**: switch to a format that is parse-robust (structured JSON or scaffolded headings the agent fills). Removes 3+ validators.

### `gap_check.md`, `source_integration.md`, `synthesis.md`, `score.md`, `calibrate.md`, `research.md`, `resurface.md`, `address_review.md`
- **Now / Needs**: largely untouched. Minor: any frontmatter field rename (`Reuses` → `Comparables`) referenced in `synthesis.md` or `score.md` prompt prose needs updating.

### `config/analysis_goals.md`, `config/quality_standards.md`, `config/scoring_framework.md`
- **Now / Needs**: review against the new methodology spine. `analysis_goals.md` 5 goals may need editing to add "Design Point Specification" as an explicit goal. `quality_standards.md` should add "no re-passing of library defaults" and "every parameter must describe the design point."

### New: `model_critic.md` (agent prompt)
- New prompt for the standalone critic. Inputs: concept artifacts + archetype-fit grade + comparables + sanity-check flags. Output: one review document (headline + detailed traces).

## 7. Per-concept artifacts — delete and regenerate

For every concept where archetype-fit ≠ `None`:

### Delete in `exploration/concept_analysis/analyses/{id}/`:
- `analysis.md`, `model_setup.py`, `model_output.txt`, `iter-*/`, `synthesis.md`, `gap_report.md`, `review.md`, `address_log.md`, `research_log.json`, `prompts/`

### Preserve:
- Everything under `knowledge/concept_research/{id}/` — dossiers, sources, extracted documents, images.
- User-filled review Decisions if any are worth preserving (snapshot to `.project/` before delete).

### Regenerate via new `regenerate-concept` subcommand:
- `gap-check` (preserved one-shot) → `analyze` (new template) → `model-setup` (new template + shared helpers) → `review` → `synthesize` → `score` → `approve`.

### Sequencing:
1. Library prerequisite change (validation.py `n_mod` float).
2. Tables + frontmatter migration script — non-destructive.
3. New shared helpers + new templates + new validators.
4. Pilot 3–5 concepts spanning High/Med/Low fit (per design open question).
5. Bulk regenerate remaining concepts.
6. Freeform / `None` concepts: leave their `analyses/{id}/` untouched; asterisk in explorer.
