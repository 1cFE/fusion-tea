Can one model carry a plant's techno-economics? The test is running general studies on it

A SysML v2 model of a stellarator power plant was mechanically compiled into a sealed Python package, and two A/B parameter studies — asked in three lines each — ran against it end to end, leaving verified verdicts, immutable records, and a filed list of everything the model could not yet answer. This page walks that chain.

1 · The bet, and the test that exercises it

Fusion techno-economic analysis (TEA — estimating what a power plant concept would cost per unit of electricity) is normally one bespoke cost code per concept, welded to the design it was written for. The bet here: a SysML v2 model of the plant — structure, physics relations, cost accounts, and viability checks in one artifact — is the single source, mechanically compiled into a runnable package, so analyses run against the model itself. Component swap is designed into that structure designed — not yet demonstrated at component level: the two studies below swap parameter blocks on one sealed package, not components.

The test: two three-line prompts

If the structure is real, "compare A against B, sweep the rest" should run with no per-question re-modeling. Two such studies ran, as parameter-block swaps on one sealed package. They are the demonstration, not the headline — the owner's own framing: not impressive on their own OWNER.

Compare steam Rankine against sCO2 on the stellarator
Run sensitivity analysis on other axes for each type
Try to find a non-intuitive result on the interactions

Study 1 (20260821-power-cycle-ab, 4 arms, 3,792 points): the sCO2 case is the efficiency, not the equipment price — in this package the cheaper sCO2 turbine and heat-rejection rates are worth ≤ ~1.3 % of LCOE anywhere, the efficiency step 13–23 %.

Compare magnet technology A/B (REBCO vs Nb3Sn) on the stellarator
Run sensitivity analysis on other axes for each type
Try to find a non-intuitive result on the interactions

Study 2 (20260823-magnet-technology-ab, 2 arms, 8,288 points): the cheap conductor never gets to bid — the model rejects every Nb3Sn plant before price can matter, and the 4.5 K cryogenic load closes the region, not the field ceiling alone.

Where the model could not push back on an axis, the pipeline said so before any point ran and filed the gap as model-development work (§ 3, § 5). Every number was re-derived against a hand-written mirror of the model's equations that shares no code with the generated package — what that check catches and what it cannot is § 3's verification station, not an opening claim.

Why the machinery? Why not just a Python script, or 1costingFE directly?

The counterfactual sits in the repo: exploration/stellarator_e2e/verify_stellaris.py, 432 lines of plain Python, computes the same plant. And 1costingFE — the project's existing costing code — is the acknowledged source of most cost relations and constraint thresholds here (the viability doc comments cite its validation.py throughout). What the SysML route buys over both:

  • Typed contracts — every input is a named, classified entry point (model_contract.json); nothing is a buried constant you have to grep for.
  • Constraint identity — each check has a qualified identity and its verdict is data in an evidence store, not a log line.
  • Sealed fingerprints — a study result is bound to an exact package digest; a changed model refuses to resume an old store.
  • Cross-concept reuse — the library definitions (costed components, CAS accounts, DCF core) are concept-agnostic; the stellarator binds values, it does not re-derive structure.
How does this compare to systems codes like PROCESS, SYCOMORE, or ARIES?

What those codes have that this package does not, yet: self-consistent physics (confinement scaling closures), optimizers, engineering loops (coil stress ⇄ radial build), and a portfolio of studied concepts. What this has that they do not: the model itself as the single source, mechanical derivation of the executable, and study records auditable by a reader with no access to the session that ran them. The roadmap claim is kept modest: one concept has passed through the chain; cross-concept comparison is the goal, not the achievement.

2 · A stellarator plant in ~13 SysML files, compiled into a sealed 173-parameter package

The model is the published Stellaris stellarator design, deliberately simple — fixed-profile 0-D physics — and run under a disciplined, auditable process.

The six constraint checks, graded plainly

The four live fences are algebraic inequalities; there are no engineering loops (no coil-stress ⇄ radial-build coupling, no confinement closure). That honesty matters in § 4.

SysML → Python, side by side

The code generator emits, per calc: a typed module wrapper and an implementation carrying the SysML expressions. All but two calcs are auto-implemented from those expressions; two — DT fusion power and levelized replacement cost — are hand-implemented and pinned.

The SysML calc (models/analyses/mfe_lcoe_dcf.sysml:4)

calc def 'LCOE DCF' {
  in attribute total_capital_in : Real;
  in attribute annual_om_in : Real;
  in attribute net_electric_mw : Real;
  in attribute availability_in : Real;
  in attribute discount_rate_in : Real;
  // ... construction + operating years

  attribute crf : Real =
    discount_rate_in * discount_pow_n
      / (discount_pow_n - 1.0);
  attribute idc_factor : Real =
    (1.0 + discount_rate_in)
      ** (construction_years_in / 2.0);
  // annual capital, annual energy, out lcoe
}

The generated implementation (generated/handwritten/mfe_lcoe_dcf/lcoe_dcf_impl.py)

# AUTO_IMPLEMENTED = True
# SysML Source: analyses/mfe_lcoe_dcf.sysml:4
def run_lcoe_dcf(inputs: LCOE_DCFInput) -> float:
    ...
    crf = (discount_rate_in * discount_pow_n
           / (discount_pow_n - 1.0))
    idc_factor = ((1.0 + discount_rate_in)
           ** (construction_years_in / 2.0))
    annual_capital = (total_capital_in
           * idc_factor * crf)
    annual_energy_mwh = (8760.0
           * net_electric_mw * availability_in)
    return ((annual_capital + annual_om_in)
           / annual_energy_mwh)

Each doc comment survives the trip, source citation included (the DCF follows 1costingFE's economics.py). The wrapper also restates the expressions as a "Calculation Specification" block, so the Python names its own SysML line.

How the LCOE math works (one worked path)

The DCF core is four lines: a capital recovery factor CRF = d(1+d)ᴺ⁄((1+d)ᴺ−1); an interest-during-construction factor (1+d)^(Yc/2) (even-spend midpoint); annual capital = total capital × IDC × CRF; and LCOE = (annual capital + annual O&M) ⁄ (8760 · P_net · availability). The total capital it consumes is the CAS rollup: every subsystem's capital_cost (magnets by kA·m, accounts by power-law scaling) summed through the costed-component ladder above. Constraint verdicts ride beside the number: each check's qualified identity (e.g. stellarator_09__stellaris__beta_ok__82b78aad…) names its verdict column in the evidence store.

Plainly: executor, pre-execution critic, and administrator were all Claude agents. The honest defense is not independence of vendor but the mechanical recount — the administrator recomputed every number from the committed CSVs and caught real errors (a 31-vs-20 count, an overreaching sampling claim), which became addenda.

The stations, each with its real exhibit

Intake — the owner's words, kept verbatim

The record's § 2 opens with the goal exactly as typed (the three-line prompts in § 1 above), then a marked block: "Executor's additions (mine, not the owner's)" — how "Rankine vs sCO2" became three package keys, how "REBCO vs Nb3Sn" became four. The translation is on the record as the executor's own, never blended into the owner's words.

Axes — declared as key groups, with a declared tie

Every axis is declared at attribute level and expanded to its complete entry-key set (axes.json), each key tagged fan_out or tie. The teachable tie: stellarator_09__stellaris__magnet__R0 rides with the major radius …__R — the magnet-cost calc runs Ampère's law on the coil major radius, which is the plasma major radius under a separately authored name. Its suffix is R0, not R, so no name scan would find it; it must be declared. Sweeping R while holding R0 would price coils for a machine that does not exist. Study 2's density axis is a four-key tie (n_D0 with n_T0, n_e0, n_He0 riding at one scale factor, preserving quasineutrality).

Indicators and rulings — what pushes back, decided before any point runs

A deterministic trace over the package's artifacts reports, per axis, which constraints and cost channels it can reach. Fixed vocabulary: no_constraint_response (a sound negative — nothing pushes back), constraints_reachable (a possible path, never a claim of response), unresisted (the agent's judgment, never a tool output). In study 1, availability and discount_rate came back no_constraint_response; the owner ruled — verbatim, "no sensitivity" — and both were declined before execution. The ruling does not discharge the finding: each declined axis still filed a model-development gap (what should push back and is not modeled), rows #1 and #2 of the discovery log.

Verification — what the mirror check is, and is not

10 of 75 output channels were re-derived at stratified sample points — 12 of 3,792 and 48 of 8,288 cases, sampled so that every verdict combination the study produced is covered — with worst relative deviation ~4×10⁻¹⁶, and all six verdicts re-derived from the predicate IR through the package's published operand bindings, with zero mismatches. The mirror (verify_stellaris.py) is a hand-written recompute of the whole plant chain that shares no code with the generated package — but it transcribes the same SysML equations, so it catches codegen and execution bugs, not a wrong equation; two functions are contractually shared and pinned. Verification bounds transcription error, not model error. This oracle check retires after the current epic item; what remains for future studies is the baseline pin, the sealed fingerprints, and verdict re-derivation.

The record, the cold read, and the log

Each record is one directory with 17 fixed sections: verbatim intake, axis groups, indicators and rulings, preflight results, route and glue disclosure ("glue ledger: none" — nothing was harness-supplied in either study), window provenance, constraint outcomes by qualified identity, verification, review outcomes, findings, and a closing section titled "What this record does not contain". Once committed it is immutable — corrections land as dated addenda; both records carry them. Then a fresh agent with no memory of the run read each directory alone and wrote synthesis.md: every number recomputed, recorded facts, missing facts, and the reader's own interpretations kept apart, ending with a mandatory "What the record does not support" list. Nothing the administrators reported missing was actually in the directories — the misses were contract gaps, and they were filed as findings.

4 · The capability held; the findings are graded "what this package could push back on"

The capability verdict first: both three-line prompts ran end to end — intake, declared axes, rulings before execution, gated preflight, sealed execution, verification, immutable record, cold synthesis, filed findings — in 9 and 20 minutes of compute. That is § 1's test passing. The domain findings below are exhibits of the model pushing back (or failing to). They are, in the records' own words, statements about this package, not about stellarators.

Study 1 — the sCO2 case is the efficiency, not the equipment price

Across all 948 grid points per arm the LCOE ordering never flips: η 0.33 → 0.47 is worth 13–23 % of LCOE; the cheaper sCO2 turbine/heat-rejection rates at most ~1.3 % anywhere in the window. Two fences shape the space in every arm: recirc_ok closes the small-machine corner (and moves inward as η rises — the one verdict the cycle touches), wall_load_ok closes a ≥ 1.70 m at every R. And capital rises with efficiency while LCOE falls — the turbine is priced per MW electric, so a more efficient plant buys a bigger turbine and wins on energy sold.

Study 2 — the cheap conductor never gets to bid

Nb3Sn's conductor costs 7× less than REBCO's, and its arm has no feasible point in 4,144: its 13 T ceiling caps the field at 4.69 T, where the beta limit allows density ≤ 0.50× but the recirculation threshold demands ≥ 0.51× — and what tips that one remaining node is the 4.5 K cryogenic load (7.0 MW vs REBCO's 0.9 MW), not the ceiling alone. REBCO at the same node is feasible. Subordinate, and explicitly not a result: Nb3Sn's LCOE is lower at every grid point — but every one of those points is a plant its own verdicts reject. Also: the 9.0 T design field is never optimal here — LCOE rises with B at every density, because this package has no confinement closure, so field buys only magnet capital and beta margin (filed as finding #4).

What these numbers are not

  • Not plant estimates. Every LCOE is "of this package": fixed-profile 0-D physics, no confinement closure, engineered sweep windows chosen to contain the fences the pre-run scan found. A result at a window edge is a result about the window.
  • Study 1: the five power-balance channels (p_net, rec_frac, …) are not recordable in the evidence store (finding #5) — the record's recirculation numbers at corners come from the labelled oracle scan. p_pump is held ~100× below sourced circulator figures; it biases no arm, but understates recirculation everywhere.
  • Study 2: Nb3Sn's cold volume (390 m³) is held — exact at its ceiling, an overstatement below it; the closure verdict was re-checked across every sourced value of the two held cryo assumptions in a certification addendum and the arm stays empty at grid resolution, with the margin narrowing to 0.004 of recirculating fraction. Below ~0.35× density the package cannot evaluate at all (√p_net goes complex), so the net_positive fence is never located.
  • Both: the records carry dated addenda correcting their own overstatements (a too-tight flatness claim, a wrong count, an overreaching sampling sentence). The corrected numbers are the ones on this page. Verification bounds transcription error, not model error — model accuracy is unquantified.

Closing the loop on § 1: the bet was that one structured model could carry general techno-economic questions. Two arbitrary A/B questions later: the structure held — three-line prompts became verified, auditable, cold-readable answers — and every place the model could not push back is now named, graded, and routed as work.
