# TLDR

We set out to test whether our modeling workflow could use one stellarator design to make useful predictions for another. Stellaris supplied the starting design; ARIES was withheld as the external test. Before that test, we made engineering choices affect power, cost and operating limits. Sizing enough conductor to carry the required current, for example, raises modeled electricity cost from about **$145 to $163/MWh**, but the larger pack still does not fit.

What should we make of the failures? **We have not demonstrated a workable plant within this approximate reconstruction and its fixed assumptions. We have not ruled out feasible stellarators.** In the sampled designs, lowering current can relieve excessive magnetic field while increasing heating demand and heat on the divertor. The model reproduces some Stellaris plasma quantities fairly closely, but still needs **44–45 MW of auxiliary heating** where the publication reports ignition. These results leave both engineering requirements and model limitations to resolve; they provide no validated feasible electricity price or optimum.

For the ARIES test, we change permitted parameter values in a JSON request and execute the already-built Python calculation package. The archive preserves both that package and its source SysML; we do not edit equations, regenerate code or optimize before recording the first result. We compare the physical subsystems and radial layers represented, computed outputs such as coil mass and net electricity, and costs for matching components. This tests what transfers beyond the starting design. The first result stays unchanged; later explanations and corrections become separate results.

## The holdout tests whether the method transfers

[OWNER] The original aim was “80% methodology demo,” principally validating SysML v2 modeling and code generation. The owner wanted to hold out design information and see whether the workflow reached similar structural and costing conclusions. The broader motivating question was what would need to be true for 1¢/kWh electricity.

[INHERITED: demo concept] Stellaris supplies a detailed starting design, alongside W7-X and generic MFE sources. It supplies no complete cost benchmark in the cited design paper. Its role was to provide a starting model. Reproducing every claim in the Stellaris publication was not the original success criterion. Later reconciliation work tested how faithfully that starting point had actually been reconstructed.

The two anchors ask different questions. **1costingFE** checks the calculation machinery: give both implementations the same inputs and compare their cost accounts. **ARIES** tests generality by evaluating the frozen model at permitted reference inputs and comparing the resulting structure, derived quantities and costs. This is one held-out conceptual-design benchmark, not a statistical test set. Optimized sizing was explicitly moved to a separate stretch comparison; the initial reveal is a fixed-point test.

## The rubric asks what the model computes and what pushes back

To make that transfer test meaningful, the model needed to expose when a chosen design stops working. [INHERITED: frozen rubric] Twelve functional areas use two separate ladders. **Physics P0–P4** progresses from absent, to held, calculated, constrained/coupled, then design-closed. **Structure/cost S0–S4** progresses from absent, to aggregate, parametric, decomposed lifecycle, then design-based estimation. Scores never average. Most row targets are P2/P3 and S2/S3; conceptual modeling does not require level four everywhere.

Calculating how heating demand changes with the design, then checking it against installed capacity, demonstrates a real design limit. Comparing an assumed breeding ratio with an assumed minimum does not show how blanket choices affect fuel production. A failed constraint can therefore demonstrate increased model depth. It cannot demonstrate a feasible plant.

The current comparison package is **r2**, the second frozen version. It preserves the executable model, selected inputs, comparison procedure and evidence. Its independent review checks whether that package can be reproduced.

## Model evolution made attractive points harder to accept

[AGENT synthesis of reviewed history] The rubric made a practical demand: replace held assumptions with calculations and limits that affect the plant. Four changes show how this developed:

1. **Executable accounting:** the initial physics-to-cost chain produced electricity and cost-account totals; the 1costingFE handshake separated machinery errors from modeling choices.
2. **Plant feedback:** confinement/ash/radiation created operating heating demand; hydraulic flow created pump electricity; temperature created cycle efficiency; component life created replacement outages and availability. These links change whether the plant works and how much electricity it produces to offset its costs.
3. **Conductor and space:** the current requirement determined how much superconducting tape was needed. That determined pack dimensions and cost, while geometry changes affected peak field. Divertor accounting and loop counts made heat-removal requirements explicit.
4. **Source reconciliation and freeze:** exact prescribed profiles and separately supplied source quantities clarified which outputs are predictions. The unresolved ignition gap was retained, and r2 froze the resulting interface without tuning equations to match the source.

The consequence is visible in one comparison: historical legacy inventory with exact profiles gives **$144.62/MWh**; r2's current-sized inventory gives **$162.87/MWh**. More conductor costs more and demands more space. It does not by itself create a feasible machine.

## The search found competing limits, not a feasible region

A failed starting point leaves another question: can changing the design satisfy the competing limits? [RETAINED STUDY, September 16] The latest bounded search selected **71 cases plus a baseline**; no selected case passed all twenty authored constraints. This search predates r2's exact-profile controls and retains its own frozen assumptions. It is not a new search of r2 or proof of global infeasibility. The two later r2 controls also fail, but do not establish how its full design space behaves.

The search varied plasma size, coil current, space for the conductor pack and coolant-loop count. A local tradeoff explains why fixing one limit did not yield a working plant: lowering current reduced peak magnetic field, but increased the auxiliary heating needed to sustain the plasma and the heat reaching the divertor. Adding space or cooling equipment addressed other limits without removing that tradeoff.

The result means **this approximate plant reconstruction, with these fixed assumptions, has not produced a demonstrated workable design**. It does not establish that stellarators are infeasible, or that the published Stellaris design is impossible. The reconstruction differs from that design, and important source details remain missing. The evidence does not settle how much of the failure belongs to the engineering choices versus the model's approximations.

The study ranked samples by their largest normalized constraint violation. Its closest sample gives **$150.158/MWh**, but still fails field, divertor and wall-load limits. That is the calculated cost of a failing scenario, not a feasible price or optimum. Installation/manufacturing costs also remain missing. The breeding check illustrates another limit: an assumed tritium breeding ratio of **1.074** passes the authored minimum, even though the fuel-cycle calculation requires **1.190**. Passing every current screen would therefore still leave engineering questions.

## Reveal means preserving the first result, then explaining it

The **SysML source** declares the plant's parts, equations and constraints. Code generation turns that into a **Python execution package**: a computational graph that orders the calculations, together with the retained handwritten implementations of equations. The freeze archives both the SysML and the executable package, plus the input and comparison rules. The actual comparison runs Python.

Changing “design inputs” means changing only permitted parameter values in a JSON request, with their source and units recorded. It does not mean editing SysML or Python equations, regenerating the package, or optimizing a design. [EXAMPLE, illustrative rather than ARIES data] Supplying a different major radius sends that value through the existing geometry calculations, which change computed radial dimensions and vessel volume, which then affect vessel cost. A supplied radius is an input, not a successful prediction; the computed consequences are what can be tested.

“Compare structure” means checking whether the model represents the reference's major physical subsystems, their radial-layer ordering and their cost-account coverage. It does not mean comparing Python graphs. “Derived quantities” are calculated outputs such as coil mass, thermal power, net electric power, recirculating power and computed radial dimensions. Assumed layer thicknesses and supplied values receive no independent prediction credit. Component costs need matching scope, units, currency and price-year basis; otherwise the comparison remains unresolved.

[INHERITED: frozen procedure] **The first frozen forward report is never overwritten.** The executor refuses to reuse an output directory. The reviewer checks the source/input mapping and keeps later conditioning, corrections and optimization separate from that original result. The sequence is:

1. **Owner triggers reveal.** Record the protocol status/date and unsealed files. Replacement r2 and conditional helium scope are already approved; reveal has not been authorized.
2. **Extract and select inputs under frozen rules.** Keep raw source transcriptions in the permitted extraction/comparison locations. Match definitions, revision, units, scope and technology. Only seven predeclared inputs may change: two plasma dimensions, peak density and temperature, coil ampere-turns, and two coil-space dimensions. Missing inputs remain labeled held fallbacks and block dependent fixed-reference claims.
3. **Run r2 forward first.** Keep profiles, sizing mode and remaining assumptions fixed. Preserve outputs, failures and all twenty predicates.
4. **Assess every row and reconcile accounts.** Review structural correspondence; apply unchanged derived and cost bands; retain missing/incompatible quantities in the denominator. C220107, the inherited ARIES-derived power-supply cost account, earns no independent comparison credit; totals that depend on it retain that disclosure. Preserve raw monetary bases; do not invent a common price year.
5. **Publish the original result immutably.** Report numerical agreement separately from constraint feasibility. The reporter's overall blind pass additionally requires a blind run and the complete constraint inventory; it does not require every predicate to pass. The separate physical-feasibility flag requires all predicates true. LCOE remains diagnostic. A successful software exit does not mean scientific success.
6. **Explain differences in separate reports.** Predeclared conditioned runs can isolate cycle, pump, calendar, inventory and finance assumptions. They earn no independent blind credit. Corrections, new technology models and optimization need separate versions; none can retroactively improve the first result.

The comparison reviewer must check whether the source and model quantities mean the same thing. The reporting software checks the submitted data and arithmetic; it cannot establish that two technologies are equivalent. Accepted conditional helium scope therefore permits the comparison to proceed without making incompatible downstream rows pass.
