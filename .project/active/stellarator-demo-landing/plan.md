## The Point

The demo worktree holds six weeks of work that `main` needs: the run-study capability (skill, generic tools, 273 tests), the stellarator proof-of-life study and its evidence, the handshake oracle, and the PM records behind all of it. It has sat on a branch forked before the stop-parser pins and the D-5 model migration landed. Every week it stays there, the two trees drift further apart and the next stellarator item (the model migration) has no stable base.

This PR lands all of that on `main` **without touching a model or a generated byte**. The one structural collision (main's spine test generates the whole `models/` tree, and the MFE models there can't generate yet) is resolved by keeping the MFE models only in the staged twin that was actually generated (owner decision Q1 → A). The migration PR promotes them back.

It also commits the "before" half of the migration's before/after evidence, captured on the era route while that route still exists.

## Implementation Strategy

**Phasing rationale.** Merge first, because every other step is meaningless if the merge surprises us. Then the one deliberate structural edit (Option A) and hygiene, isolated so the diff is reviewable. Then run both sides' suites on the result — main's to prove we didn't break the pinned contract, the demo's to prove we didn't break the study. Then capture the before-record, which is only trustworthy after the suites are green. Then ship.

**Critical path.** Phase 0 (prereqs) → Phase 1 (merge) → Phase 2 (Option A) → Phase 3 (suites) → Phase 5 (ship). Phase 4 (before-record) needs Phase 3 and nothing else.

**First proof point.** Phase 1: `uv lock --check` and the pin test green on the merged tree. If that fails, the pyproject auto-merge lied and we stop.

**Overall validation approach.** Each phase opens with a check that would fail if the phase's assumption were wrong, then does the work, then re-runs the check. Tree hashes are the regression oracle for SC2; the two suites are the oracle for SC3/SC4.

**Where the work runs.** All phases run in the demo worktree (`cd ~/1cfe/fusion-tea-stellarator-mbse-demo`) on `feat/stellarator-mbse-demo`, except the final `main` pull. Main's checkout (`~/1cfe/fusion-tea`) currently has three uncommitted docs — this plan, the research doc, and two `BACKLOG.md` rows — which Phase 1 carries across.
