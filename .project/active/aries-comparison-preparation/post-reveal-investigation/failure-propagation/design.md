# Native partial diagnostic evaluation

[AGENT] Proposed additive implementation. This changes diagnostic execution infrastructure in an isolated copy of TEAx. It changes no model equation, empirical domain, generated package, historical execution, ordinary evaluator or study completion contract. Implementation awaits coordinator release after review.

## Evidence and implementation boundary

The native executor aborts its topological loop at the first module exception (`simkit/core/pipeline_executor.py:148`). The in-memory evaluator discards its private context and raises a fixed failure record (`simkit/evaluation/evaluator.py:54`, `:175`). The runner commits `evidence_json=None` (`simkit/study/runner.py:120`). Query consequently has no numeric or predicate evidence to recover. `partial_artifacts` is an empty tuple of path names, not an existing partial-value publication API. The ordinary projector refuses a missing expected aggregate constraint report (`simkit/evaluation/projection.py:60`). Local adapter changes cannot recover unexecuted branches through these contracts.

A synthetic fault injected at the conductor node, with unchanged baseline defaults and the actual native executor, confirmed 111 completed computational modules and 259 in-memory channels, including 231 numeric channels. None appeared in the native failure record. `probe.py` and `probe-results.json` retain the exact graph and diagnostic observations. The probe stops at the injected error; it implements no alternate executor.

The 269-node native graph has only three descendants of this conductor module: the reference-conductor-current predicate, the constraint aggregator and ExitPoint. Of 1,420 ExitPoint publications, 13 depend on that failure: eleven numeric conductor results, one structured predicate result and the aggregate report. Both LCOE computations are graph-independent. This is an arithmetic dependency fact, not a claim that the resulting plant is physically supported. Costs derive from supplied material inventories and equipment offers; a diagnostic LCOE could describe their conditional arithmetic while conductor adequacy remains unknown. Other independent branches can still encounter their own domain errors; graph independence alone does not certify a result before execution.

## Proposed API and ownership

Native TEAx work occurs in `failure-propagation/native-teax/`, copied from the adopted package runtime source corresponding to pinned TEAx revision `8d877460ac4f6f264561d916e40c1708adb13397`. The shared checkout remains unchanged. Final source changes are retained as a patch, source hashes and tests under this investigation directory. No runtime or package adoption is implicit.

- `simkit/core/pipeline_executor.py`: add a diagnostic entry point using the existing module execution and binding machinery. An internal flag enables continuation in the same topological loop. Default `run()` behavior remains fail-fast. A diagnostic module record identifies `completed`, `execution_error`, `unavailable_numeric_output`, `unavailable_numeric_input` or `blocked_dependency`; failed/blocked records carry direct root causes and upstream module identities. Diagnostic publication reads each declared ExitPoint binding against channels actually produced even when another binding is blocked. It does not claim the aggregate ExitPoint completed; the ExitPoint node remains blocked when its dependencies are blocked.
- `simkit/evaluation/diagnostics.py`: define separate immutable diagnostic evidence and publication records. Numeric publications require finite real values. Unavailable publications carry typed status and reason, with no substituted numeric carrier. Structured publications retain serialized native data, including individual predicate evaluations. No aggregate constraint report is invented.
- `simkit/evaluation/evaluator.py`: add `PreparedEvaluator.diagnose(typed_inputs) -> DiagnosticEvidence`, using the normal package loader, graph, validated inputs and native executor. Provenance binds executable fingerprint, input digest, diagnostic schema version and evaluator version. It never returns `ModelEvidence` and cannot be mistaken for a successful ordinary evaluation. Entry-validation and preparation errors remain ordinary fatal errors.
- `simkit/tests/evaluation/test_partial_diagnostics.py`: native synthetic graph tests and integration tests for the additive method. Tests use actual native bindings/execution and fail on accidental ordinary-contract changes.
- Local `failure-propagation/diagnose.py`: a separately labelled synthetic diagnostic consumer of that public native API. Join the generated catalogue's evaluation-channel names to retained native structured predicate results. Missing predicates are `unavailable`, never `violated` or `satisfied`. Produce a finite numeric output table with module-status/blocked provenance and a qualification that whole-plant acceptance is withheld. This script does not execute a reference request.

## Execution rules

The native diagnostic loop executes a module only after every declared provider completed. It skips descendants of a failed or blocked module and continues remaining independent nodes. Explicit default bindings retain their current meaning; runtime failures do not activate defaults. A failed multi-output module publishes none of its outputs, including any fields set before the exception. Its output channels are removed before continuation so an incomplete module cannot leak partially valid-looking values. Numeric scalar/root publications are checked for finiteness before marking a module completed. A nonfinite or unsupported complex numeric publication marks the producer unavailable and removes its publications before any descendant executes; a downstream function cannot turn infinity into a valid-looking zero. Native structured predicate evidence remains structured, including legitimate indeterminate results.

Module exceptions remain `execution_error` with the original exception type/message. Current generated domain guards raise ordinary `ValueError`; the engine must not identify scientific unsupportedness by matching exception text. A module error says nothing about physical inadequacy. A future typed domain exception may refine that distinction, but is not needed to retain independent evidence safely. Predicates downstream of errors are unavailable. A successfully evaluated false predicate remains a genuine violated predicate.

The diagnostic result is `partial` if any module errors, dependency blocking or any unavailable publication exists; otherwise it is `complete_diagnostic`. Neither state is a `StudyCase.completed`, a feasibility claim or approval for optimization feedback. No study store schema, existing evidence version, ordinary projection, assessment policy or historical report is changed. New diagnostic artifacts live separately and retain their own identities. Nonfinite results are explicit unavailable publications rather than NaN, infinity, zero or other fake values.

## Review and validation obligations

1. Unchanged fail-fast evaluation still raises the original failure; successful baseline evidence remains byte-equivalent in its numeric and predicate values.
2. A diamond-shaped synthetic graph exercises a failing branch, its blocked descendants and a later independent branch. Independent finite values survive; failed and blocked values are absent; every declared exit has a status.
3. A module that publishes one output and then fails cannot leak that output. Two independent failures retain separate causal records. Explicit defaults cannot silently replace failed dependencies.
4. Nonfinite and complex outputs cannot appear as valid numeric publications. Independent false predicates remain violated; blocked predicates remain unavailable; no fabricated aggregate report or affirmative feasibility appears.
5. Fresh-context tests prevent cross-case leakage. Diagnostic source/schema identity differs from ordinary evidence identity. The study runner cannot consume a diagnostic result as ordinary model evidence.
6. On the real generated package, a synthetic injected conductor failure should preserve graph-independent finite outputs and independent predicates. Compare them with an unchanged baseline, including conditional LCOE arithmetic where calculated. Do not execute the reference request. All originally failed historical attempts remain unchanged.

Scope estimate: three native implementation files, native test coverage and one local diagnostic consumer. This is an additive native-engine feature with a new evidence type, rather than a reporter-only fix. It requires fresh independent review before any reference diagnostic is run or runtime is adopted.

Model-level definedness remains separate from execution availability. A finite carrier behind a false generated definedness flag may be numerically available in native diagnostics but cannot become a defined prediction in the comparison consumer. The consumer applies the adopted definedness overlay without changing that model flag. Existing complex/nonfinite model results are recorded as unavailable numeric publications, with a retained representation and reason; they are never passed through as valid finite predictions.

The consumer accepts only native predicate tokens `satisfied`, `violated` and `indeterminate`; an unknown token is unsupported evidence and is never normalized to a pass/fail. Any unavailable numeric or structured publication, including a missing native aggregate report, makes diagnostic state `partial`. Dataflow isolation assumes the native functional module contract: modules do not mutate upstream payloads or shared globals. Removing newly published channels cannot roll back arbitrary side effects or mutations of objects owned by another module. This feature is not a transactional sandbox.

Implementation refinement: declared numeric input bindings are resolved and checked before a diagnostic module runs. This also covers field references into structured outputs and nonfinite entry fields, without recursively invalidating legitimate structured predicate records. Such a consumer becomes `unavailable_numeric_input`; its dependent modules are blocked and its invalid channel/field references are recorded. Ordinary execution remains unchanged.
