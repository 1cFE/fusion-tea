## Proposed result schema

`DiagnosticEvidence` is a frozen dataclass (schema `native-diagnostic/v1`) containing `state: complete_diagnostic | partial`, executable/input/source provenance, module records, publication records and finite numeric outputs. Its names differ from the ordinary study `responses`/`report` protocol. A module record contains `status`, declared dependencies, causal root module names, and exception type/message when it failed. A publication record contains its declared exit key, channel, producer, `status: available_numeric | available_structured | unavailable_module_error | blocked_dependency | nonfinite_result | unsupported_numeric_type | missing_publication`, and optional finite value or serialized structured value. Unavailable records contain no substituted value. Mutable nested payloads are frozen on attachment or deep-copied for serialization.

The local consumer writes a separate diagnostic document. For each current predicate it carries `satisfied`, `violated`, native `indeterminate`, or `unavailable` plus execution reason. It explicitly marks absent aggregate report, execution completion and engineering acceptance as separate concepts. Model-definedness flags and source limitations stay visible even when native execution succeeds. This is a diagnostic record, not the historical 276-row comparison report or a native study database case.
