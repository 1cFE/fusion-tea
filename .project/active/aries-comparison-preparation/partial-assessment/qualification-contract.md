# Field applicability contract

[AGENT] `tools/qualification.py` applies the reviewed [field audit](../post-reveal-investigation/field-audit/audit.md) to the retained original three-input request. It implements a case-scoped finding, not a generic scientific domain test. Numerical scalars cannot certify unchanged nonplanar coil geometry, current families or complete magnetic similarity. The axis and peak calculations are both unknown/unqualified in this assessment, regardless of whether they execute.

`qualify(graph, diagnostic_document, contract)` takes the native `PipelineGraph`, the native diagnostic `to_document()` result and generated model contract. It returns `field-applicability/v1` with `roots`, `publications` keyed by exit publication, and `predicates` keyed by constraint ID. Each publication/predicate has `field_applicability`, `execution_status`, `producer` and `causes`. Predicate records also name `publication_key`. Each cause gives the axis/peak root name, a deterministic shortest module path, the finding and its evidence path. Artifact hashing belongs to the runner's provenance record.

Both root module keys, module types and single output channels are pinned to the current generated graph. Missing roots, duplicate instances of either pinned type, changed output identity, mismatched diagnostic coverage and missing predicate publications fail closed. This prevents an incomplete root list from silently making downstream results appear unaffected.

Propagation follows the graph's channel providers and module adjacency. Every output of an affected consumer inherits the finding, conservatively at module granularity. Some internal output formulas may not actually consume every input, but this graph does not expose that finer dependency structure. The report must retain this limit. Axis and peak findings remain separate, including where both reach the same output. A failed module retains its applicability finding and its execution failure separately.

`unknown_unqualified` means the field audit prevents a supported prediction claim. `unaffected_by_field_finding` means only that neither audited field root reaches this publication. It never means scientifically supported, and it does not remove other existing model limitations. This helper does not change raw arithmetic, native engineering verdicts or model-definedness.

`combine_qualifications(records)` unions causes for every producer and definedness flag used by a comparison row. It returns only `field_applicability` and `causes`. Callers must resolve all expected producers and flags before calling it; an empty input is rejected. A computed definedness flag is itself a graph publication and inherits field findings in exactly the same way as any numerical or predicate publication. The runner separately enforces the flag's raw definedness state.

Verification uses the actual generated DAG and all 67 catalog predicates without executing the plant. Tests cover transitive path edges, an independent winding-current publication, both roots at the peak field, failed-root availability separation, missing/ambiguous/changed roots, diagnostic completeness, and combining independent producers with affected flag records.
