## F1: typed Boolean transport and deliberate refusal

The exact six Boolean keys have prefix `stellarator_09__stellaris__` and these suffixes:

- `buildings__facilities_enabled`
- `cryoplant__inventory_enabled`
- `fuel_cycle__inventory_enabled`
- `fuel_cycle__processing_enabled`
- `fuel_cycle__processing_source_conditions`
- `heat_transport__equipment_enabled`

The route will retain this reviewed key set and verify its equality with the contract's `python_type == 'bool'` declarations. The numeric default `1.0` is not type authority. For these six keys only, `True`, `False`, integer zero/one and floating zero/one normalize to actual Python `bool` before the bridge. Any other numeric value, nonfinite number, string, null or container raises `RouteError` identifying the key and required Boolean domain. Boolean values on numeric controls raise `RouteError`. Existing deliberate retired-key refusal remains. No invalid proposal returns `None`.

Batch semantics: materialize and validate the entire requested proposal sequence before package preparation or study/store creation. A mixed valid/invalid batch raises the named diagnostic and executes zero cases, so it cannot partially execute and silently omit the bad point. A wholly valid batch retains every normalized proposal, including false controls. Requested-case accounting compares proposal identities after normalization, accounting explicitly for the existing study runner's duplicate-point semantics; use distinct valid inputs for the multi-case transport test. Do not mislabel deduplication as execution loss.

Required checks: each of the six keys accepts and transports both truth values through route validation, `CandidateBridge` typed fields, native evaluation and recorded case inputs; numeric zero/one produces the same actual Boolean values. For each key, reject `2`, `-1`, NaN, infinity, strings `'0'`/`'true'`, null and containers. Reject Boolean radius/current/price inputs. A mixed batch must raise before a store exists; a valid distinct batch must retain all requested points. The active-processing dependency needs a coherent false-inventory point: also set processing false when inventory is false. This dependency does not justify suppressing transport coverage for any key. Keep semantic tests that active processing with inactive inventory fails deliberately.
