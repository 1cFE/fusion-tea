# Report custody implementation detail

[AGENT] This implements the existing C2 first-report obligation. A caller declares a result-register directory for the comparison. Its fixed `first-forward.identity.json` is the single original receipt; changing the report filename cannot create another original in that register. An exclusive transient lock serializes first registration and follow-ups. A process crash leaves the lock for explicit recovery rather than silently promoting another result. Ordinary malformed attempts retain their exclusive report/error evidence and release the lock; they never create the original identity. The original receipt is written exclusively only after a completed blind native result has produced a report. Numerical disagreement and violated engineering predicates remain eligible for first registration.

[AGENT] Report writing defaults to preparation. Preparation verification and Table5 controls do not need a first-forward reference and cannot register one. Post-reveal kinds are explicit `forward`, `conditioned` and `corrected`; follow-ups name the register's original receipt and corrected reports require a reason. The wrapper validates the archive index, archived-versus-current candidate metadata bytes, candidate fingerprint/rules joins, raw request selection against retained native inputs, regenerated model export, observation/native consistency and every original-receipt artifact digest. Hashes come from actual files, not caller claims. Artifacts are hashed again before final identity publication. Report hashes live in sidecar receipts, never in the reports themselves.

[AGENT] Custody status is separate from scientific/publication readiness. All current reports remain `publication_ready: false`; selecting a post-reveal kind records caller intent and does not establish owner reveal/adoption authorization. This implementation is tested only using synthetic request/result/reference/archive bytes in temporary test directories. It neither publishes an actual candidate archive nor grants a reveal. Receipt paths are relative to their register directory so a complete retained bundle may relocate together. Existing pure `compare` callers retain explicitly preparation-only result links for compatibility; the exclusive writer is the custody boundary.

## Implemented scope and review submission

[AGENT] Owned implementation files are `compare_candidate.py` and new `report_custody.py`; focused tests are `tests/test_candidate_report_custody.py`. The new exclusive `write_report` entry point defaults to preparation and supports explicit forward/conditioned/corrected kinds. Required post-reveal inputs are the actual archive, raw execution request, native result, model export, observations and result register. Candidate metadata and both model/package contracts must match bytes inside the checksum-verified archive. Native selected inputs and classification are reconstructed from the raw request; the model export is regenerated and compared. The package/executable/semantic/rules joins do not equate evaluated native case IDs with archive identity. Follow-ups validate all original artifact bytes, the original report's recorded artifact hashes and its native result link. Relative artifact paths resolve against the declared register.

[AGENT] The first receipt is written after the report and binds twelve files: archive, rules, request, native result, model export, observations, manifest, model contract, package contract, candidate identity, diagnostics and report. The report carries all preceding artifact hashes and the expected external receipt location but cannot claim completed custody by itself. Follow-up receipts also bind the immutable original receipt. A second differently named forward report in the same register refuses. Ordinary malformed/uncompleted attempts release the transient lock and preserve their error documents/raw bytes; a failure after a report has been written but before its identity completes retains the lock and a custody-refusal sidecar for explicit recovery. A killed process or incomplete receipt must be investigated; there is no automatic stale-lock deletion. Filesystem exclusivity protects this wrapper's writers, not hostile edits by a user who can rewrite both the artifacts and their checksums.

[AGENT] Verification/Table5 preparation no longer requires an original forward result. Verification observations are explicitly rendered through the shared comparator's conditioned schema because that shared schema has only blind/conditioned kinds; the enclosing report remains preparation. Preparation reports preserve numeric ratios/bands and supplied roles but clear independent prediction credit and blind-comparison success. Engineering readiness remains withheld independently of custody.

[AGENT] Tests cover failure/disagreement eligibility, first-register uniqueness across names, conditioned/corrected links, required correction reason, all three preparation run kinds, missing archive/identity, malformed raw observations, altered archive/request/export/rules/native bytes, falsified selected/classification/lineage claims, original artifact mutations, existing destinations, concurrent same/different destinations, relocation and an interrupted identity publication. All use temporary synthetic native/reference/archive artifacts and the existing public candidate selection/comparison metadata; no native plant or actual candidate archive is executed or published. The combined candidate/shared/legacy suite command and result are retained in `checks/report-custody-tests.log`. Fresh independent review is pending; this author does not close R3.

[AGENT] Integration still needs the new helper and test included in the future reviewed archive/base membership, and the parent-owned reporting documentation updated after review. Actual candidate identity/archive, restored integration, owner reveal/adoption and final scientific treatment remain absent or externally gated. A caller choosing another result register starts another namespace; this mechanism guarantees uniqueness within the explicitly declared register, not across arbitrary directories. Existing pure-comparison callers cannot claim report custody.
