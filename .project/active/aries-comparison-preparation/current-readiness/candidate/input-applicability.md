# Input selection and applicability

[INHERITED] The seven independent reference inputs, source priorities, units and matched-definition rules are unchanged from r2. `selection-policy.json` freezes the exact input-selection contract used by `input-rules.json`. All source-specific values remain absent before owner reveal. Missing inputs retain the declared held fallback and cannot be presented as a fully reference-specified forward point.

[INHERITED] The selected forward controls remain current-driven winding sizing 1, inventory multiplier 1, density-profile exponent 0.35 and temperature-profile exponent 1.2. Current raw defaults are a separately labeled diagnostic baseline. Fourteen cooling circuits and current live subsystem choices remain held. Input-file bytes, declared types and canonical values are distinct records; numeric zero/one is permitted only for stored Boolean defaults, while new Boolean values must be JSON Booleans.

[AGENT] Every conditioned run remains separate from the first forward result. Held-cycle efficiency is supplied and earns no independent credit; it does not waive heat-transfer validity. Held-pump values replace primary-loop pumping/recovery only. Secondary salt pumping and shaft heat remain active under the held energy mode. Loop accommodation recomputes represented equipment/layout for the supplied count without qualifying the complete installation. Legacy inventory changes magnet sizing only. Held calendar and finance cases retain their existing meanings and domains.

[INHERITED] Table5 is a fixed supplied geometry/field control. Both `values` and `conditioned_values` must be empty objects. Its supplied geometry, field and derived-from-supplied aliases receive the recorded roles; they do not become independent reference predictions.

[INHERITED: ../../package/accounting-normalization.md] The formal `pump_electric` row remains calculated primary compressor demand (`primary_loop__p_elec`), including in a held-pump diagnostic. It is not selected primary demand or total primary-plus-secondary pumping. The selected primary demand uses the supplied value in held mode, while total demand also includes active secondary salt pumping. Calendar availability is labeled supplied whenever held-calendar mode is requested, even though current facilities refuse that mode. The existing manifest has no conversion-efficiency row; electricity outputs remain calculations conditioned on any supplied efficiency.

[AGENT] Invalid requests, mismatched units/definitions, malformed or conflicting rules, incomplete input/schema coverage and changed package identities are refused with retained evidence. An incompatible historical all-subsystem-off replay is not an additional comparison input seam. Final scientific interpretation remains pending the owner's cycle decision.

[AGENT] Newly verified current incompatibilities: a supplied positive availability selects held-calendar mode, which live facilities reject (`facilities requires one module, four sectors, live calendar`). Current active cooling rejects negative discount rates (`negative allowance or invalid makeup fraction`), even though the isolated general finance kernel has a wider mathematical domain. These input seams remain explicit refusals under the current integrated model. The comparison adapter must preserve those failed attempts; it must not disable facilities or cooling to make them run. Explicit legacy branches used by historical regression fixtures are separate scenarios. Evidence: `../regression-evidence/additional-consumer-repair-note.md`, `additional-store-failures.json` and `additional-finance-case-states.json`.

[INHERITED: WI-073 released interface] Current selected defaults enable matched steam and cooling water. Held efficiency atomically disables the raw live fit, matched cycle and cooling water and supplies `eta_th_direct`. The selected efficiency and downstream power/cost outputs are conditioned on that supplied value. New inactive cycle state rows retain raw zero diagnostics but export no available prediction. Current raw legacy fit predicates remain recorded with explicit matched-mode applicability.
