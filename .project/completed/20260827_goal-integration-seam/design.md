## Overview

One fusion-tea-side CLI runs the producer-owned gates in R-B1's order against a named package and emits exactly one `CANDIDATE` or `BLOCKER` document. It writes nothing into the tracked tree: every producing step is invoked in place and required to be a no-op, and anything that moves is the refusal.

## The Point

`[INHERITED: epic Item 3 Objective, agent decomposition ratified by owner 2026-08-25]` Turn audited model work into exactly one verified, study-ready candidate pin and fingerprint, or a named blocker.

`[INHERITED: .project/concepts/goal-strategy-task-harness-design.md § Native seams]` Integration is the hop between an audited model change and a study that can run against it. Every gate that hop needs already exists and already fails closed. What does not exist is a boundary that owns them together: the sequence lives in two work-item plans and a pile of shell commands, and a goal task cannot request integration without reconstructing the hand pattern. The cost has been paid once already — Item 6 opened with eleven red tests because a scaffold commit added an objective to the manifest without re-pinning the fixtures. The check existed; no gate was bound to the hop, so it fired far from the commit that broke it and only when a human happened to run the suite.

Two things make the return usable rather than merely correct. `[INHERITED: concept-design § Problem, § Task-grain invocation]` A goal agent reading a `BLOCKER` must be able to tell an operational accident it may retry from a semantic result that changes what work is justified — an unexported licence key is not a refusal. `[INHERITED: epic Item 3 Deliverables]` And a person who did not build the seam must be able to operate the whole thing from its own documentation.

## Research Findings

Everything below was read or run in this worktree.

**Every producing step already has a checking form, and the checks are the same code.** `preflight.check_manifest_currency` (`preflight.py:233`) compares the manifest's recorded fingerprints against the live contracts — that is the re-pin, read backwards. `manifest.assert_pin_matches` (`manifest.py:453`) recomputes `indicator_input_fingerprint` over the live package and compares it to the manifest's pin — the read-set half of the re-pin, read backwards. `test_mfe_census_is_the_one_captured_from_the_first_clean_package` (`test_model_family_spines.py:349`) compares `data/mfe_census.json` against a fresh canonical-subset generation, and fails with "model meaning moved — re-derive" when the census is stale (WI-030 saw exactly this, `WI-030 plan:129`). `identity.assert_matches` (`identity.py:288`) recomputes rather than trusts.

**The spine test is already hermetic and already generates.** `baselines` (`test_model_family_spines.py:243`) generates each family from a materialized canonical subset into `tmp_path`; `test_family_subset_generates_and_live_equals_snapshot` (`:308`) captures a snapshot into `tmp_path` and compares. Nothing in that suite writes into `exploration/`. It needs `SYSIDE_LICENSE_KEY` (`license_must_be_loaded`, `:114`) and errors rather than judges without it — the R-A6 live instance the spec names.

**Two of the nine producers judge the repository, not the request** (M1, and it changes what those gates mean). `pytest tests/models/test_model_family_spines.py` takes no package argument: `_subset` (`:216`) calls `materialize_canonical_subset(family, …)` from `tests/model_families` (`:40-47`), which sources the repo's canonical `models/` tree, and the MFE census test compares against the tracked `DATA / "mfe_census.json"` (`:353`). `pytest tests/test_dependency_provenance.py` reads `pyproject.toml` and `uv.lock` at `ROOT` and the installed wheels. Neither can be pointed at `--package`, `--models-root`, or `--census-file`. So gates 1a and 5 are **repo-scoped by their producers' construction**, and gates 1b, 2, 3, 4, 6, 7, 8 are request-scoped.

**Gate 1a fails today in a default environment, as a `<failure>`.** `test_installed_artifacts_are_the_recorded_wheels_and_public_apis` reads `os.environ["STOP_PARSER_WHEEL_TARGET"]` and one `STOP_PARSER_<NAME>_WHEEL` per entry of `WHEEL_HASHES` — `AGENTIC`, `CODEGEN`, `COSTINGFE` — inside the test body (`tests/test_dependency_provenance.py:31-35`, `:82-87`). Unset gives a `KeyError` in the body, which pytest records as a `<failure>`, exit 1. Three repo records log exactly this as the standing environmental state, not a real refusal (`WI-030 verification_record.md:54`; `goal-research-seam/audit.md:62`; `goal-research-seam/plan.md:589`). A junit `<error>`/`<failure>` split cannot carry R-A6 for this producer.

**`verify.py` writes no summary when it refuses.** `main` catches `common.ToolError` and `manifest_mod.ManifestError` and returns 1 (`verify.py:527-529`) *before* reaching `common.write_document`; `VerifyError` is a `ToolError` subclass (`:80`). A parity refusal, an empty store, an unreadable manifest and a failed `import simkit` (inside `build_summary`, `:415`) therefore all look identical from outside: exit 1, stderr text, no document.

**`manifest.load` already validates** (`manifest.py:384-398` calls `validate` before constructing `LoadedManifest`), and `preflight.py` already has a standalone `clean` subcommand (`:487`) that is exactly the git-clean check.

**`preflight.py` is the blocker-taxonomy shape to match.** `run_gates` (`:333`) loads four documents first, records each load error, and `unavailable()` (`:368`) turns a load error into the named condition a check could not run under. `PASS` / `FAIL` / `DID_NOT_RUN` are module constants (`:85-87`); the seam imports them rather than re-spelling them.

**Verification needs an executed store, and the route is package-specific.** `verify.build_summary` (`:414`) opens each `--store` and `verify_store` (`:343`) refuses a store with no completed cases. `preflight gates` needs `package_identity.json` and `baseline_result.json`. Both documents are deposited by `study_route.execute_baseline(out_dir, *, package_dir, manifest_path)` (`exploration/stellarator_e2e/studies/study_route.py:358`), which runs the manifest's own pinned baseline point. That module names the package; `scripts/study/` never does ("generic by construction … names no package", every producer's module docstring). `execute_baseline` returns the identity and baseline-result paths but **not** the store path; the store is named in `baseline_result.executed_under.store_id` (`study_route.py:381`), repo-relative when the output directory is under the repo root and a bare filename otherwise.

**`git status` cannot be the byte-movement gate on its own.** `common.git_status_porcelain` (`common.py:60`) runs from `manifest.repo_root()` — `scripts/study/`'s own grandparent, i.e. the fusion-tea worktree — with `-- <resolved path>`. A package outside the repo makes git error; a package inside the repo but gitignored reports clean whatever its bytes do. So the seam computes its own before/after content digest over the package tree (the spike's technique, `spike_regen_determinism.md` Step 2) and lets `preflight.check_package_clean` remain the producer's own git gate on the real tree. The two are complementary, not redundant.

**The stellarator package root is a tracked symlink.** `exploration/stellarator_e2e/pkg/stellarator_tea` → `../generated`; git operations resolve through it.

**A package-copy factory already exists** — `package_copy` (`tests/study/conftest.py:191`) copies a package, manifest and axes into `tmp_path` and rewrites `package.path` to a repo-relative path. It does not exercise `package_clean`, and `tmp_path` is outside the repo, so it cannot carry the seam's git-backed gates unchanged. `stock_route_run` (`:274`) and the `STOP_PARSER_TEAX_ROOT` / `STUDY_REQUIRE_TEAX` skip machinery (`:239-270`) are directly reusable.

**Snapshot recapture is byte-stable, and the tracked snapshot carries no `captured_at`.** Measured by spike (`spike_snapshot_stability.md`): three recaptures — twice from the real `models/` root, once from a `/tmp` copy — all produced a file byte-identical to the tracked `stellarator.snapshot.json`, with **zero** differing key paths on a fully recursive comparison, in 1.65 s each. The `captured_at` key does not exist in the file: it belonged to the pre-v6 flat format, and the v6 envelope dropped the whole `capture` block as unverifiable (`sysml_codegen/snapshot/envelope.py:38-46`). The WI-029 comparison this used to rest on (`work/analysis/20260725-091831_audit_WI-029_handshake-lcoe-construction.md:190`) measured that older format; the migration commit `89f78130` replaced it. The models path does not leak either — v6 records root-relative referents, so the absolute-vs-relative `document_path` hazard WI-027 recorded is gone. Gate 4 therefore compares **whole-file bytes**, with no exclusion.

**There is no teax pin anywhere.** Confirmed by the spec (R-B1.1b) and re-checked: `simkit` exposes no `__version__`, and `verify.py:441` writes `getattr(simkit, "__version__", "unrecorded")`.

## Core Concept

**Integration is a proof, not a transformation.** The seam takes a package that someone claims is the integrated form of some audited model work and proves it, by re-running every producing step in place and requiring each one to change nothing. Regenerate on the pin: zero bytes move. Recapture the snapshot and re-derive the census: they match what is tracked. Recompute the manifest's pin and fingerprints: they match what is recorded. Then run the producers that only ever judged — the spine tests, preflight, verify — against that fixed point. R-B1's eight steps, in its order, stopping at the first one that is not a no-op or not a pass, plus the seam's own lineage comparison at the end. One `CANDIDATE` naming the package, manifest, pin and both fingerprints, or one `BLOCKER` naming the producer, whether it refused or could not run, and where its own output sits.

**Two of those gates judge the repository rather than the request** (Research Findings, M1), and that is correct rather than a defect: the toolchain pin and the canonical-tree/twins/census chain are properties of the repo the package was generated from. They close the other end of the lineage chain that gates 4, 6 and 7 close at the package end. What the design owes is to say so — and to make the one place it could go wrong, the test workspace, an asserted precondition rather than an accident (D13).

This shape is not a preference; it is forced, and the derivation is worth stating because the spec's prose reads the other way (see the surfaced conflict below). It is also what makes the seam cheap: it composes producers that all already exist, adds no identity scheme (R-D2, R-F2), and needs no rollback machinery, because on the success path there is nothing to roll back.

The pieces it composes, and what each keeps owning: `tests/test_dependency_provenance.py` owns the pinned-package check; `sysml-codegen generate` owns generation; `sysml_codegen.snapshot.capture` owns snapshot capture; `tests/models/test_model_family_spines.py` owns the canonical tree, the twins and the census; `scripts/study/manifest.py` owns the manifest schema, the two digest recipes and the pin comparison; `scripts/study/identity.py` owns identity recomputation; `preflight.py` owns the six mechanical gates and the refused-versus-could-not-run vocabulary; `verify.py` owns oracle parity and verdict re-derivation; the caller's route module owns baseline execution. The seam owns the order, the stop rule, the two return classes, and the one gate that has no producer — the teax revision comparison (R-B5).

### Surfaced: the spec reads as "perform", the requirements force "prove"

`[AGENT]` R-B1 is written as a list of things the seam does — regenerate, recapture, re-pin. But **SC4** requires the returned candidate to be accepted by the stock preflight route, whose sixth gate `check_package_clean` refuses a package tree that is not git-clean; and **R-F1** forbids the seam from committing. A candidate can therefore exist only when the whole sequence moved zero bytes in the tracked tree. R-C6 says the same thing from the other side: failure is reported, never repaired, and a seam that regenerates to fix a stale package is repairing.

The consequence, stated plainly rather than buried: **the seam refuses model work that has not yet been regenerated and committed.** That work belongs to the modeling item — WI-030 regenerated, recaptured, re-pinned and committed in its own Phases 3–4, *before* audit (`WI-030 plan:146-199`), which is the shape the epic's "audited model work" assumes. The seam is the gate on the hop, not the hand that performs it. If the owner intended the seam to perform the mutations and hand the operator a tree to commit, that is a two-call seam with a human commit between the calls, and R-A2's one-invocation-one-return no longer holds; that is an owner question, not a design call, and it is flagged rather than taken.

## Key Bets

- **B1.** Regeneration on the pin, in place on an already-sealed package, is byte-stable. *If false → gate 2 refuses on every invocation and the seam returns nothing but blockers.* CONFIRMED by spike: zero bytes across two in-place runs, both fingerprints held, 1.8 s (`spike_regen_determinism.md`).
- **B2.** Snapshot recapture from the same models path is byte-identical to the tracked snapshot. CONFIRMED by spike, and stronger than the bet was written: zero bytes and zero key paths differ across three recaptures, 1.65 s each; there is no `captured_at` key to exclude, and the models path does not affect the bytes (`spike_snapshot_stability.md`). The reserved fallback — narrowing to `instance_graph.fingerprint` alone — is not needed and is not carried. One residual: the `authority` block pins the toolchain versions into the file, so gate 4's byte comparison is also a toolchain-lineage check, and gate 1a is what should catch a pin drift first.
- **B3.** By the time model work is audited, its package is regenerated and committed. *If false → the seam's normal return is `BLOCKER` and it is a linter rather than a seam.* Held by WI-030's phase order and by the epic's Item 6 flow (invoke the seam, then run a study).
- **B4 — not a bet; measured.** Executing the manifest's own pinned baseline point is enough evidence for gates 7 and 8. WI-030 ran `verify.py` against the **baseline** store, not a sweep store, and got `outcome: pass`, `not_independently_verified: []`, six verdicts re-derived, `beta` among the compared channels (`WI-030 plan:203`). One completed case carries all six catalog verdicts, which is what `verify_store`'s completeness check demands (`verify.py:388`). Recorded as evidence rather than carried as a bet (A3).
- **B5.** A goal agent can act on `refused` versus `could not run` without further interpretation, given the stable `condition` slug the return carries (D14). *If false → the whole R-A6 distinction is decoration and the retry rule stays a human judgment.*
- **B6.** The census file a request names is derived from the same package the request names. The census records `entry_points` and a `derived_against_semantic_fingerprint`; gate 4 compares them against the sealed package, while gate 5 compares the same file against a fresh canonical-subset generation. That only closes into a chain if both derive from one model state — true today (`mfe_census.json` carries `entry_points: 173` and `1ca93d0c…`, the stellarator package's own count and semantic fingerprint) and load-bearing. *If false → gate 4 and gate 5 pass while binding the census to two different trees, and the lineage chain has a hole in the middle.* This is what breaks first when a second package enters the picture.

## Key Decisions

- **D1. One CLI script, `scripts/integrate.py`, is the only entry surface.** A script is callable from an operator shell, from another script, and from an agent's Bash tool, and is the only form testable offline — the sibling's D3 reasoning, unchanged. `[AGENT]`, settling the spec's entry-surface Open Question under orchestrator ruling 2. *Rejected: a slash command or skill* (not callable from code, no deterministic contract). *Rejected: a second operator surface* (ruling 2; R-A4 asks only that a human reach the same seam).
- **D2. Inputs are flags, and every one of them is optional to argparse.** The producers under `scripts/study/` all take flags; a human types the same line the goal agent's Bash tool runs. Required-ness is enforced *in the seam*, not by argparse, so a missing input produces a `BLOCKER` return document rather than a usage error on exit 2 — which is what R-A1 asks for and what makes "every invocation ends in exactly one return class" mechanically true. *Rejected: a request JSON* (a second schema to define and validate for eight scalars).
- **D3. The return is one atomic JSON document, `integration-seam-return/v1`, written into a caller-supplied `--out-dir`, plus a `preflight`-style human summary on stderr.** Written with `common.write_document` (`common.py:96`), so the seam's document has the same atomicity and canonical bytes as every other document in the family and is digestible by one recipe. The seam owns no tracked directory: `--out-dir` is the caller's, every reference inside the return is repo-relative, and the document is self-contained, so a goal trail or a study record cites it wherever the caller keeps it (ADR-006). *Rejected: a fixed home under `exploration/` or `work/`* (the producers name no package and neither may the seam; and a tracked home would make the seam a writer into one of the two PM systems). *Rejected: markdown* (R-A5 wants a test to check it).
- **D4. The blocker taxonomy is `preflight.py`'s, imported.** Every gate result carries `status` from `preflight.PASS` / `FAIL` / `DID_NOT_RUN`, and the blocker's `mode` is `refused` for `fail` and `could_not_run` for `did not run` — one distinction, R-A6's, with the producer-native condition text as its detail. Gates after the stop get a fourth status, `not reached`, so a reader never mistakes a skipped gate for a licence failure. Per-producer detection is in Architecture. *Rejected: typed codes for R-C1–C5 and R-C9* (six codes the caller's retry rule does not read; the producer name plus its own message is the evidence R-B3 wants).
- **D5. The expected teax revision is caller-supplied (`--expected-teax-revision`), and absent means could-not-run.** The seam recording its own expectation would be the seam minting a pin — a new identity scheme R-D2 and R-F2 forbid — and a self-recorded value re-records itself on drift, so it could never refuse. The caller is the one who knows the lineage. *Rejected: a seam-side pin file* (that file is the missing producer R-B5 files as a gap; building it here is the seam growing a producer).
- **D6. The seam executes the manifest's pinned baseline point through a caller-named route, and verifies against that store.** Orchestrator ruling 1. The route is named the way the manifest already names its oracle — a sys-path directory, a module, a callable (`manifest.oracle`, consumed as data by `verify.py:419`) — so the seam stays generic and invokes rather than imports a package. Contract: `callable(out_dir, *, package_dir, manifest_path) -> {"identity": Path, "baseline_result": Path}`, which is `study_route.execute_baseline`'s existing signature. *Rejected: a caller-supplied store* (the seam's verdict would rest on evidence it did not produce, and SC4 wants the stock route). *Rejected: hard-coding `study_route`* (breaks the family's no-package-names invariant for the one tool that sits above all of them).
- **D7. R-C8 is answered by ordering, plus one restore mechanism that works everywhere the seam runs.** No gate writes a promoting artifact: the identity document, baseline result, store, junit files, producer documents and the return all land under `--out-dir`. The only in-repo writes are the ones the byte-stability gates require to be no-ops. Before the first mutating gate the seam copies the resolved package tree to `--out-dir/_backup/`; on a byte-movement refusal it restores by copy — replacing changed files, deleting files the run added, restoring files the run removed, all driven by D8's before-digest so the restore set is exactly what moved.
  **Re-derived, not patched.** The first draft restored with `git checkout --` plus an `unlink` of the untracked paths git names, and rejected the copy as redundant. That was wrong in the place it matters: D10 puts the package in a **gitignored** directory, where `git status --untracked-files=all` reports nothing and `git checkout -- <ignored path>` matches no pathspec — so the git restore is a silent no-op exactly where the restore test runs. Detection already had this problem and D8 already solved it by not trusting git; restore has the same problem and gets the same answer. One mechanism, git-independent, correct in the tracked tree and in the workspace, and cheap: ~150 files, and the two spikes measured the tree operations they did on it in under two seconds. *Rejected: `git checkout --` plus `unlink`* (inoperative in a gitignored tree — the M3 finding). *Rejected: `git clean -fd`* (a hammer that can reach files the seam did not create, and it inherits the same ignored-path blindness). *Rejected: giving the workspace its own git repo* (it makes the restore work but leaves two restore mechanisms in the codebase, and it would also make `check_package_clean` judge the workspace's throwaway repo instead of the real one, which changes what gate 7 means).
- **D8. Byte movement is judged by the seam's own content digest, and git-cleanliness stays preflight's.** A per-file sha256 manifest over the package tree before and after each mutating producer, compared exactly (the spike's Step 2 technique). This is what makes the gates real inside a gitignored test workspace, where `git status` reports clean whatever the bytes do. `check_package_clean` is still invoked, unchanged, as preflight's own sixth gate. *Rejected: git status alone* (silently vacuous in the test harness — the failure mode where a green suite proves nothing). *Rejected: mtimes* (the spike measured 95 of 153 files moving mtime on a byte-identical run; any mtime detector reports a false positive on every re-run).
- **D9. The census gate re-derives through the spine test's own helper, and `--census-file` scopes gate 4 only.** `_by_entry_type` (`test_model_family_spines.py:169`) run against the sealed package, normalized `{k: sorted(v)}` the way the producer's own test does (`:358` — the helper returns sets, the file stores sorted lists, A5), compared to `--census-file`'s `by_entry_type` and `entry_points`, and its `derived_against_semantic_fingerprint` compared to the package's live semantic fingerprint. WI-030's plan says to run that helper rather than hand-edit (`plan.md:157`). Importing a private helper out of a test module is a smell whose cause is that the census derivation has no importable home; that is filed per R-F5, not fixed here (Integration Strategy). *Rejected: reimplementing the classification* (R-B1's `[HARD]` half). The two census checks are different and both are wanted: gate 4 binds `--census-file` to the *sealed package*; gate 5 binds the **tracked** `tests/models/data/mfe_census.json` to a fresh canonical-subset generation, and the twin-equality test binds the staged tree to the canonical one. Together they close the lineage chain, on bet B6. Note for the guide: `--census-file` reaches gate 4 and nothing else — gate 5 reads the tracked file whatever the flag says.
- **D10. The SC1 fixture is the committed stellarator package as it stands, materialized into a gitignored in-repo workspace whose equality with the committed state is asserted, not assumed.** It is WI-030's audited model change, already integrated, so no new modeling work is minted; its recorded fingerprints are the expected lineage. The workspace has to be *inside* the worktree because `repo_root()`-relative machinery (`repo_relative_posix`, `identity.recompute`'s adapter paths, `git_status_porcelain`) resolves against it, and gitignored so R-G3 holds — no test writes a tracked file. Removed in a `finally`.
  **The precondition D13 needs.** The fixture asserts, before handing the workspace to the seam, that every materialized file's sha256 equals the tracked file's, and that the repo itself is clean over the source paths. Repo-scoped gates 1a and 5 stay meaningful exactly while that holds, so it is checked rather than hoped. A test that doctors a workspace file to drive a refusal (gate 4 or gate 6) does so **after** that assertion, and the return then records that gates 1a and 5 judged the unmodified repo — which is the truth. *Rejected: running the seam against the real tracked package* (the spike proves it is safe and Item 2's F3 finding still says don't). *Rejected: `tmp_path` via the existing `package_copy`* (outside the repo; git errors instead of judging).
- **D11. SC4 needs no hand-off step in the seam.** Gates 7 and 8 *are* the stock preflight and verify invocations, run with the arguments a study runs them with. R-G1a's test reads `integration_return.json` and rebuilds those two command lines from its fields alone, with no seam code in the loop. *Rejected: a `--handoff` step* (machinery for something two gates already do).
- **D12. No lock, no ledger, no retry, no idempotency wrapper.** R-F2 and the epic's hardening rule: nothing enters the first build without a recorded run failure that promotes it.
- **D13. Gate scope is declared per gate, and repo-scoped is not a defect.** Every row of the gate table carries a `scope` of `repo` or `request`. Gates 1a and 5 are `repo` because their producers are built that way (Research Findings) and because what they judge — the toolchain pin, the canonical tree, the twins, the tracked census — genuinely is a repository property. The return records the scope beside each gate result, so a reader is never misled about what a pass covered. The claim "the seam names no package" is narrowed to what is true: *the seam* names no package; two of the producers it invokes are bound to this repository by construction. *Rejected: pretending gate 5 is package-scoped* (the M1 finding — it silently makes the workspace tests prove something other than what they claim). *Rejected: dropping gates 1a and 5* (R-B1 `[HARD]`: each gate is invoked).
- **D14. The blocker carries a stable `condition` slug; the goal layer's vocabulary stays in the goal layer.** `condition` is a short kebab-case string from a closed set the operator guide enumerates — `input-missing`, `env-missing`, `toolchain-drift`, `package-not-integrated`, `handwritten-lost`, `census-stale`, `snapshot-drift`, `repo-lineage-broken`, `manifest-stale`, `preflight-refused`, `verification-refused`, `lineage-mismatch`, `seam-internal-error`. It is *detail*, not a third return class: the seam stays two-class (R-A2) and two-mode (R-A6). The guide states the mapping a goal caller applies — `package-not-integrated`, `census-stale`, `snapshot-drift` and `handwritten-lost` are the modeling item's unfinished work and read as `PREREQUISITE` on the goal side; `env-missing` and `seam-internal-error` read as `MECHANICAL_FAILURE`; the rest read as `STRATEGY_BLOCKER`. **Why the mapping is not in the seam:** importing the concept-design's task-return vocabulary would make a native tool depend on the goal layer's ontology and would put the goal layer's classification rule in a file the goal layer does not own (M7 steering). A test pins the slug for each refusal fixture, so the mapping has something stable to key on. *Rejected: a third mode* (R-A6 fixes two, and the retry rule reads two). *Rejected: prose only* (Item 6 would parse English).
- **D15. Gate 8 has one discriminating signal, and gate 0 supplies the other.** `verify.py` writes no document when it refuses and returns 1 for every cause including `import simkit` (Research Findings, M4), so exit code and output cannot separate refused from could-not-run. The seam therefore checks verify's *preconditions itself, at gate 0* — `STOP_PARSER_TEAX_ROOT` set, its `packages/teax-simkit` present, `simkit` importable under the environment the seam will hand the subprocess (D16) — and classifies their absence as could-not-run before any producer runs. Past gate 0, a non-zero exit from `verify.py` is **`refused`**, full stop, with its stderr captured to `--out-dir/verify_stderr.txt` as the cited evidence. The residual is honest and stated: a teax import failure that gate 0's probe did not predict lands as `refused`. That is a producer shortfall, filed per R-F5 against `scripts/study/verify.py`. *Rejected: matching stderr strings* (a brittle coupling to messages `verify.py` is free to reword, and R-B2 freezes the file so the coupling could never be made safe from the other side).
- **D16. One subprocess environment, defined once.** Every subprocess the seam launches inherits `os.environ` and then gets, explicitly: `PYTHONPATH` prepended with the repo root and `$STOP_PARSER_TEAX_ROOT/packages/teax-simkit`; `SYSIDE_LICENSE_KEY` and the four `STOP_PARSER_*` wheel variables passed through; and `STUDY_REQUIRE_TEAX=1`, so a teax-dependent producer fails loudly instead of skipping and reporting green (`conftest.py:239-242`). WI-030 recorded the trap this closes (`plan.md:304`): `verify.py` does no `sys.path` work of its own and imports `simkit` from wherever the environment provides it (`verify.py:415`). The guide lists the same variables, so an operator's hand invocation and the seam's match. *Rejected: a clean environment* (the producers need the licence and wheel variables, and reconstructing them is inventing configuration). *Rejected: leaving it to the plan* (it is the difference between gate 8 judging and gate 8 crashing).
- **D17. `assert_read_set_covered` is out of reach and stays out, with the obligation named.** R-B1.6 enumerates four manifest assertions; gate 6 runs three. The fourth needs `resolved_paths` — the paths the indicator reader opened from the pipeline's own `EntryPoint` refs — which exist only inside `scripts/study/indicators.py:808`, its sole caller. The seam does not run the indicator tool and cannot synthesize that list without reimplementing the reader, which R-B1 `[HARD]` forbids. So the assertion is **not covered by this seam**, and nothing else covers it either: preflight's six gates do not, and `verify.build_summary` does not. Stated as a coverage boundary rather than left silent (M5), and filed per R-F5. *Rejected: calling it with a list the seam derives* (a second implementation of the reader's resolution, which is the exact failure R-B1 exists to prevent). *Rejected: running the indicator tool to get the list* (it is a study tool; running it here would make the seam do a study's work for one assertion).
- **D19. The tracked snapshot is found beside the models root, not named by a flag.** `[AGENT]`, ruled by the owner at implement (2026-08-26). The request carries no `--snapshot`: the design's own data-flow list does not include one, and adding a flag for a file that has exactly one home would be a ninth input for an operator to get wrong. So gate 4 discovers it as the single `*.snapshot.json` beside the models root — the "found rather than named" pattern `study_route.spec_path` already uses for a package's one pipeline spec. **Zero or several is `input-invalid`, mode `could_not_run`** (R-C5's ambiguity clause, the same slug two `--package` values get), never a guess at which one. The test workspace mirrors the tracked layout so the discovery is exercised the way production hits it, and a test pins it. *Rejected: a `--snapshot` flag* (a ninth input, and an operator who passes the wrong one gets a refusal that reads as model drift). *Rejected: deriving the name from the package name* (the seam names no package).
- **D20. Gate 2 owns everything regeneration rewrites; gate 3 owns the subtree it must never open.** `[AGENT]`, at implement. R-B1 makes regeneration and handwritten preservation two steps, and the design's gate table gives them two conditions — `package-not-integrated` and `handwritten-lost` — because the operator action differs: a stale package is re-run in the modeling item, a stubbed normative implementation is a lost hand-written proof. If gate 2 compared the whole tree it would refuse first on any handwritten movement and gate 3 could never fire, so gate 3's own condition would be unreachable. Gate 2 therefore compares every package-relative path **outside** `handwritten/` and gate 3 compares those inside it. The union is the whole package, so nothing is uncovered, and each gate refuses for its own reason. *Rejected: gate 2 comparing everything and gate 3 re-asserting a subset* (an unreachable refusal path, which is the shape of dead code).
- **D21. Interpreter bytecode caches are not package artifacts.** `[AGENT]`, at implement, after a measured false refusal. `package_digests` skips `__pycache__`. Measured: with them included, gate 2 refused on 60+ `.pyc` files whose bytes move because the copy reset their source mtimes — a refusal about nothing anyone authored. Nothing seals them (`contracts/package_contract.json`'s `artifact_hashes` does not list them), and the repository ignores them everywhere, so `preflight.check_package_clean` does not see them either. Excluding them makes the seam's own digest judge **the same set of files the repository's cleanliness gate judges**, which is what D8 said the two were for. *Rejected: leaving them in* (every package that has ever been imported refuses gate 2, and the gate stops meaning anything).
- **D18. Exit codes are part of the contract.** `CANDIDATE` → 0. `BLOCKER` → 1. An unexpected exception inside the seam is caught at the top level, written as a `BLOCKER` with `mode: could_not_run` and `condition: seam-internal-error` carrying the traceback path, and exits **2** — so the caller can tell "the seam judged and refused" from "the seam broke," and a return document exists in every case (A2). *Rejected: a bare non-zero for everything* (an agent's Bash tool reads the exit code before it reads the document).

## Architecture

**One invocation, in order.** Gate 0 is the seam's own precondition sweep and it owns **every** environment precondition, in one place, so no producer is ever invoked into a condition the seam already knew about (M2, D15, D16):

1. Required inputs present and resolvable; package resolves to exactly one root and one manifest, else R-C5/R-A3.
2. Environment: `SYSIDE_LICENSE_KEY`; `STOP_PARSER_WHEEL_TARGET`, `STOP_PARSER_AGENTIC_WHEEL`, `STOP_PARSER_CODEGEN_WHEEL`, `STOP_PARSER_COSTINGFE_WHEEL` (gate 1a reads all four in its test body); `STOP_PARSER_TEAX_ROOT` with `packages/teax-simkit` present and `simkit` importable under D16's environment. Any absence is a `BLOCKER` with `mode: could_not_run`, `condition: env-missing`, naming the variables — **before** gate 1a runs, which is what stops the standing `KeyError` from being reported as a refusal.
3. Package tree git-clean, via `preflight.py clean --package --out` — the producer's own subcommand (`preflight.py:487`), invoked rather than reimplemented (A9), else R-C1.
4. The D8 before-digest and the D7 backup copy.

Then R-B1's eight steps, which expand to nine rows because step 1 splits into two producers, and the seam's own lineage comparison as the tenth. The seam stops at the first non-pass, restores if it has to, and writes one return.

| # | Gate | Scope | Producer, invoked as | `could not run` when | `refused` when |
|---|---|---|---|---|---|
| 1a | pinned packages | repo | `pytest tests/test_dependency_provenance.py --junitxml` | gate 0's env sweep already refused; else exit 2/3/4/5 or any `<error>` | exit 1 with a `<failure>` |
| 1b | teax revision | request | the seam: `git -C $STOP_PARSER_TEAX_ROOT rev-parse HEAD` (R-B5) | `--expected-teax-revision` absent, or `rev-parse` non-zero | revision differs (A6: compared casefolded, expected matched as a prefix of actual, both recorded in full) |
| 2 | regeneration | request | `sysml-codegen generate --smart-regen --preserve-handwritten`, in place | non-zero exit (licence handled at gate 0) | exit 0 and any package byte moved (D8) |
| 3 | handwritten preservation | request | the same digest comparison, scoped to `generated/handwritten/` | gate 2 could not run | any byte under that subtree moved |
| 4 | census / snapshot | request | `capture_instance_graph_snapshot` into `--out-dir`; `_by_entry_type` on the sealed package (D9) | capture raises; `--census-file` absent; the tracked snapshot is not found uniquely (D19) | recaptured snapshot differs from the tracked one in any byte (B2); census counts, classes, or bound fingerprint differ |
| 5 | model-family spine | repo | `pytest tests/models/test_model_family_spines.py --junitxml` | as 1a (licence errors are pre-empted at gate 0) | exit 1 with a `<failure>` |
| 6 | manifest | request | `manifest.load` (which validates, A4) → `assert_package_identity` → `assert_pin_matches` over the live `indicator_input_fingerprint`; `assert_read_set_covered` is out of reach (D17) | `ManifestError` from `load` (unreadable / not JSON) | `ManifestError` from either assertion |
| 7 | preflight | request | `preflight.py gates --package --manifest --groups --identity --baseline-result --out` | its own `DID_NOT_RUN` on the stopping gate; baseline execution failed | its own `FAIL` |
| 8 | verification | request | `verify.py --package --manifest --identity --store --out` | pre-empted at gate 0 (D15) | any non-zero exit, stderr captured as evidence |
| 9 | lineage (R-C9) | request | the seam: live semantic and executable fingerprints against the request's expected pair | `--expected-*-fingerprint` absent | either differs; the blocker carries `expected` and `actual` (M6) |

Gates 1a and 5 judge the repository the package was generated from, not `--package` (D13); the other seven judge the request. Baseline execution (D6) sits between gates 6 and 7, because both 7 and 8 read what it deposits and neither can run without it; its own failure is a `could not run` on gate 7, named as such. Gate 9 is last because a package that failed a gate has no lineage worth reporting.

**Refusal is producer-grain, not sub-gate-grain** (R-B4). `preflight gates` reports all six of its checks whatever happened; a blocker from gate 7 names the producer and cites the whole results document, which may carry several failures at once. Gates after the stop are recorded `not reached`.

**Data flow.** In: audited work references (repo-relative path plus commit sha, ADR-006's citation form), models root, package root, manifest, axis declaration, census file, expected lineage (semantic and executable fingerprints, teax revision), route triple, out-dir. Out, under `--out-dir`: `integration_return.json`, `package_identity.json`, `baseline_result.json`, `_work/<baseline>.db`, `clean.json`, `preflight_results.json`, `verification_summary.json`, `verify_stderr.txt`, `recaptured.snapshot.json`, `junit/*.xml`, `_backup/` (D7), and on a byte-movement refusal `moved_files.txt`. In the tracked tree: nothing, ever.

**Return shape** (R-A2, R-A5, R-A6, R-E2, R-E3):

```jsonc
{"schema_version":"integration-seam-return/v1","tool":{"path","source_digest"},"command":[],
 "request":{"audited_work":[{"path","commit"}],"models_root","package","manifest","groups",
            "census","expected":{"semantic_fingerprint","executable_fingerprint","teax_revision"}},
 "class":"CANDIDATE|BLOCKER","exit_code":0,
 "candidate":{"package","manifest","pin","semantic_fingerprint","executable_fingerprint",
              "identity_document","baseline_result","verification_summary"},   // or null
 "blocker":{"gate","producer","scope","mode":"refused|could_not_run","condition",
            "detail","expected","actual","evidence":[]},                       // or null
 "gates":[{"gate","producer","scope","status","checked","detail","evidence":[]}],
 "toolchain":{"agentic_mbse","sysml_codegen","costingfe","teax_revision","teax_module_path"}}
```

`pin` is the manifest's `fingerprints.indicator_inputs.digest` — the value `assert_pin_matches` compares, not a new number. `blocker.condition` is D14's closed slug set. `blocker.expected` / `blocker.actual` are populated for gates 1b and 9 and null elsewhere; `blocker.producer` is `"scripts/integrate.py"` on the two gates the seam judges itself (1b, 9), which is what makes "name the producer" true rather than empty (M6).

## Required Invariants

- No tracked file's bytes differ before and after an invocation, whatever its return class.
- All **ten** gate entries appear in the return with a status and a scope: R-B1's eight steps expanded to nine rows (step 1 splits into two producers), plus the seam's lineage comparison. `CANDIDATE` exists only when all ten are `pass` (A1).
- A `BLOCKER` names exactly one producer — the first non-pass in gate order — with `mode` set from that producer's own status vocabulary and a `condition` from D14's closed set. Every later gate is `not reached`, never `could not run`.
- Every path, digest and identity in the return resolves to a repo path, a commit, or a file under `--out-dir` (R-E3).
- No gate is skipped because a prior run passed it (R-B4), and no gate runs after an earlier one refused.
- No producer is invoked into an environment precondition gate 0 could have checked (D15, D16): the seam's env sweep is the only place `could_not_run` is decided for a missing variable.
- Nothing under `scripts/study/`, `tests/models/`, or `tests/test_dependency_provenance.py` is edited (R-B2): `git diff --stat` over those paths is empty at close. Existing `tests/study` fixtures are unchanged in behaviour, and the suite's pre-existing tally is unmoved by the conftest extension (A12).
- A re-run on unchanged inputs returns the same `pin`, the same semantic and executable fingerprints, and the same `package` and `manifest`. The three `candidate` fields that are paths under `--out-dir` — `identity_document`, `baseline_result`, `verification_summary` — differ by construction and are not part of the claim (R-D1, A8).
- Repo-scoped gates (1a, 5) are only meaningful while the tree they judge is the tree the request's package came from. In production that is the repo itself; in tests D10's workspace-equals-committed-state assertion is what keeps it true.

Imports `preflight`, `manifest`, `identity`, `common` for constants, digests and document writing; invokes `pytest`, `sysml-codegen`, `preflight.py` and `verify.py` as subprocesses so each producer's own exit code and output document are the evidence.

It lives here to reuse the teax and licence skip machinery (`:239-270`) rather than duplicate it; it is test infrastructure, not a gate producer, so R-B2 is untouched — and its arrival must not move the existing suite's behaviour (A12).

- **`docs/integration_seam_operator_guide.md`** — R-E1/SC6: assembling a request (including where each of the eight inputs comes from, since the concept-design's seam row names only two of them — A7), invoking the seam, reading `CANDIDATE` versus `BLOCKER`, the exit-code contract (D18), the `condition` → goal-class mapping (D14), the subprocess environment an operator must export (D16), citing a candidate in a study, and acting on each blocker. ## Non-Goals

- Performing the integration. The seam proves a package is the integrated form; regenerating, recapturing and re-pinning stay in the modeling item that made the change (surfaced above; R-C6).
- An `--apply` mode that leaves mutations in place for an operator to commit. It is the two-call shape the surfaced conflict describes, and it is an owner question.
- Committing, pushing, closing modeling work, or choosing among model designs (R-F1).
- A goal-side effects ledger, idempotency wrapper, or second verification implementation (R-F2).
- Fixing the calc-then-compare parser limitation, or `verify.py`'s `teax.revision: "unrecorded"`. Both stay filed against their own homes (R-F4, R-F5).
- Running or interpreting a study. Baseline execution is a gate's own input, not a study (Non-Goals boundary note; ruling 1).
- Carrying the goal layer's task-return vocabulary. The seam emits two classes and two modes plus a stable `condition`; `PREREQUISITE` / `STRATEGY_BLOCKER` / `MECHANICAL_FAILURE` are the goal layer's names and the mapping lives in the operator guide, not in `scripts/integrate.py` (D14).
- Making gates 1a and 5 package-scoped, or a driven refusal for gate 5. Their producers are repo-bound by construction; parameterizing them is an R-F5 filing, not this item's work (D13, and the stated coverage boundary in Validation Approach).
- Covering `assert_read_set_covered`. Out of reach here and uncovered anywhere; named and filed rather than silently dropped (D17).

## Implementation Notes

- **The baseline store path is not returned by `execute_baseline`.** Resolve it from `baseline_result.executed_under.store_id`, which is repo-relative when `--out-dir` is under the repo root and a bare filename otherwise; fall back to `<out-dir>/_work/<name>`.
- **The package root is a symlink** (`pkg/stellarator_tea` → `../generated`). Resolve before digesting, before backing up, and before comparing paths.
- **Never build mtime-based change detection.** 95 of 153 files move mtime on a byte-identical regeneration (spike Step 4).
- **`--junitxml` separates `<error>` from `<failure>`, and that is all it does.** It does not carry R-A6 on its own for gates 1a and 5 — the wheel-variable `KeyError` is raised in the test body and lands as a `<failure>` (Research Findings, M2). Gate 0's env sweep is what makes those two gates classify correctly; junit is the secondary signal and the evidence file.
- **Every environment precondition is checked in one place, gate 0** (D15, D16). No producer invocation is preceded by its own ad-hoc env check.
- **`_by_entry_type` returns sets and the census file stores sorted lists.** Normalize `{k: sorted(v) for k, v in …}` as the producer's own test does (`test_model_family_spines.py:358`).
- **The seam names no package and no key prefix**, matching every module it sits above (`preflight.py:44`, `manifest.py:16`, `identity.py:29`). Two of the producers it invokes are repo-bound by construction (D13); that is a property of those producers, not of the seam.
- **Reuse `common.write_document`, `common.tool_source_digest`, `manifest.sha256_file`, `manifest.repo_relative_posix`.** One recipe id must mean one algorithm (`common.py:50-52`).

## Potential Risks

- **B2 measured and closed.** Snapshot recapture is byte-identical to the tracked file (`spike_snapshot_stability.md`); gate 4 compares whole-file bytes and the weaker `instance_graph.fingerprint` fallback is dropped. What remains is that the snapshot's `authority` block pins the toolchain, so a version bump moves the bytes and refuses gate 4 — correct behavior, but a refusal there reads as model drift unless the return names the cause.
- **The gitignored workspace makes `check_package_clean` vacuous in tests.** D8's own digest is what keeps the byte gates real there; the risk is that a future edit removes the digest comparison believing git covers it. The invariant is stated and one test asserts movement is caught inside the workspace.
- **Wall clock.** Two pytest suites, a generation, a snapshot capture and a baseline execution per invocation. Generation is 1.8 s; the spine suite and the baseline run dominate. Acceptable for a hop that happens once per model change, and a reason not to call the seam in a loop.
- **The restore path is exercised rarely and matters most.** It is covered by its own test (a deliberately stale package), not left to the success path, and D7's rewrite exists because the first mechanism was inoperative exactly there.
- **A `--census-file` that is absent silently weakens nothing** — it is a could-not-run blocker, by design — but an operator who does not know to pass it will read the seam as broken, and one who passes it may believe it scoped gate 5. It does not. The guide leads with the full invocation and says so.
- **Repo-scoped gates make the seam's verdict partly about the working tree the operator is standing in.** A dirty or mid-edit repo can refuse gate 5 for reasons that have nothing to do with `--package`. The return's `scope` field is what tells the reader which happened; the guide names it as the first thing to check on a gate-5 refusal.
- **Gate 8's residual** (D15): a teax import failure gate 0's probe did not predict arrives as `refused`. Bounded by the probe importing `simkit` under the same environment the subprocess gets, and filed against `verify.py`.
