## Business Goals

### Why This Matters

`concept_id` means two different things depending on which system you're in:

| Location | `concept_id` value | Example |
|----------|-------------------|---------|
| `concept_registry.json` → `ConceptTaxonomy` | Slugified name | `"hts-compact-tokamak"` |
| `04.json` → `ConceptData` | Analysis directory ID | `"04"` |
| `manifest.json` → `ConceptManifestEntry` | Analysis directory ID | `"04"` |

The `analysis_id` field on `ConceptTaxonomy` (renamed from `cost_model_id` in commit d4ceb34) bridges the two, but doesn't fix the naming collision. This already caused two bugs:
1. The categorical view keyed a cache by taxonomy `concept_id` (slug), but the comparison shell passes `ConceptData.concept_id` (analysis ID) — everything showed "N/A".
2. The selection tray's compare navigation passes slugs to the compare page which validates against the manifest (analysis IDs) — **selections from taxonomy don't work in compare**.

Every cross-boundary feature will rediscover this.

### Success Criteria

- [ ] `concept_id` means the analysis directory ID (`"04"`) everywhere — taxonomy and cost model systems agree
- [ ] The taxonomy slug (`"hts-compact-tokamak"`) has a distinct field name (`slug`) that cannot be confused with `concept_id`
- [ ] `analysis_id` field eliminated — redundant once `concept_id` holds the analysis ID on both sides
- [ ] Analysis ID is the universal lookup key in all JS registries — no slug-keyed lookups, no translation layers
- [ ] All pages work unchanged (taxonomy, concept profile, comparison, index)
- [ ] Selection tray → compare page navigation works (currently broken)
- [ ] `grep -rn "analysis_id" exploration/` returns zero hits

### Priority

Tech debt. Prevents bugs in every future cross-boundary feature. Also fixes an existing bug (selection tray → compare navigation).

## Problem Statement

### Current State (Verified)

**`concept_registry.json`** (38 entries, loaded as `ConceptTaxonomy`):
```json
{ "concept_id": "hts-compact-tokamak", "analysis_id": "01", "name": "HTS Compact Tokamak", ... }
```
- `concept_id` = slug (generated by `slugify(name)` in `seed_registry.py`)
- `analysis_id` = analysis directory ID (read from `concept_analysis/table.csv`)
- `ConceptRegistry.by_id()` searches by slug
- Similarity reports dict keyed by slug
- `taxonomy.js` builds `_registry` keyed by slug (line 95)
- Decision tree leaf arrays contain slugs
- API routes `/api/taxonomy/similarity/{concept_id}` and `/api/taxonomy/concepts/{concept_id}` expect slug

**Cost model data files** (`04.json`, `05.json`, etc., loaded as `ConceptData`):
```json
{ "concept_id": "04", "name": "Laser ICF - p-B11 Fast Ignition", ... }
```
- `concept_id` = analysis directory ID
- URLs use this: `/concept/04`, `/compare?concepts=04,05`
- `/api/concepts/{concept_id}` expects analysis ID
- `manifest.json` uses analysis ID

**Known bugs caused by the split:**
1. `view_categorical.js:89-92` — required `c.analysis_id || c.concept_id` workaround
2. `taxonomy_card.js:120-123` — must use `concept.analysis_id` instead of `concept.concept_id` to link to cost model pages
3. `selection_tray.js:128-132` — stores both `concept_id` (slug) and `analysis_id`; compare navigation passes slugs → compare page rejects them because manifest uses analysis IDs

### Desired Outcome

Analysis ID is the single canonical identifier everywhere:
- `ConceptTaxonomy.concept_id` = `"01"` (analysis directory ID, same meaning as `ConceptData.concept_id`)
- `ConceptTaxonomy.slug` = `"hts-compact-tokamak"` (human-readable, for display only — never a lookup key)
- `analysis_id` field gone
- All JS registries, decision tree leaves, similarity reports, and API routes use analysis ID as `concept_id`
- No translation layers between systems

## Scope

### In Scope

**Python models** (`taxonomy_models.py`):
- `ConceptTaxonomy`: rename `concept_id` → `slug`, rename `analysis_id` → `concept_id` (type: `str`, required)
- `ConceptRegistry.by_id()`: searches by `concept_id` (now analysis ID — same code, different value)
- Add `ConceptRegistry.by_slug()` for any future slug-based lookups

**Data regeneration** (`seed_registry.py` + output files):
- Update field assignments: `concept_id=row["ID"]`, `slug=slugify(name)`
- Regenerate `concept_registry.json` and `decision_tree.json` (tree leaves will contain analysis IDs)

**Server** (`server.py`):
- No code changes needed. All `concept.concept_id` references automatically become analysis IDs because the field value changes. Similarity report dict keys, route handler lookups — all just work.

**Similarity** (`similarity.py`):
- No code changes needed. All `concept_id` references on `ConceptTaxonomy` objects automatically carry analysis IDs.

**Frontend JS:**
- `taxonomy.js`: No code changes needed. `_registry[concepts[c].concept_id]` automatically keys by analysis ID.
- `taxonomy_card.js`: `concept.analysis_id` → `concept.concept_id` (2 lines)
- `selection_tray.js`: Remove `analysis_id` storage, simplify to single `concept_id`. Add `_modeledIds` check for cost-model gating (currently uses `analysis_id` truthiness).
- `view_categorical.js`: Remove `analysis_id || concept_id` workaround (1 line)
- `constellation.js`, `neighborhood_graph.js`, `tree_view.js`: No code changes — `concept_id` passthrough carries analysis IDs.

**Tests:**
- `test_taxonomy_models.py`: Update all slug → analysis ID in test data, update assertions
- `test_taxonomy_server.py`: Update route calls and assertions

### Out of Scope

- `ConceptData.concept_id` — already correct, not touched
- `manifest.json` — already uses analysis ID, not touched
- URL schemes — `/concept/04`, `/compare?concepts=04,05` unchanged
- Data file naming — `04.json` stays as-is
- `server.py` route code — no changes needed
- `similarity.py` code — no changes needed

### Edge Cases

- **Tree leaf label flash**: After change, tree leaves briefly show `"01"` instead of `"hts-compact-tokamak"` before `updateLeafLabels(nameMap)` replaces with the concept name. Imperceptible (<100ms) and the slugs were poor labels anyway.
- **Broken bookmarks**: Anyone with `?selected=hts-compact-tokamak` URLs will lose their selection. Dev-only tool, no external users.
- **`ConceptTaxonomy.concept_id` becomes non-nullable**: Currently `analysis_id: str | None = None`. After rename to `concept_id`, it MUST be `str` (required). All 38 concepts already have analysis IDs (commit d4ceb34).

## Requirements

### Functional Requirements

1. **FR-1**: `ConceptTaxonomy.concept_id` MUST contain the analysis directory ID (e.g., `"01"`), type `str` (required, not optional).

2. **FR-2**: `ConceptTaxonomy.slug` MUST contain the descriptive slug (e.g., `"hts-compact-tokamak"`), type `str` (required).

3. **FR-3**: `ConceptTaxonomy.analysis_id` MUST be removed entirely.

4. **FR-4**: `ConceptRegistry.by_id(id)` MUST search by the new `concept_id` field (analysis ID).

5. **FR-5**: `ConceptRegistry` SHOULD provide `by_slug(slug)` for any future slug-based lookups.

6. **FR-6**: `concept_registry.json` and `decision_tree.json` MUST be regenerated with analysis IDs as `concept_id` and slugs as `slug`.

7. **FR-7**: All Python, JS, and test code referencing `analysis_id` on taxonomy objects MUST be updated. Zero remaining references.

8. **FR-8**: Analysis ID MUST be the universal lookup key in all JS registries (`_registry` in `taxonomy.js`, `_taxonomyCache` in `view_categorical.js`, `_selected` in `selection_tray.js`). No slug-keyed lookups. No translation layers.

9. **FR-9**: All existing pages MUST continue to work without user-visible changes.

10. **FR-10**: `seed_registry.py` MUST assign `concept_id` from the CSV ID column and `slug` from `slugify(name)`.
