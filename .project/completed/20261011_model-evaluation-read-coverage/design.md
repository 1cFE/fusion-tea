# Design: scoped Python read observation

[AGENT] Preserve the ten existing integration gates. Gate 6 parses pipeline references using `indicators.read_pipelines`, calls `manifest.assert_read_set_covered` over its resolved artifacts and the contract, and records a small static coverage receipt. Gate 7 wraps its existing route subprocess in a read observer and refuses `read-coverage-refused` before stock preflight if observation fails. The candidate schema and identities remain unchanged; gate evidence cites the additional receipt.

[AGENT] A new `scripts/study/read_coverage.py` owns a Python audit hook. Install it before importing the selected route. Canonicalize paths to catch symlink escapes. Before observation, declare exact package files from the package contract artifact seal plus the package contract itself, manifest, and Python source files under the supplied route directory, repository scripts and configured teax-simkit root. Hash those source/declaration files before execution. Package files must match their seal; pipeline/input paths must also satisfy the manifest membership assertion. The route's output directory admits files first written during this invocation only; it is not a general read exemption. Audit open events reject other non-runtime files. Record dependency identities and compare observed declared files again after execution, including initial hashes at each read, to catch changes before or after a read. Writes alone do not establish a new input identity except for new run outputs.

[AGENT] Interpreter/stdlib/site-packages files under `sys.base_prefix` and `sys.prefix` are a separately recorded runtime category, not falsely added to the manifest pin. Hash observed readable runtime files at first observation and check again at completion. Existing toolchain gates independently establish their pinned wheel/revision provenance; observed hashes do not claim a complete runtime installation attestation. Bytecode imports are canonicalized to their source where available and source hashes are checked; Python's existing cached-bytecode validation remains a limitation.

[AGENT] Record unsupported integer file-descriptor reads. Refuse Python-audited subprocess creation, `os.system`, fork and exec attempts rather than let a child silently escape observation. Native C file reads, SQLite internals, mmap/direct syscalls, pre-opened handles and adversarial audit bypass are not observed. This is a cooperative Python baseline gate, not a sandbox or universal read monitor. Failed opens may conservatively refuse. Environment and network reads are outside its file claim. Persist outcome, classified paths/hashes, violations and limitations in `read_coverage.json` after deactivating the hook, including exceptions.

[AGENT] Focused tests run real observer subprocesses and a synthetic integration route. The coordinator runs the full live seam against its committed checkpoint. Existing historical receipts are not rewritten.

## Review amendment

[AGENT] The claim is baseline Python-observable dependency identity for one invocation. It does not cover unexecuted branches or future study points. Runtime first-observation hashes remain distinct from pre-execution declared hashes. Hash-before-open and post-execution checks cannot prove consumption of the hashed bytes under concurrent or transient mutation (TOCTOU).

[AGENT] Superseding the source-only cache policy above: retain the actual bytecode path and its first-observation hash alongside the predeclared source identity. Check both on subsequent reads and completion. Accept cached imports only when their resolved source is declared (or classified runtime); reject sourceless project bytecode. A cache hash records observed executable bytes, not equivalence to source. Test unchanged cached import and cache mutation during observed execution.

[AGENT] Add `scripts/study/read_coverage.py` and `scripts/study/indicators.py` to the seam's existing tool-source identity list. Test both entries in the emitted identity.

[AGENT] Classification order is sealed package, exact declared manifest/source, bytecode with declared source, runtime, newly created output. Output admission requires the canonical path to be absent at first write-open and under the output root. Append or read/write opens of pre-existing output files refuse; writing a declared dependency cannot reclassify it. Receipt wording records attempted creation admission, not proof of completed writes.

[AGENT] Parent creates a fresh invocation token and removes any prior receipt before spawning the route. Require a structurally valid receipt with matching token and successful outcome before stock preflight. Retained violations force refusal even if route code catches the observer exception and exits zero. Missing, malformed, mismatched or failed receipts refuse. Preserve the receipt on route errors, and test these conditions at the integration gate.

[AGENT] Stock probe 1 exposed a required `importlib.metadata` read of teax-simkit's installed `*.egg-info/entry_points.txt`. Declare and hash the exact files in immediate teax-simkit `*.egg-info` directories before execution as `declared-dependency-metadata`. Apply the same read-time and completion comparisons as sources. This is a bounded metadata declaration, not a blanket teax data exemption. Preserve the original refusal receipt.

[AGENT] Stock probe 2 exposed the standard library's creation/read of a new tempfile directory probe outside the output root. Give only the baseline subprocess a fresh `TMPDIR` under its invocation output directory, preserving the reviewed new-output policy without exempting arbitrary temporary inputs. The observer still starts before route import. This changes scratch placement only.

[AGENT] Stock probes 3 and 4 reached the stock artifact store. Directory handles are metadata outside regular-file byte observation. Atomic output rename transfers attempted creation admission only from an already admitted new file to an absent destination under the output root; package/source precedence still wins. Pre-existing destinations and undeclared sources cannot acquire admission through rename. This supports the store's atomic-write protocol without exempting its whole directory. Add both positive and pre-existing-destination tests.

[AGENT] Independent implementation review found stale new-output admission after rename. Admission now follows the currently admitted path: moves revoke source and destination (including descendants), deletion revokes, and only a newly created regular non-symlink source transfers to an absent output destination. Hardlink creation does not transfer admission; symlink reads must classify their resolved target. Failed mutation attempts conservatively revoke admission. Directory-relative mutation paths resolve through their actual descriptor parent on this Linux runtime; unavailable resolution refuses. The historical creation-attempt list is separate from current admission. Thread-local recursion suppression prevents one thread's observer hash from suppressing another thread's audit events.

[AGENT: coordinator request] The current stock route can otherwise reuse a SQLite case store in a reused output directory, outside regular-file open observation. Renames, removal and link replacement revoke store admission too. URI/unnamed temporary databases refuse; in-memory databases have no file input. Native SQLite contents remain unobserved. This establishes fresh baseline store creation, not native-byte hashing.
